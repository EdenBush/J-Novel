# 执行契约：如何保证 Agent 不跳步、不偷懒

**为什么会有这份文件？** 经验表明，Agent 在长流程中会出现"遵从不稳定"：有时候严格走流程，有时候直接跳过；有时候会读 guides，有时候不读就擅作主张。这不是能力问题，是**指令工程问题**——流程太长、约束太弱、没有留痕机制。

这份契约是融合版全流程的**执行宪法**。SKILL.md 的硬指令区引用它，每个流程文件的执行清单遵守它。

> **J-Novel 3.0 变更**：在 Reasonix 2.17 的四条铁律之上，新增四条来自 J-Space 的**过程层铁律**（五、六、七、八）。前四条管"产物是否合格"，后四条管"Agent 在长跑中是否还醒着"。

---

## 一、八条铁律（最高优先级，任何情况下不得违反）

1. **【必须】进入任何 Phase，先读对应的流程文件，并按该文件的「执行清单」逐项执行。** 不读流程文件就动手 = 流程违规。清单没打完全部勾 = 该阶段未完成，不许进入下一阶段。
2. **【必须】标注【必须】的步骤，不可跳过、不可合并、不可简化。** 标注【标准】的步骤，默认执行，除非有明确且可说明的理由。【可选】的才允许按情况取舍。
3. **【必须】执行到关键环节，先读对应的 guides 文件再动手。** "动作前必读"不是建议，是前置条件——不读就写 = 质量违规。（必读映射见 `guide-index.md`）
4. **【必须】检查型工具固定排班，到点必调。** "我认为这章没问题"恰恰可能是 AI 味的来源——**自检结论不可信，检查必须发生，通过也是结果**。对话/情绪/节奏专项检查按排班制执行（见 `guide-index.md` A 表），不因自检"没问题"跳过；检查结果记入 `04-质检档案.md`，Phase 4 查痕。

**以下四条为 J-Novel 新增（过程层）：**

5. **【必须】三态标记：任何标 `?` 的条目，下游章节不得当作已发生的事实来写。**
   状态台账、伏笔对照表、大纲章节字段的每一条，强制带状态位：

   | 标记 | 含义 | 写法 |
   |---|---|---|
   | `✓` | 已在正文明确写出 | `✓ 林砚知密道（第3章结尾）` |
   | `?` | 仅规划/推断，未落正文 | `? 苏晚的伤 —— settled by: 第12章揭露` |
   | `✗` | 已被后续剧情否定 | `✗ 反派是复仇者（第14章推翻，保留可追溯）` |

   **默认无标记 = `?`。`✗` 不删除、不覆盖，保留证据链。**
   长篇里最贵的一类 BUG 是"我以为这条已经写过了"——第 5 章登记的伏笔，第 20 章被当成既成事实引用。三态标记把"已确认"和"我推断"物理分开，代价是每行多敲一个字符。

6. **【必须】seam 重读：每章边界（Phase 3 步骤 0.5）重读 `05-创作台账.md` 五段后再动笔。**
   注意力能平等触达此前的任何 token，但**只在那个 token 还在你眼前的时候**。
   **不重读的台账比没有台账更糟**，因为它看起来像状态。重读只花 30 秒；不重读的代价是第 20 章才发现文风从第 8 章就漂了。
   Core 换条目必须**说出声**（"放下 X，拿起 Y"）——不说的交换叫静默丢弃，是"某个约束在任务中途悄悄停止生效"的头号原因。

7. **【必须】置信度绑定：读到「晃」禁止原路重走。**
   详见 `guides/confidence-binding.md`。速查：

   | 读数 | 触发（任一） | 义务 |
   |---|---|---|
   | **稳** | 人侧 ≥7 项 且 评分 ≥70 且 无未决杠精点 | 放行 |
   | **薄** | 人侧 4-6 项 / 评分 65-69 / 有 1 个未决杠精点 | 在质检档案**点名最薄的一项 + 理由**，然后放行 |
   | **晃** | 人侧 ≤3 项 / 评分 <65 / retryCount ≥2 | **禁止原路重走。** 三选一：①升到锚点章标准全调专项 ②换路重进入 ③停下问用户 |

   **读到「晃」还继续，是这一条存在的全部理由。** 一次没有选中出口的估计不是监控，是评论。

8. **【必须】注册分离：正文里不得出现细纲记号、质检字段、未展开的私人缩写。**
   每章收尾执行注册审计（Phase 3 步骤 6）。任何缩写必须能当场展开成完整句子；展不开就不是缩写，是丢失。
   切换到"外"寄存器是**彻底的**，并且在**每个 seam 都要切一次**——不是交付前切一次。长跑中压缩寄存器会往外渗，而你是最后一个发现的。

## 二、指令等级系统（全文统一标注）

| 标记 | 含义 | 跳过后果 |
|------|------|---------|
| **【必须】** | 硬闸门。不可跳过、不可合并、不可简化 | 该产物不合格，Phase 4 校验会退回 |
| **【标准】** | 默认执行。跳过需明确理由并向用户说明 | 质量下降，用户可追问 |
| **【可选】** | 按情况取舍（快速模式/追加追问/后记等） | 无 |

**判定口诀**：文中出现"必须/强制/禁止/不可跳过/先读" → 【必须】；出现"默认/应/要/遵循" → 【标准】；出现"可以/可选/视情况/如需" → 【可选】。**拿不准时，按更严格的等级执行。**

## 三、为什么 Agent 会不遵从（根因清单，写文件时对照）

| 根因 | 表现 | 本体系的对策 |
|------|------|-------------|
| 流程文件太长，注意力衰减 | 读到后面忘了前面，漏子步骤 | 执行清单前置（开头最强注意力区）；大文件拆小（并发已拆出 parallel-workflow） |
| 弱约束词（可以/建议/详见） | 被理解成可选项 | 统一等级标注【必须/标准/可选】 |
| 找不到引用文件 | 读不到就跳过 | guide-index 集中映射；SKILL.md 注明"路径相对本 SKILL 目录" |
| 没有"做过"的痕迹 | 跳过也无法被发现 | 产物留痕：执行清单打勾、质检摘要字段、台账更新——Phase 4 查痕 |
| 对话历史干扰 | 聊着聊着忘了流程 | 每阶段出口声明"进入下一阶段的唯一条件是清单全过" |
| 子代理/主代理脱节 | 子代理自由发挥 | 子代理任务包内附必读路径 + "不自由发挥创作方向"约束 |
| **长跑中静默丢约束**（J-Novel） | 连写十几章后，文风锚点/伏笔状态/排班记录全凭印象；不报错，只会在第 20 章变成"读着不对劲" | 铁律六：每章 seam 重读 `05-创作台账.md`；Core 换条目必须说出声 |
| **"已写"与"打算写"混淆**（J-Novel） | 台账记了一条，后文当既成事实引用，其实从未落笔 | 铁律五：三态标记 ✓ / ? / ✗，`?` 不得作下游前提 |
| **禁止式指令反而激活**（J-Novel） | 越强调"不要写 X"，X 出现得越多；deai 反复清洗仍复发 | 占位式指令：`guides/occupancy-rewrite.md` |

## 四、遵从防护机制（怎么让"做过"可验证）

### 1. 执行清单（每个 flow 文件开头）
```
本阶段执行清单：
[ ] 1. 【必须】读取偏好与中断续写检测
[ ] 2. 【必须】…… 
[ ] N. 【标准】……
→ 清单全勾 + 产物齐全 = 本阶段完成，可进入下一阶段
```
Agent 每完成一步就打勾，阶段结束时清单必须全勾。

### 2. 产物留痕（过程遵从 → 产物验证）
**不检查 Agent"有没有做"，而是检查产物里"有没有做过的痕迹"**——这是防偷懒的最强手段，因为痕迹无法凭空跳过：

| 环节 | 必须留下的痕迹 | 谁验证 |
|------|--------------|--------|
| 采访 | 蓝图进度表（验收 12 项逐项状态） | 进入 Phase 2 前自查 |
| 每章写作 | `04-质检档案.md` 中本章记录（AI 味自评 X/10 + 终极自问、衔接检查、逻辑检查、质量评分） | Phase 4 逐章查 |
| 每章收尾 | 大纲章节摘要（300-500 字）追加；伏笔登记到对照表 | Phase 4 抽查 |
| 状态台账 | 出场人物终态写回（含"最近更新"章号） | 主编批次间核对 |
| 规划 | 大纲每章字段完整（核心事件 2-3 句等） | 写作前查，缺字段禁止动笔 |
| 正文纯净 | 章节正文不含【质检摘要】等加工痕迹 | Phase 4 正文纯净检查 |

**缺痕 = 未做 = 不合格**，退回补做。

### 3. 用户可监督
- 阶段输出格式里带"执行清单完成度"（如"✅ 采访验收 12/12 已磨透"）
- 用户看到"⚠️ 某步被跳过"可以当场指出，Agent 必须补做
- 用户说"你刚才是不是跳过了 XX" → Agent 立即自查清单并补做，不狡辩

## 五、常见偷懒点与对策（对照自查）

| 常见偷懒 | 对策 |
|---------|------|
| 跳过采访直接写 | Phase 0 快捷入口需五要素齐备；验收清单 12 项全过才放行 |
| 写作不读 writing-mindset | 动笔前必读标记为【必须】，前置在步骤最前 |
| 质检时跳过 AI 味自评 | 质检摘要必须含"AI 味自评 X/10"行，Phase 4 缺此字段判不合格 |
| 不更新状态台账 | 台账"最近更新"章号必须推进，主编批间核对 |
| 不登记伏笔 | 大纲伏笔对照表必须同步，Phase 4 抽查 |
| 快速验收糊弄 | 主编验收含硬底线全查 + 锚点章细看 + 风格抽查，抽样不可全免 |
| 子代理不看前序结尾 | 子代理任务包内含"上一章真实结尾"，不包含则拒绝开工 |
| **该调子技能时不调**（只用内建指南应付） | guide-index「子技能触发表」强制映射；质检档案标注"子技能执行"留痕，Phase 4 查痕 |
| **自检"没问题"跳过专项检查**（对话/情绪/节奏） | 排班制强制（guide-index A 表）；质检档案必须含"专项检查：通过/发现X"，Phase 4 缺"专项检查"记录 = 不合格 |
| **派发子 Agent 不装齐工具**（不告知工具权限/给相对路径/不附脚本） | subagent-brief.md 派发检查清单六项全过才派发；四缺一不派发；子 Agent 找不到文件必须停下要，不许跳过 |
| **子 Agent 不用 dialogue-master 打磨对话** | subagent-brief 排班：对话每章必调（AI 味重灾区）；质检档案"专项检查"行缺 dialogue 记录 = 不合格 |
| **被爱者写成"完美守护者"**（无缺陷的理想化） | character-template"缺陷警示"必填；质检"情感戏换人演"测试查角色是否有真实缺陷 |
| **台账建了不重读**（看起来像状态，其实是死文件） | 铁律六：每章 seam 强制重读；Phase 4 抽查台账"最近重读章号"是否推进 |
| **把"打算写"当成"已经写了"** | 铁律五：三态标记；默认无标记 = `?`，`?` 不得作下游前提 |
| **读到「晃」还原样重写第三遍** | 铁律七：换路或上报；retryCount==2 强制换路，==3 上报用户 |
| **台账/伏笔表写了但没标三态** | 缺三态位 = 未执行铁律五 = 不合格，Phase 4 查痕 |
| **AI 味清单用禁止式念了一遍**（越念越写） | 改用占位式指令，见 `guides/occupancy-rewrite.md` |
| **句法层不检测**（只跑 ai-taste 就觉得"人味够了"） | 必跑 `check_human_rhythm.py`，退出码 1 = 不合格；Phase 4 查质检档案有没有这一行 |
| **情绪全部转译成身体反应**（禁情绪词禁过头） | 情绪词 0.25–0.5/千字、身体部位 ≤1.0/千字；三种写法混用（`human-rhythm.md` 规则 6） |
| **对话堆到 30% 以上凑数** | 无下限、≤40%（护栏）；对话少的章用叙述推进，不要注水 |
| **比喻顶格写满** | 2–4 个/3000 字（区间），其中 ≥1 个非明喻 |
| **动作短语照着清单往里塞** | ACTION_PATTERNS 是违禁品清单不是素材库；密度 ≤0.4/千字 |
| **本章开头把上章场景又写一遍** | 场景重述红线：前 300 字不得与上章最后 800 字描述同一事件序列 |

## 六、创作崩坏红线与五拍恢复（J-Novel 新增）

现有的退化检测只作用于**产物**（`check_repetition.py` 重复检测、`check_aistyle.py` 统计指纹）。以下四条管的是**过程**——产物还干净，但人已经不对了。

**四条红线（任一出现即停）：**

1. **连续 3 章**使用同一钩子招式，或同一开场句式
2. 同一章内对**同一段落**修改 ≥3 次，且每次改动 <10%
3. 同一章内 `deai` 与 `pad` **交替调用** ≥2 轮（清洗→补字→又洗→又补）
4. 子代理回报出现**无具体数字的兜底表述**（"我已尽力""大致完成""应该没问题""风格基本一致"）

**五拍处置（按顺序，不跳步）：**

1. **停。** 当前轨道立刻中止。不再"再写一段试试"——那是最贵的一句话。
2. **名。** 一句话说清是什么：`发现崩坏：连续 3 章同一钩子招式。`
3. **锚。** 一句话重述本卷目标，再念出最后一条编号 Verified。
4. **新计划。** 写一份 3-5 步的**编号**计划，**从 Step 1 重入**——不是"接着改"。观测到的恢复轨迹没有一次是"从断点续"，都是写一份新计划、从第一步重新进。
5. **记。** 写入 `05-创作台账.md` 的 Open 或事故记录。

**绕着崩坏处改一改继续，才是真正的失败。** 编辑掉循环痕迹假装没发生，比循环本身更贵——因为它同时销毁了诊断信息。

## 七、重试三出口（J-Novel 新增，改 Phase 4）

任何一次对章节质量的估计，必须选中且仅选中一个出口：

1. **信任它。** 通过，记入 `04-质检档案.md`。通过也是结果。
2. **带诊断重试。** 重试指令的**第一行**必须写：
   ```
   诊断：<一句话，上次到底错在哪>
   本稿必须不再犯：<一句话，可判定的>
   ```
   **不带诊断句的重试 = 同一个尝试**，成本一样，收益为零。子代理换人时，诊断句随任务包一起给新代理。
3. **换路，然后对账。** `retryCount == 2` 时**强制**。禁止沿用上一稿的场景顺序与开场类型——先用 200 字把"这一章要完成的三件事"用**完全不同的原语**重述（例如从"场景清单"改成"人物在这一章失去了什么 / 得到了什么"），再动笔。写完新旧两稿并排放，只比一件事：**哪一稿读起来像同一个作者写的。**

**`retryCount == 3`：同一堵墙撞第三次，说明不是解法错了，是问题被错误框架化了。** 停下来，向用户上报，附两个版本的差异说明，让用户选。不要"保留记录但不阻塞"——那等于把最难的一章悄悄埋了。

## 八、给 Agent 的最终提醒

- **不确定就读文件，不要靠记忆。** 你觉得"我知道这个指南讲什么"的时候，正是应该读它的时候。
- **跳过任何【必须】步骤 = 流程事故。** 宁可慢，不可漏。
- **你留下的每一个痕迹（清单勾、质检摘要行、台账更新），都是给未来的读者和 Phase 4 质检员看的。** 痕迹齐了，质量才可信。
- **产物合格 ≠ 过程清醒。** 前四条铁律保证你交出去的东西合格，后四条保证你还知道自己在做什么。长篇里真正致命的事故，几乎全部来自后者。
- **一次没被读的台账，等于没有台账，而且更危险。** 它看起来像状态。
