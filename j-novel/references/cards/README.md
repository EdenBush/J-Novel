# `cards/` —— 一页操作卡（写手唯一读的东西）

> **本目录解决的是本体系最大的一个结构性矛盾。**
> 详见 `references/architecture.md`；这里只说结论与用法。

---

## 一、为什么要"卡"而不是让 agent 读指南

实测算术：

| 项 | 数 |
|---|---|
| `references/guides/` 总量 | **54 本 / 44.3 万字符 ≈ 30 万 token** |
| 单章"该读的都读" | 去重 21 本 ≈ **15.2 万 token** |
| `execution-contract.md` 自己规定 | 每次调用平均重发 **>100k = 纪律失守** |
| 调用预算 | **10–18 次/章** |

**→ 读点要求与成本纪律在数学上互相否定。** 执行者只能二选一，
而**成本有审计（`audit_tokens.py` 能查），读点没有审计** —— 于是它选成本、跳过读点，**而且选得对**。

这就是"改写阶段那些指南没被读取"反复复发、改了多遍仍无效的真因：
**不是指令不够狠，是清单不可执行。**

**所以本轮把机制换掉：不再要求读，改成编译。**
写手拿到的 `brief` 里**已经内联了 3–4 张卡**（约 3,000 字），它**不需要读任何指南**。

## 二、两层分工（写死，别混）

| 层 | 目录 | 回答什么 | 谁读 |
|---|---|---|---|
| **操作层** | `references/cards/*.md` | **怎么写**（指令、形态、正反例） | **写手**（由编译器注入 brief） |
| **原理层** | `references/guides/*.md` | **为什么**（机理、实测证据、反例、边界） | 人；或**改写深查**时按索引取一节 |

> **`card` 不是 `guide` 的摘要，是它的"可执行形态"。**
> 卡里**不许出现"平均句长 23–37"这类阈值**——阈值是体检的事，写作时要的是形态。
> （这是 `quality-constitution.md` 第三节的"表述规范"：脚本用数字，写手用形态。同一个东西，两个读者，两种写法。）

## 三、现有 10 张卡

| 卡 | 回答什么 | 默认注入 |
|---|---|---|
| `card-thinking.md` | **动笔前思考什么**（决策五问 / 四条不许 / 起手式） | ✅ **每章，且永远在 brief 的最末尾**（不进 `craft_cards` 的 3–4 张配额） |
| `card-voice.md` | 每一句像不像"那个人"在讲 | ✅ 每章 |
| `card-prose.md` | 长句怎么长、短句怎么用、具体性怎么抓 | ✅ 每章 |
| `card-dialogue.md` | 是不是这个人在说 | ✅ 每章（每章都有对白） |
| `card-ending.md` | 章末落笔怎么不公式化 | ✅ 每章 |
| `card-scene.md` | 一个场景四件套；静场章怎么活 | 静场章 / 冲突章时替换 dialogue |
| `card-opening.md` | 章首是慢起；入口是人不是天气 | 首章 / 卷首 / 新场景断开 |
| `card-story.md` | 五格与三种病 | 故事账缺段时补位 |
| `card-world.md` | 设定是约束；机制卡怎么用 | 本章要新造地点/势力/机制时 |
| `card-revise.md` | 先补足再压住；占位式；三行对照 | **改写时**替换 ending |

**选取规则由 `scripts/make_task_package.py` 的 `_craft_cards()` 实现**（脚本选，不靠记忆）。

> ★ **`card-thinking.md` 是个例外，它不走 `_craft_cards()`**：它管的是**思维链**，不是句子。
> 由 `_thinking_card()` 接在 **brief 的最后一个字节**上——因为模型读完 brief 立刻开始思考，
> **最后一行 = 第一个思考动作**。原理见 `guides/thinking-protocol.md`。

> ⚠️ **这是第 10 张，也是最后一格。** `architecture.md` 第八节的自毁条款写的是
> **卡 >10 张就该合并**；再想要新卡，先问"能不能并进现有这张"，不要开第 11 格。

## 四、写一张新卡的门槛（四条都过才写）

1. **它必须是"落笔时的动作"**，不是"事后的判据"。（"补一句环境"是动作；"句长≥23"不是）
2. **它不许出现阈值**。需要数字时，写成"一句""一处""一次"这样的**计数形态**。
3. **它不许重抄 guides**。要引用就写一句"深度见对应指南"，卡里只留操作。
4. ★ **空写测试（2026-11-01 加，本目录最硬的一道）**：
   **模型能不能在"什么都不想"的情况下完成这一条？**
   能 → 它是**装饰**，删掉或改成产出物。不能 → 才配留在卡上。

   | 过不了空写测试（装饰） | 过得了（真动作） |
   |---|---|
   | 「注意人物的肢体语言」——空写一句"她低头"就算完成 | 「写这个人的一个身体动作，**且这个动作和她想达成的目的相反**」 |
   | 「对话要推进信息」——写什么都能说自己推进了 | 「这一场对白里，藏一件**没说完**的事，且读者能察觉」 |
   | 「要有情感张力」——形容词，无法验证 | 「三句台词里，有**一句是谎话**，不标注是哪一句」 |

   > 判据一句话：**这一条有没有一个"它没做到"的具体样子？** 举不出来 = 口号。

> ★ **第 0 道门（比上面四条更前面）：这件事模型**会不会**做？**
> 不会（超出能力）→ 卡写得再好也没用，别写卡，去改任务或换模型；
> 会但默认不做 → **这才是卡的战场**（见 `guides/prompt-engineering.md` 第零前节）；
> 会且主动做 → **别写，白占预算**。

> 第 3 条是本项目零容忍的那条（**双载体同名必漂**）。卡的定位是**编译产物**：
> 源头在 guides，形态在这里。改了源头，回来同步卡；**卡始终是写手看到的那一份。**
