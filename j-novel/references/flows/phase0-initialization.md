# Phase 0：初始化与偏好加载

**每次触发本技能时首先执行本阶段。**

```
本阶段执行清单：
[ ] 1. 【必须】读取 user-preferences.json（不存在则用默认值）
[ ] 2. 【必须】中断续写检测：扫描 novel-output/ 下 02-写作计划.json
[ ] 2.5【必须】状态恢复四步（仅当命中未完成项目时）：读 05-创作台账全文 → 读 03-状态台账全文 → 读上一章真实结尾 → 说出 Next
[ ] 3. 【必须】确定入口：续写项目 / 快捷入口（五要素齐备）/ 完整采访
[ ] 4. 【标准】个性化欢迎（有偏好时）
→ 清单全勾 = 本阶段完成，进入 Phase 1 或 Phase 2
```

---

## 1. 读取用户偏好

检查 `user-preferences.json`（位于当前工作目录）是否存在：

- 存在 → 加载偏好数据，用于后续选项排序、推荐标记（⭐）、个性化欢迎语、以及采访时的引导
- 不存在 → 使用默认值，首次交互结束后自动创建

偏好数据结构与更新规则详见本文件末尾「用户偏好系统」一节。

## 2. 中断续写检测（优先于快捷入口）

扫描 `./novel-output/` 目录下所有项目的 `02-写作计划.json`：

- 查找 `status` 为 `"in_progress"` 或 `"validating"` 的项目
- 如果找到未完成项目：
  - 展示项目信息：小说名称、完成进度（X/Y 章已完成）、当前写作模式
  - 提供选项：
    - "继续上次创作" → 读取该项目的 `02-写作计划.json`，进入 **Phase 3**，从 `status` 为 `"in_progress"` 或第一个 `"pending"` 的章节继续
    - "开始新作品" → 进入第 3 步快捷入口检测
- 如果未找到 → 进入第 3 步

> 这是融合版新增的关键能力：Reasonix 1.x 依赖上下文续写，一旦会话中断即"失忆"；现在项目状态全部落盘，任何一次触发都能无缝续写。

#### 2.5 状态恢复四步（命中未完成项目时必做）

`02-写作计划.json` 告诉你**写到哪一章**了，但不知道**你当时在想什么**。文件里少这一层，续写的章节就会"接得上情节，接不上脑子"。

找到未完成项目后，按顺序做完这四步再动笔：

1. **读 `05-创作台账.md` 全文**——包括每一条 Verified，不是只读最后一条。它记的是"我已经确认了什么"。
2. **读 `03-状态台账.md` 全文**——人物位置/情绪/关系/已知信息 + 伏笔 + 时间线。
3. **读上一章的真实结尾**（不是摘要）。
4. **说出 `Next`**，让它指向第一个动作。

如果用户提供的是"会话中途被压缩 / 我记不清前面了"这类情形，同样走这四步——**页面上的状态熬得过压缩，脑子里的熬不过。**

> 若 `05-创作台账.md` 不存在（旧项目迁移），从 `03-状态台账.md` + `04-质检档案.md` 反向补齐五段再继续。

## 3. 快捷入口检测

分析用户的首次输入是否已包含丰富的创作信息：

- **信息充足的定义（必须同时覆盖五要素）**：核心钩子（一句话）、主角设定（想要/需要）、核心冲突、世界观规则、篇幅（章数/每章字数）。五要素齐备才视为"充足"——缺任何一项，都不算充足，走完整采访
- 如果信息充足 → 展示提取结果，提供三个选项：
  - "是的，直接开始规划" → 跳过 Phase 1 采访，直接进入 **Phase 2 规划**（未覆盖的要素按合理默认值补齐，并在规划摘要中**显式标注"默认值，未经作者确认"**）
  - "先展示提取的信息让我确认/修改" → 展示配置供确认后进入规划
  - "不，我还是想走一遍采访流程" → 进入 **Phase 1** 采访（**默认推荐**——采访能把故事磨透，跳过是效率妥协不是优选）
- 如果信息不足 → 直接进入 **Phase 1** 采访

> **态度约束**：采访是融合版质量的第一道保障，快捷入口是给"信息已充分"的用户省时间用的，不是给 Agent 偷懒的。除非五要素齐备，否则一律走采访；即使跳过，规划摘要也必须标注默认值让作者审。

## 用户偏好系统（跨项目共享）

### 存储文件

`user-preferences.json`（当前工作目录，首次使用后自动创建）

### 数据结构

```json
{
  "version": 1,
  "updatedAt": "2026-08-05",
  "preferences": {
    "favoriteGenres": [],
    "preferredProtagonist": "",
    "preferredPerspective": "",
    "preferredTone": "",
    "typicalChapterCount": null,
    "typicalChapterWords": null,
    "styleReferences": [],
    "dislikes": [],
    "creationHistory": []
  }
}
```

### 偏好更新规则

| 时机 | 行为 |
|------|------|
| 每完成一轮采访 | 静默将本层回答同步到偏好文件（追加/更新，不删除历史） |
| 用户说"记住我的偏好" | 保存当前所有配置到偏好 |
| 用户说"忘记XX偏好" | 清除指定维度的偏好 |
| 用户说"重置偏好" | 清空所有偏好数据 |
| 一部长篇创作完成 | 将作品信息追加到 `creationHistory` |

### 偏好如何影响交互

1. **启动欢迎语**：有偏好时显示"欢迎回来！" + 个性化提示
2. **选项排序**：Phase 1 第 1 轮中将 `favoriteGenres` 匹配项排前面
3. **常用标记**：对应用 ⭐ 标记"你的常用"/"上次选择"
4. **需求报告**：结合偏好给个性化建议（如"你之前喜欢悬疑+第三人称限制，这次要不要试试多视角？"）
5. **风格参考追问**：优先推荐 `styleReferences` 中的作者

### 错误恢复

- **回退修改**：用户随时可说"回到第X轮"、"修改XX"，回退到指定轮次重新询问
- **中途暂存**：通过 `02-写作计划.json` 实现自动暂存；下次触发时 Phase 0 自动检测未完成项目
- **偏好文件损坏**：JSON 解析失败时忽略偏好，使用默认值，并在后台修复文件
