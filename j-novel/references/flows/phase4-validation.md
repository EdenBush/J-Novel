# Phase 4：自动校验与修复

**目标**：确保所有章节完成且字数达标，全程无需用户介入。这是融合版的质量兜底——Reasonix 1.x 缺这一环，Chinese Novelist 的"自动重写"让它变得可靠。

```
本阶段执行清单：
[ ] 1. 【必须】status → validating
[ ] 2. 【必须】逐章检查：文件存在 + 字数脚本 + 质检摘要齐全（**按 costMode 分档查痕：low 只查 3 脚本痕迹，standard 查全量**）+ 执行痕迹检查（清单勾/台账更新/伏笔登记）
[ ] 2.5【必须】过程层查痕：05-创作台账.md 的"最近重读章号"是否推进到最后一章；03-状态台账与伏笔表是否全部带三态标记 ← 铁律五/六
[ ] 3. 【必须】读者体验抽检（锚点章三层验证）
[ ] 4. 【必须】不合格章按「重试三出口」修复（≤3 轮，按专家介入对照表）
[ ] 5. 【必须】全部通过 → status → completed → 完成报告（**必须含「未检查项」**）
→ 清单全勾 + 全部章节 PASS = 本阶段完成，进入 Phase 5
```

---

## 校验流程

### 1. 初始化校验

读取 `novel-output/{小说名}/02-写作计划.json`，将项目 `status` 更新为 `"validating"`。

### 2. 逐章检查

对每一章执行以下检查：

1. **文件存在性**：检查 `filePath` 指定的文件是否存在
2. **字数检查**：运行脚本
   ```bash
   python scripts/check_chapter_wordcount.py --all novel-output/{小说名}/
   ```
3. **质检档案检查（含执行痕迹）**：`04-质检档案.md` 中是否每章都有记录。**先读 `02-写作计划.json` 的 `costMode`，查痕标准分两档**：
   - **`costMode: "low"` 的章节**：只查以下 4 行（low 模式不产生其它痕迹，查了必误判"缺痕"）：
     - `节律检测：check_human_rhythm.py 退出码 X`（退出码 1 按未通过）
     - `统计指纹：check_aistyle.py 模板短语/动作密度` 
     - `字数：XXXX ✓`
     - `写前声音预置：具体坐标 / 立场 / 留白点 / 破折号预算 / 专有名词锚点`
   - **`costMode: "standard"` 的章节**：查全量痕迹字段（缺一即视为该章流程未走完，判不合格）：
   - `AI 味自评：人侧 X/10`（证明 AI 味自评量表执行过）
   - `衔接检查：通过/未通过`（证明写前锚点与衔接三查执行过）
   - `逻辑检查：通过/未通过`（证明 BUG 四查执行过）
   - `硬性句式扫描：已清零`（证明拦截执行过）
   - `质量评分：XX/80`（证明评分卡执行过，参考 quality-scorecard.md）
   - `专项检查：对话-master / 情绪-master / 节奏-check`（证明排班制执行过——对话每章必调、情绪偶数章加调、锚点章全调、每 3-5 章节奏；**缺专项检查记录 = 排班未执行 = 不合格**）
   - `节律检测：check_human_rhythm.py 退出码 X + 九项实测值`（证明句法层检测跑过；**缺此行 = 不合格**；退出码 1 按未通过处理）
   - `统计指纹：check_aistyle.py 模板短语/动作密度/明喻密度实测`（证明词汇层+模板短语检测跑过；**缺此行 = 不合格**）
   - `写前声音预置：具体坐标 / 叙述者立场 / 留白点 / 破折号预算 / 专有名词锚点`（证明写前声音预置在**动笔前**做过；**缺此行 = 不合格**——这一步是"具体性/立场/留白"三层的载体，写后补的高光是假痕迹）
   另抽查：`01-大纲.md` 章节摘要区是否已追加本章摘要、伏笔对照表是否同步、`03-状态台账.md` 出场人物是否已写回终态——**缺痕 = 未做 = 不合格**
3.5 **全书节律汇总**：各章九项实测值拉成曲线，标记"节律塌陷区"——
   连续 3 章有 ≥2 项未达标 = 系统性漂移（不是单章问题），按批次级问题处理：
   停下、重抽文风锚点、**用 `--baseline` 重算句法目标**、后批按新目标写。
3.8 **章节边界连续性检测**：跑 `python scripts/check_continuity.py novel-output/{小说名}/`
   ——退出码 1 = 有"上章结尾钩子人物在本章开头缺席"的边界，逐条人工复查：
   该接没接（退回补一句桥接）还是刻意留后章（在大纲/细纲补标"此钩子第X章回收"）。
   **并行写作最容易在章与章之间断线，这一步是专门补这个的。**
4. **正文纯净检查**：章节文件正文中**不应出现**【本章质检摘要】等质检痕迹（如发现旧版遗留，从正文移除）
5. **质量曲线汇总**：所有章节评分汇总，生成全书质量曲线（章节号 × 总分）——连续 3 章 < 65 分标记"低潮区"；锚点章 < 70 分必须回炉
6. **读者体验抽检**（来自 Reasonix Reader Simulator）：对品质锚点章（`qualityLevel: "anchor"`，至少覆盖开篇、中点、高潮各一章）做三层读者验证：
   - **普通读者视角**：不分析技巧，只看好不好看、想不想继续翻——给感性反应
   - **挑剔读者视角**：找"疙瘩"——让读者从沉浸中被迫抽离的瞬间（逻辑对不上、反应不合理、转折没铺垫）
   - **作者同行视角**：欣赏 + 建设性心得
   发现"疙瘩" → 标记到对应章节的修复清单
7. **更新 JSON**：将 `wordCount` 和 `wordCountPass` 写入对应章节记录

### 3. 汇总结果

- **全部通过**（所有章节文件存在、`wordCountPass == true`、质检摘要齐全）→ 更新项目 `status` 为 `"completed"`，进入 Phase 5
- **有不通过** → 进入步骤 4

### 2.5 过程层查痕（J-Novel 新增）

产物合格不等于过程清醒。除了查章节，还要查两件事：

1. **`05-创作台账.md` 的"最近重读章号"是否推进到最后一章。** 没推进 = seam 重读没执行 = 铁律六未执行。此时即使所有章节都 PASS，**也要把最后一章之后断掉的章节按批次回补重读**（不必重写，但要把 Verified/Open 补齐并复核对账）。
2. **`03-状态台账.md` 与伏笔对照表是否全部带三态标记**（`✓` / `?` / `✗`）。缺标记 = 铁律五未执行 = 不合格，退回补标。
   顺带查一件：**有没有标 `?` 的条目被后文当成了既成事实写进正文**——这是三态铁律存在的全部理由。命中即修。

### 4. 自动修复（最多 3 轮）—— 重试三出口

对每个不通过的章节：

1. 将 `status` 设为 `"failed"`，`retryCount` 加 1
2. **诊断失败原因**（见下方「专家介入对照表」，这决定修复方式）
3. **选中且仅选中一个出口**（必选，不许零选）：

   **出口 A — 信任它。** 诊断后认为上一稿只是偶发瑕疵，直接定点修补，记入质检档案。

   **出口 B — 带诊断重试。**
   重试指令（或子代理任务包）的**第一行**必须写：
   ```
   诊断：<一句话，上次到底错在哪>
   本稿必须不再犯：<一句话，可判定的>
   ```
   **不带诊断句的重试 = 同一个尝试**，成本一样，收益为零。换子代理时，诊断句随任务包一起给新人。
   然后回到 Phase 3 对该章节执行逐章创作流程（seam 重读 → 写前分析 → 撰写 → 质检 → 修改 → 注册审计 → 台账回写）。

   **出口 C — 换路，然后对账。`retryCount == 2` 时强制。**
   禁止沿用上一稿的场景顺序与开场类型。先用 200 字把"这一章要完成的三件事"用**完全不同的原语**重述（例：从"场景清单"改成"人物在这一章失去了什么 / 得到了什么"），再动笔。
   写完把新旧两稿并排放，**只比一件事：哪一稿读起来像同一个作者写的。**

4. 修复完成后重新检查字数与质检摘要
5. 更新 `02-写作计划.json`
6. **`retryCount == 3` → 停止自动修复，向用户上报。** 同一堵墙撞第三次，说明不是解法错了，是问题被错误框架化了。上报时附：三次失败各自的诊断句 + 两个版本的差异说明 + 你建议的方向，让用户选。**不要"保留记录但不阻塞"**——那等于把最难的一章悄悄埋了。

### 专家介入对照表

**子技能已安装时为首选（必须调用，专业版）；内建指南仅作兜底（子技能未装时）。**

| 失败原因 | 首选处理（调用子技能） | 内建兜底 |
|---------|----------------------|---------|
| 字数不足 | `reasonix-novel-pad`（专业补字） | 补字 SOP（悬空瞬间/沉默间隙/过渡空白 + 质感三问） |
| AI 味重（自评 4 项以上 AI侧） | `reasonix-novel-deai`（六步深度清洗）+ 自评复评 | DeAI 六步工作法（deai-workflow.md） |
| **节律检测未达标**（句首代词/句长/破折号/身体部位等） | 翻 `guides/rewrite-playbook.md` 对应节逐项改——**这是句法层问题，deai 修不了**（deai 管词汇层）。改完重跑 `check_human_rhythm.py` 直到退出码 0 | `guides/rewrite-playbook.md` 十节改写招 |
| **通用模板短语超标**（一个人/这一刻/走廊里等通用词） | 换成专有名词或独一无二的具体物（`rewrite-playbook.md` 第 10 节），改完重跑 `check_aistyle.py` | `guides/rewrite-playbook.md` 第 10 节 |
| **章节开头重述了上章场景** | 删掉重述部分，从上章结尾之后的第一个新动作开始（`continuity-check.md` 场景重述红线） | — |
| **情绪词低于下限**（被禁过头） | 补 1–2 处直说或动作——**注意这是"补"不是"删"**，方向跟直觉相反 | `human-rhythm.md` 规则 6 |
| 硬性句式残留 | 逐句重写（杀干净） | — |
| 没毛病但差口气 | `reasonix-novel-write-master`（单点手术） | 六维诊断 |
| 对话生硬 | `reasonix-novel-dialogue-master` | 台词换人说测试（dialogue-writing.md） |
| 情绪没推上去 | `reasonix-novel-mood-composer` | 落差/蓄能/释放诊断 |
| 平淡无聊 | `reasonix-novel-thrill-booster` | 十色爽点（thrill-panel.md） |
| 读者抽检有"疙瘩" | 一致性四问 + 杠精自检定位 | — |
| 剧情断档/BUG | 衔接三查 + 逻辑 BUG 四查（continuity-check.md） | — |

**循环规则**：
- 最多执行 **3 轮** 校验-修复循环
- 第 3 轮仍未通过 → **停下来上报用户**（不是"保留记录不阻塞"）。附三次诊断句 + 两个版本差异 + 建议方向，由用户决定：接受现状 / 降标准 / 改大纲 / 换人工
- 所有修复完成后更新项目 `status` 为 `"completed"`

## 完成报告

向用户展示创作完成总结：

```
📊 《[小说名称]》创作完成

总章数：[X] 章
总字数：[X] 字
完成率：[X]%

各章节状态：
✅ 第1章：[标题]（[字数]字）
✅ 第2章：[标题]（[字数]字）
...

项目文件夹：novel-output/[小说名称]/
```

如有不合格章节（超过 3 次重写仍未通过），在报告中标注：

```
⚠️ 第X章：字数不足（[实际字数]/3000），已重试3次
   三次诊断：①… ②… ③…
   两版差异：…
   我的建议：…
   → 需要你决定：接受现状 / 降标准 / 改大纲 / 换人工
```

### 未检查项（必填，不可省略）

**每件完成的事都有一个未检查的边缘。** 说出来只花一句话，但它是"完成"和"假定完成"的区别——而且它天然生成 Phase 5 的待办清单。

```
⚠️ 未检查项：
- 全书人名地名一致性仅做了脚本级扫描，未逐章人工通读
- 第 12 章之后未再调用 rhythm-check
- 第 8-15 章的伏笔状态仅按台账记录核对，未回正文逐条验证
```

**报告之后**：进入 Phase 5 完稿润色。「未检查项」原样带到 Phase 5 作为待办输入。
