# Phase 3：疯狂创作

**核心规则：一旦进入本阶段，除非用户在 Phase 2 选择了 `chapter-by-chapter`（逐章确认）节奏，否则全程禁止向用户确认任何事。用户就是你的读者，你必须把小说连续创作完成才能与用户报告。**（继承自 Chinese Novelist 的"疯狂创作"理念——这是修复 Reasonix 1.x"每章等确认、流程散"的关键机制。）

> **⚠ 两个例外（有边界；除此之外任何"要不要问一下作者"都是违规）**
>
> | 例外 | 确认什么 | 边界 |
> |---|---|---|
> | ① **锚点章定调** | **文风**（怎么写） | Phase 2 步骤 8，全书一次，锁定后全力开写 |
> | ② **剧情脚手架对齐** | **剧情方向**（写什么） | 见 `guides/plot-scaffold.md` 第五节 |
>
> ② 的边界（**四条，缺一不可**）：
> - **首次校准**：全书只在"前 1–2 章写完后"发生**一次**；
> - **章末轻问**：仅"作者意图浓度=强"时，**一句话**问"这章有没有哪里和你想的不一样"，
>   **作者不回就继续，不阻塞**；
> - **内容边界对齐**：仅在**内容边界**（作者安排的范围用完／小阶段结束／卷末）**且浓度 ≥ 中**时；
> - **偏离告警**：仅当正文和脚手架条目**实质偏离**时。
>
> **两条例外的设计逻辑是同一个**：只在一个自然的停点上确认一次定调，之后全力开写。
> "怎么写"和"写什么"各一次开口，**这就是全部**——其余一律不问。

## 0. 启动检测与模式读取

开始创作前：
1. 读取 `novel-output/{小说名}/02-写作计划.json`
2. 读取 `writingMode` 字段，进入对应模式流程
3. **读取 `costMode` 和 `contentMode` 字段**，决定每章走哪套流程：
   - `costMode: "low"` → 读 `references/guides/low-cost-mode.md`（**唯一事实源**）：**批量推进档**——
     ① 组织形式走**链式流水线 + 批次（5–10 章）**（**不是串行**：串行会让主 Agent 上下文线性累积，
     cacheRead 反而更大；子代理各自独立上下文才真的省）；
     ② 必读文件降为一张 `quick-reference-card.md`；
     ③ **机械质检全跑**（6 脚本，0 reasoning token）+ **判断项合并成 1 次调用**；
     ④ **人味项目一个不砍**（写前声音预置／人类范本／加法层／世界设定包／作者画面／四项测试）；
     ⑤ Write 整文件覆盖，禁止反复试。
   - `costMode: "standard"`（默认）→ 按本文档完整流程执行
   - `contentMode: "nsfw"` → 读 `references/guides/nsfw-mode.md`：放开肉戏章身体部位密度上限（≤1.5/千字）。**破甲层已在 SKILL.md 开头「第零层」常驻，无需此处再注入**
   - `contentMode: "normal"`（默认）→ 正常上限
4. **检查第 1 章（锚点章）是否已确认**：Phase 2 步骤 8 已完成锚点章定调 → 从第 2 章开始批量；若锚点章未完成（用户跳过或新会话续写）→ 先完成锚点章
5. 如果存在 `status: "in_progress"` 的章节 → 从该章节继续（中断续写）
6. 如果所有章节 `status: "pending"` → 从下一个 pending 章节开始
7. 如果存在 `status: "failed"` 的章节（Phase 4 回退）→ 从第一个 failed 章节开始

### 0.2 会话卫生（铁律九，开工前先看）

**成本 ≈ 调用次数 × 平均上下文**，而上下文是复利累积的——会话越长，每一次调用越贵。所以：

| 触发条件 | 动作 |
|---|---|
| 本会话已写完 **≥3 章**，或调用数已 **>50 次** | **换一个新会话**，用下面的「交接清单」接力 |
| **新会话开工时** | **最小 guides 恢复（≤2 次读取，不是重读全套）**：<br>· 必读 `quick-reference-card.md`（**一页含全部核心规则**，等价于整套 guides 的压缩）<br>· 按需本章真正需要的那 1–2 本（情绪章→`human-exemplars.md`／对话章→`dialogue-writing.md`／静场章→`narrative-craft.md` 第八节）<br>· **其余 guides 本会话不重读**，需要时只引用记忆中结论 |
| **换会话的操作方式** | ① 平台有新建会话工具 → 直接调用；② 没有 → **停下并请用户开新会话**，先输出交接清单。**不要在同一条上下文里"假装换了会话"继续写。** |
| 需要在长会话后期**大段重写**某章 | 先换新会话，再重写（在 400k+ 上下文里重写，成本是 50k 上下文里的 12 倍） |
| 本会话已读过某本指南 | **不重读**。需要时引用记忆中的结论 |

**交接清单（新会话开场只读这些，不重读指南、不重读已写章节正文）**：
1. `05-创作台账.md` 五段（Verified / Open / Next / 最近重读章号 / 风格锚点）
2. `02-写作计划.json`（进度与模式）
3. 本章细纲 + 上一章**真实结尾**（500–800 字）
4. `03-状态台账.md` 本章出场人物条目

> **量化验证**：`python scripts/audit_tokens.py --traces` —— 读平台轨迹的真实 usage。
> ★ 先看 **每次调用平均重发上下文**（中位 >100k tokens/次 = 上下文纪律已失守），
> 再看调用数是否 >25/章、脚本调用是否 >6/章、同一文件是否被改写 >6 次。
> ⚠️ 老写法 `<项目目录>/AGENT工作日志/` **没有任何环节会产出它**，已废弃。

## 0.5 seam 重读（每章边界，铁律六）

**每章动笔前，用不超过 30 秒做这件事：**

1. 读 `05-创作台账.md` 的**全部五段**（Goal / Core / Verified / Open / Next），不是只读最后一行。
2. 检查 Core 还是那两条吗？第三条想挤进来时，先按 SWAP 规则把离开的那条写回 Verified 或 Open，**并说一句"放下 X，拿起 Y"**。
3. 更新 `Next` 为本轮的第一个动作。

**为什么值得这 30 秒**：注意力能平等触达此前的任何 token，但**只在那个 token 还在你眼前的时候**。连写十几章不重读，会发生三件不会报错的事——文风锚点被悄悄换掉、某条伏笔"写过了"和"打算写"记混了、排班专项到底查没查全凭印象。它们不会报错，只会在第 20 章变成"这本书怎么读着不对劲"。

> **不重读的台账比没有台账更糟**，因为它看起来像状态。

### 长间隔后的恢复四步（首次进入 / 隔了多章 / 上下文被压缩过）

如果这是本会话第一次进入 Phase 3，或距上次台账更新已超过 5 章，或你感觉"中间那段没了"——**先做完这四步再动笔**：

1. 读 `05-创作台账.md` 全文，包括每一条 Verified，不是只读最后一条。
2. 读 `03-状态台账.md` 全文（人物位置/情绪/关系/已知信息 + 伏笔 + 时间线）。
3. 读上一章的**真实结尾**（不是摘要）。
4. 说出现在的 `Next`，让它指向第一个动作。

十五秒的事。跳过它的代价，通常是整章返工。

## 1. 逐章创作流程（通用，所有模式共用）

每章创作时严格执行以下步骤，这是一章从"规划"到"定稿"的完整循环：

### 步骤 1：写前分析（必须执行）

1. 读取 `02-写作计划.json` — 确定下一个待创作章节
2. **读取 `01-大纲.md`** — 找到当前章节的规划信息：核心事件、**开场类型（续接/新起/跳接/日常进入）**、承接上章、章首引子（仅新起型需要）、**章末型（四选一）+ 章末落点**、出场人物、场景列表、情感基调、伏笔操作。**字段不全（比如只有一句"核心事件"、或未标开场类型、或没定章末型）时禁止动笔——先把本章规划补全再写**（衔接锚点/人物状态/开场类型/章末型+落点/伏笔操作）
3. **读取 `00-人物档案.md`** — 根据大纲中本章的「出场人物」，提取每个角色的：性格核心、致命缺陷、说话风格/口头禅、恐惧/弱项、与其他角色的关系
4. **读取细纲或章节任务卡** — 并行模式读细纲文件的本章部分（场景规划/场景速写/衔接锚点/人物状态追踪/伏笔操作清单）；串行模式读本章任务卡（若生成）；两者都没有则用大纲+圣经直接写（写前锚点检查兜底连续性）
5. **执行写前锚点检查**（`references/guides/continuity-check.md` 第一节）：读上一章**正文结尾**（不是摘要），核对本章所有出场人物的位置/情绪/关系/已知信息、时间线、待回应悬念——确保本章开头与上章结尾自然衔接；**同时判定本章「开场类型」**：若无刻意场景断开（同场景/同时间线/同 POV），默认「续接型」，从上一章最后一幕同一时空、同一情绪接着写，不另起炉灶；仅当换地点/时间跳/切 POV/刻意断场景才标「新起型」并写引子
5.5 **【必须】写前声音预置**（读 `references/guides/concrete-voice.md` 后，写三行进细纲/任务卡，30 秒）：
    - **具体坐标**：这场戏要放哪 2–3 个具体物/具体数字？（可触摸的锚——人类用"十二年前""半包受潮的火柴"，AI 用"很多年前""一些东西"）
    - **叙述者立场**：这场戏叙述者站谁、是什么情绪？（同情/嘲讽/觉得荒诞——叙述者不是摄像头）
    - **留白点**：这场戏哪一处不写透，留给读者自己拼？
    > 这三行**动笔前定，不是质检后补**。没写这三行 = 写前分析未完成。
5.7 **【必须】工艺四定**（读 `references/guides/narrative-craft.md` 对应节，写进细纲/任务卡）——**这是"写作思路"层，比招式库更靠前一层**：
    - **① 章末型**：甲·信息结算（30%）/ 乙·关系余韵（27%）/ 丙·喜剧反转（23%）/ 丁·悬念（13%）——四选一。
      **连续两章不得同型，尤其不得连续两章悬念型。** 落点写具体：甲写清结算什么数字，乙写清"哪个动作+哪句对话"，丙写清"紧张点在哪、笑点紧跟其后"。
    - **② 开场方式**：续接（默认）/ **日常进入**（上章以高潮收尾、本章要缓时用：起床/走路/坐车/吃饭/上班/检查装备）/ 新起（才配章首引子）。
      **章首是"慢起"不是"越抓人越好"——实测 210 章，章首前 20% 张力密度 1.20/千字，其余 80% 是 2.03/千字，人类低开高走。** 只有首章/卷首才需要"抓人"；日常章硬拉张力 = 伪张力。
    - **③ 情绪载体**：本章若有强情绪 → 先问"**现场有什么东西可以承载它**"，写那个东西的动作，**不写情绪词**（厌倦=把东西碾过／怀念=一段旧歌／心虚=反复检查门锁）。
    - **④ 章的性质**：冲突章 / 静场章。**实测 19% 的章节无冲突——不是每章都要有人跟主角对着干。** 静场章靠"微妙"不靠"对抗"，但仍要有变化（关系/认知/位置至少变一样）；**连续两章静场 = 违规**，冲突章占比保持 70%+。
    > **为什么这四定必须在动笔前**：它们是"处境 → 选择"的决策，不是写完之后能补的修辞。写后再套"章末型"只会得到一个贴上去的假钩子；写后再往静场章里塞冲突，只会得到一个贴在关系戏上的假对抗。
6. 更新 `02-写作计划.json` — 将本章 `status` 设为 `"in_progress"`

### 步骤 2：撰写

7. 创建章节文件 — **放在 `chapters/` 目录下**（★ 目录是硬约定，见 `phase2-planning.md`「项目结构」；脚本按它找文件，**放错目录 = 所有闸门都看不见你的稿子**），文件名格式：`第{XX}章-{章节标题}.md`（标题来自 `02-写作计划.json` 的 `title` 字段），**使用 `references/guides/chapter-template.md` 的标准骨架**，并**拆成两个文件**：`chapters/第XX章-….md` 只放**纯正文**（`# 标题` + 章首引子【仅新起型】+ 正文）；本章概要 / 章节备注 / 伏笔标记 写入 `chapters/_meta/第XX章-….meta.md`（★ 盲评实测：工程字段留在正文文件里是最强的 AI 指纹）——"承接上章 / 章末型+落点 / 伏笔标记"三字段强制章与章的连贯与落点明确；**续接型章节按开场类型不写章首引子，直接接上一章最后一幕**。**注意：章节文件只含正文结构，质检摘要不写入正文（存于 `04-质检档案.md`）**
8. **先读写作心法**：`references/guides/writing-mindset.md` — 动笔前把心法过一遍（心理描写用"还原"、叙述声音用"人的眼睛"、感官用"私人记忆"、允许无效社交、允许角色失控、不急着化解紧张）。写作时**关掉质检脑**——初稿的唯一任务是写出来，别边写边审。
9. **按细纲场景速写展开正文** — 每个场景严格按"开头→中间→收尾"的结构填入文字；人物状态变化遵循「人物状态追踪」；伏笔操作清单逐条不留痕迹地执行
10. **章节结构要求**（详见 `references/guides/chapter-craft.md` 与 `references/guides/hook-techniques.md`）：
    - **开场类型先行**（写前在细纲/任务卡标明，默认「续接型」）：
      - **续接型**（默认）：本章与上章同一场景/时间线/POV 未断开 → **不写章首引子**，直接从上一章最后一幕的同一时空、同一情绪接着写（可接半句对话、接一个动作中段、接沉默余波）。正文开头**不强制即时冲突**，以自然延续为上，禁止另起炉灶重设钩子。
      - **新起型**：换了地点 / 时间跳了 / 切 POV / 刻意断开场景 → 才写章首引子 50-150 字（用 `hook-techniques.md` 引子七式），正文开头给一个**明确的场景入口**。
        > ⚠ **章首是"慢起"，不要堆张力**——实测 210 章：章首前 20% 张力密度 1.20/千字，其余 80% 是 2.03/千字，**人类低开高走**。张力放中后段。"抓人"= 给明确入口 + 让人物有趣，**不是制造危险**。
      - **跳接型**：时间小跳 / 地点轻移但仍在同一条线 → 一两句桥接带过再进入行动。
      - **日常进入型**：上章以高潮收尾、本章要缓 → 起床/走路/坐车/吃饭/上班/检查装备，给人物一个暴露性格的场合。
    - **张力曲线**：全章至少 1 个张力波峰，且**放在中后段**（不要堆在开头）。**静场章（细纲标「静场」）只要求 1 处情绪高点**，不必有对抗——但要有变化（关系/认知/位置至少变一样）。连续 500 字以上无任何变化才需要引入新张力。
    - **对话占比 ≤40%（护栏，取消原"至少 30%"下限）**，每段对话有潜台词或推进情节目的，说话风格符合人物档案（自查清单见 `references/guides/dialogue-writing.md` 第七节）
      > **为什么取消下限**：原规则"对话至少 30%"逼 Agent 注水。实测人类基线只有 **20.4%**，
      > 而三部 SKILL 小说被顶到 29.5–38.4%。堆出来的全是"功能性对话"——每句都推进情节，
      > 一句废话都没有，反而更假。
      >
      > **新判据**：单章 ≤40%（护栏）；且**全书各章对话占比的变异系数 ≥0.25**（有波动才是人，
      > 每章都稳定在 32% 恰恰是机器）。对话少的章节用叙述推进，不要用对话凑数。
    - 至少 1 个读者预期之外的事件或信息
    - 结尾按大纲/细纲的**章末型**设计（甲·信息结算 / 乙·关系余韵 / 丙·喜剧反转 / 丁·悬念——见 `hook-techniques.md` 第一节；张力曲线：进入 20% / 推进+延宕 60-70% / 落点 10%）
    - **悬念闭环**：每章至少回收一个旧悬念，至少立一个新悬念
11. **字数** — 必须达到 `minWordsPerChapter`（默认 3000）。写作时带着字数意识，但别灌水；不足的部分在步骤 4 统一补
12. 内容不足？使用 `references/guides/chapter-craft.md` 的扩充技巧（场景肌理/关键时刻放慢/内心世界展开/对话层次/次要情节/感官叠加）

### 补字 SOP（字数不足时的标准操作，来自 Reasonix Pad）

别盲目灌水。找到"角色可以多待一会儿"的三类瞬间，在那里展开质感：

1. **悬空瞬间**：动作做到一半的时刻（手悬在半空、话说到一半）
2. **沉默间隙**：一句话说完没人接的空当
3. **过渡空白**：场景切换前、站在门口的那几秒

每处用"质感三问"展开 100-200 字：
- 身体在做什么？（手放哪、呼吸节奏、脚的位置）
- 环境在变化什么？（光影移了多远、温度、远处的声音）
- TA 注意到了什么无关细节？（窗帘褶皱、水渍、一只瘸腿的猫）

找到三处即达标。**严禁**：结尾补字、对话灌水、无意义的风景堆砌。

### 步骤 3：质检（创作与质检状态严格分离）

初稿完成后，从"作家"切换为"质检员"。**先按 `costMode` 分流**：

> **铁律九（成本纪律）——本步骤是成本大头，必须批量化：**
> **一条命令一次跑完全部脚本**（上面 4 个 check_*.py 用 `;` 串起来），**一次**读完整报告，拿到**全部**超标项再进入修改。
> **禁止「跑一个脚本 → 看结果 → 改一处 → 再跑一个脚本」**——实测这种方式导致 30 次脚本调用/章、63 次 LLM 调用/章，成本放大 135 倍。**本步骤 ≤2 次调用，全章 ≤4 次脚本调用。**

- **`costMode: "low"`**：**机械项照跑全量脚本**（6 个，0 reasoning token），**判断项合并成一次调用**做（AI味自评 + 人味配额 + **四项独立测试** + 一句可执行改法）——**这不是"跳过质检"，是"不再分 4–5 次问"**。人味项目（写前声音预置／人类范本／加法层／世界设定包／作者画面）**一个不砍**。规则见 `references/guides/low-cost-mode.md`（**唯一事实源**）。
- **`costMode: "standard"`（默认）**：走下方全量质检。**质检分两层：机械质检（子技能）→ 深度质检（内建指南）。子技能已安装时必须调用（见 guide-index.md 子技能触发表）。**

**先做机械质检**：加载 `reasonix-novel-hard-check` 子技能，执行三查（字数 / 硬性句式 / 圣经一致），输出【通过/退回】。退回 → 按机械问题修复后复检。子技能未安装 → 用 `references/guides/hard-style-check.md` 兜底。

**再做节律检测（脚本，硬指标）：**

```bash
python scripts/check_human_rhythm.py 第XX章-标题.md
```

**退出码 1 = 本章不合格**，与字数不够同等级处理。它测的是句法层（句首代词 / 句首引号 / 平均句长 / 破折号 / 身体部位 / 情绪词 / 明喻 / 对话占比 / 动作短语密度），规则与目标值见 `references/guides/human-rhythm.md`。

> **这一层是 AI 味最重、也最容易被"我觉得挺有人味的"糊弄过去的一层。** 主观判断不可信，数字可信。
> 注意其中两项是**区间**不是下限：情绪词 0.25–0.5/千字（AI 被禁到只有人类的 1/3）、明喻 0.8–1.5/千字（顶格写满就是 2 倍）。**这两项不是越低越好。**

**再做深度质检（七件事）：**

1. **字数** — 运行脚本：`python scripts/check_chapter_wordcount.py 第XX章-标题.md`（低于下限必须补足，用「补字 SOP」或调用 `reasonix-novel-pad` 专业补字）
2. **硬性句式拦截（已脚本化，有退出码）** — `check_aistyle.py` 判「先否定再肯定」：**「不是X，是Y」（同句）硬线 0.12/千字**、「不是X。Y是…」（跨句）硬线 0.40/千字。**超标即 exit 1，逐句重写。**
   > ⚠️ **不要只盯"不是…而是…"**——实测 AI 早已改用「是」绕开旧口径（人类 0.087/千字 vs AI 0.011/千字，旧规则完全失效）。
   > 改法：改成**直接陈述 Y**；或把否定句独立留白（`human-exemplars.md` 技法三「故意不解释」）。
3. **AI 味自评**（**强制，不可跳过**）— 执行 `references/guides/ai-taste-selfcheck.md` 的自问量表（现已 11 项，含「开场同质」一项），逐项判定"人侧/AI侧"，回答终极问题【这篇小说是不是AI写的？】并给出证据段落。**4 项以上 AI侧 → 必须加载 `reasonix-novel-deai` 子技能做六步深度清洗**（子技能未安装才用 deai-workflow.md 兜底），清洗后复评
4. **人味配额验收**（**强制，不可跳过**）— 执行 `references/guides/human-quota.md`：数毛边/废话/比喻/金句/意象/情感表达差异 + 运行 `python scripts/check_repetition.py 第XX章-标题.md`（必须 0 重复）。任何一项 ✗ = 本章不合格，补人味后复验
4.5 **统计指纹检测（脚本）** — 运行 `python scripts/check_aistyle.py 第XX章-标题.md`：查转折词/模糊词/顿悟词/明喻密度 + 动作短语密度 + **通用模板短语**（"一个人/这一刻/走廊里"这类任何小说都能套的通用词——人类高频词是专有名词）。模板短语命中 ≥2 次 = 换成专有名词或独一无二的具体物（见 `references/guides/rewrite-playbook.md` 第 10 节）
5. **杠精自检** — 换上挑刺读者的视角，找最经不起推敲的 1-2 个点
6. **连贯性与逻辑检查**（**强制，不可跳过**）— 执行 `references/guides/continuity-check.md` 的「衔接三查」（开头承接/人物状态连续/伏笔登记）+「逻辑 BUG 四查」（因果链/人物动机/信息一致/世界规则）。发现断档或 BUG → 立即修复
7. **剧作与人味** — 读完最后一段想不想看下一章？有没有"文学在场感"？对一遍圣经一致性（人名/地名/设定/时间线）

**深度质检发现专项问题 → 按症状调用子技能（专业版，见 guide-index.md 触发表）：**

| 症状 | 调用子技能 |
|------|-----------|
| 对话生硬、角色一个腔调 | `reasonix-novel-dialogue-master` |
| 没毛病但差口气 | `reasonix-novel-write-master` |
| 该燃/虐的地方没反应 | `reasonix-novel-mood-composer` |
| 平淡、不够爽 | `reasonix-novel-thrill-booster` |

子技能执行后，把结果写回 `04-质检档案.md`（留痕），继续后续收尾。

### 专项检查排班制（硬性，不由自检结论决定）

**关键原则：Agent 的自检结论不可信——"我认为这章没问题"恰恰可能是 AI 味的来源。** 检查型工具（对话/情绪/节奏）**固定排班、到点必调**，不因自检"没问题"而跳过；自检结论只用于触发修复型工具（DeAI/Write Master/Pad 等，没病不治），不用于决定"是否检查"。

| 排班 | 必须调用 | 说明 |
|------|---------|------|
| **每章** | `reasonix-novel-hard-check`（机械质检） | 保持不变 |
| **每章** | `reasonix-novel-dialogue-master`（**对话打磨**） | **AI 味重灾区，每章必调**——检查"对话洁癖"（太干净/太对/太有礼貌），主动加混沌（填充词/口误/接不上） |
| **每章**（轮换） | `reasonix-novel-mood-composer`（偶数章加查情绪） | 奇数章只调对话、偶数章对话+情绪都调 |
| **锚点章/高潮章**（qualityLevel=anchor） | `dialogue-master` **+** `mood-composer` 全调 | 精写章不轮换，两个专项都查 |
| **每 3-5 章** | `reasonix-novel-rhythm-check`（节奏诊断） | 固定批次节点，不因"节奏感觉没问题"跳过 |
| **每章**（自检后） | 读者视角自检（内建版 Reader Simulator） | 以普通读者通读本章：走神点/太假对话/钩子强度三问——卷终主编组织完整 reader-sim |

**执行方式**：调用子技能时，按该技能的完整流程执行（诊断 → 输出结论/修改）；即使子技能判定"无需修改"，也要把"检查结果：通过"记入 `04-质检档案.md`——**检查必须发生，通过也是结果**。

> 轮换制的原因：每章全调所有专项成本过高且拖慢流程；轮换保证"每个专项至多隔一章必查一次"，锚点章全查兜底。若主人希望更高强度，可改为每章全调。

### 步骤 4：置信度定档（铁律七）

质检完成后、修改之前，给这一章定一个档，然后**必须选中且仅选中一个出口**：

| 读数 | 触发（任一） | 出口 |
|---|---|---|
| **稳** | 人侧 ≥7 项 且 评分 ≥70 且 无未决杠精点 | 直接进入步骤 5 修改 |
| **薄** | 人侧 4-6 项 / 评分 65-69 / 有 1 个未决杠精点 | 在质检档案**点名最薄的一项 + 理由**，然后进入步骤 5 |
| **晃** | 人侧 ≤3 项 / 评分 <65 / retryCount ≥2 | **禁止直接进步骤 5。** 三选一：①升到锚点章标准全调专项后重检 ②换路重进入（见下）③停下问用户 |

**换路重进入怎么做**：不要在原稿上改。用 200 字把"这一章要完成的三件事"用**完全不同的原语**重述——例如从"场景清单"改成"人物在这一章失去了什么 / 得到了什么"，或从"情节推进"改成"这一段要让读者误会什么"。然后按新说法重新动笔。

**读到「晃」还继续，是这一条存在的全部理由。** 一次没有选中出口的估计不是监控，是评论。

### 步骤 5：修改与收尾

1. 修改质检发现的问题：硬性句式一个不留；杠精发现的硬伤修掉；有意保留的设计（如角色的"不合理行为"是伏笔）确认是自觉选择
1.2 **【铁律九·成本纪律】一次批量改写**：把质检报告里的**全部**超标项列成一张清单，**一次改完**（能并成一次工具调用的并成一次），然后**复跑一次**全部脚本确认。
   **禁止「改一项 → 跑脚本 → 再改一项 → 再跑脚本」**——实测这种方式导致每章 12–27 次文件改写。**全章文件改写 ≤5 次：初稿 1 + 批量修 1–2 + 台账回写 1 + 缓冲 1。**
   > 为什么这样不减质量：脚本已经把问题量化成数字了。分 10 次改和一次改完，得到的**信息完全相同**，区别只是多付了 9 次全上下文重发（每次都在几百 k 的上下文里）。
1.5 **节律超标逐项改**：`check_human_rhythm.py` / `check_aistyle.py` 报哪项 FAIL/超软，就翻 `references/guides/rewrite-playbook.md` 对应节，按"招"逐条改，改完重跑脚本直到退出码 0。**改的是句子的组织方式，不是指标本身——先改句首代词、再合并碎句、再调情绪配比，最后精修比喻/动作/数字**（顺序见 rewrite-playbook 附节）
2. **单点手术原则**（来自 Reasonix Write Master）：修改时不要全面润色——找到**最可惜的那一处**，在原有基础上往下挖（改完附一句直觉理由）。全面重写反而容易把有生命力的细节磨平
3. **字数补足** — 不足则用「补字 SOP」（三类瞬间 + 质感三问）展开薄弱处
4. **再次运行字数脚本确认**（如第一次未达标）
5. 生成章节摘要 — 在 `01-大纲.md` 的章节摘要区追加（300-500 字，作为后续章节的连贯性参考）
6. 更新 `02-写作计划.json` — `status` → `"completed"`，填入 `wordCount`、`wordCountPass`
7. **质检摘要写入质检档案**（`04-质检档案.md`，**不写入章节正文**——正文保持纯净可发布）。在档案中追加本章记录：
    ```
    ### 第N章 [标题]
    - 最终字数：XXXX（达标/未达标）
    - 硬性句式扫描：已清零
    - **写前声音预置（动笔前写的三行）**：具体坐标 / 叙述者立场 / 留白点
    - **人类区间命中率 X/Y = XX%**（★ 人类单章 p10 18% / 中位 35% / p90 53%；**硬线 ≥20%、软线 ≥35%**）
      ⚠️ 这一项**不是越高越好**：人类章是分散的，异常居中（>55%）可能是被指标驯化的痕迹
      —— 这一项和"退出码"回答的是不同问题：**退出码只答"有没有硬伤"，命中率答"离人类有多远"**。
      实测真实项目的教训：10 章**全部退出码 0**，但命中率只有 29–47%（平均 34%）——
      平均句长低于人类下沿 10/10 章、动作短语 10/10 章（值为 0.0）、长对话 9/10 章。
      **"全绿"被读成了"达标"，实际是系统性欠写。** 命中率 <70% 时，必须写出偏低的是哪几项、怎么补。
    - **节律检测（check_human_rhythm.py 退出码 X）**：
      句首代词 X%（≤15）/ 句首引号 X%（≥15）/ 平均句长 X 字（目标 23–37，底线 18）/ 破折号 X（≤1.5）/
      身体部位 X（≤1.0）/ 情绪词 X（0.25–0.5）/ 明喻 X（0.8–1.5）/ 对话 X%（≤40，护栏）/
      动作短语密度 X（≤0.4）/ **单句成段 X%（≥40，弱）** / **作者在场 X（2.5–12）**→ **未达标的项逐条写明"翻改写库哪一节、怎么改"**
      另（不跑脚本、人工核）：**对话标签是否用「道」**（人类「道/说」4.7–99.8，AI 是 0）／**省略号档位是否全书一致**
     **【独立质检子代理 · 脚本全绿也要做】**：脚本测频率，**测不出同构/空转/有没有人**。另起一个子代理，**只给纯正文**（不给细纲/规则包/改动说明），跑四项：同构测试 · 删除测试 · 作者在场测试 · 用力过猛测试——模板见 `references/guides/review-agent.md`
    - AI 味自评：人侧 X/10 — 终极自问判断 + 证据
    - 人味配额：毛边X/废话X/比喻X（非明喻≥1）/金句X/意象第X次/情感差异✓ / 重复检测 0 处
    - 叙述者插话：X 处（目标 1–3）
    - 专项检查：对话-master [通过/发现X] 情绪-master [通过/发现X] 节奏-check [第X批/通过]
    - 杠精自检：最经不起推敲的点，及处理决定
    - 衔接检查：通过/未通过 — 承接上章一句话
    - 逻辑检查：通过/未通过 — BUG 四查结果
    - 质量评分：XX/80 — 8 维明细（参考 guides/quality-scorecard.md）
    - 吸引力 / 一致性：...
    ```
    同时把章节备注的伏笔标记同步到 `01-大纲.md` 伏笔对照表。

### 步骤 6：注册审计（铁律八）

扫一遍本章正文，确认三件事：

1. 无**细纲记号**（`【场景1】`、`衔接锚点：`、`[待补]` 之类）
2. 无**质检字段**（AI 味自评、质量评分、杠精结论等一律只进 `04-质检档案.md`）
3. 无**未展开的私人缩写**（内寄存器里的 `林砚：知密道✓` 不得原样出现在正文里）

命中的就地展开或删除。长跑中压缩寄存器会往外渗，而你是最后一个发现的——所以这一扫在**每章**都做，不是交付前做一次。

### 步骤 7：创作台账回写

更新 `05-创作台账.md`：

1. **Verified** 追加本章新落地的既成事实（编号追加，永不改写），每条标注依据章号
2. **Open** 关闭已被本章终结的问题（编号不复用），或新增本章暴露的未知
3. **Next** 改为下一个动作（永不为空）
4. 推进"最近重读章号"为本轮

**写 Verified 时遵守三态铁律**：只把**已经写进正文**的东西标 `✓`。规划中、打算写、可能要写的，一律 `?`。

## 3. 子Agent并行模式（writingMode: "subagent-parallel"）

> **本模式完整机制见 `references/guides/parallel-workflow.md`（分层保真并发工作流）——必须阅读并遵守。** 核心要义：**创作方向串行（主编独占），文字执行并行（子代理填字）；依赖串行保真，独立并行提速。** 并发质量不靠子代理自觉，靠主编的细纲、台账和交叉评审。

### 核心机制（摘要，详见 chained-pipeline.md + parallel-workflow.md）

> **⚠ 默认策略是「链式流水线」（`references/guides/chained-pipeline.md`），不是"一次派 5 章各写一章"。**
> 原因：章节是**链式依赖**的——第 N+1 章的开头必须接第 N 章的**结尾**。一次派 5 章时，第 2-5 章的真实结尾**还不存在**，子代理只能靠细纲"猜"前文——逻辑 BUG、延续性差、以及"第 3 章先于第 2 章完成"，全从这里来。而且**乱序是章节并行的数学必然，不是纪律问题**。

1. **并行单位 = 工序，不是章节**（链式流水线）：
   - **笔手**（写作子代理）：**一章接一章串行写初稿**，每章开写前拿到上一章的**真实结尾**
   - **磨手**（质检/打磨子代理）：与笔手**并行**，打磨已交稿的章节（质检/去AI味/对话情绪专项）
   - **主编**：定接口契约 → 提取真实结尾转交笔手 → 缝合章节边界（承接段/钩子段）
   - 三级策略：**A 链式串行**（定稿才写下一章，锚点章用）/ **B 链式流水**（默认）/ **C 章节并行**（仅"真独立章"——番外/支线日常，不承接上章）
2. **接口契约（冻结，B/C 档必做）**：派发前主编为每章写「进入状态 / 退出状态 / 承接要素 / 交付钩子」，写进细纲。子代理要偏离契约必须先申报 + 更新相邻章契约，不得自己改了往下写。**这是治"状态分叉"的关键**——把两个子代理各自心照不宣的假设，变成同一份白纸黑字的契约。
3. **前序锚点**：每个子代理写前必读——本批细纲 + **上一章真实结尾（500-800 字，由主编从刚写完的正文里截取，不是细纲的"承接自"）** + 状态台账出场人物条目 + 文风锚点示例
4. **状态台账（03-状态台账.md）**：人物位置/情绪/关系/已知信息/伤势 + 伏笔状态 + 时间线——子代理写前读起点、写后写回终态；主编核对一致性
5. **品质分级**：锚点章（开篇/中点/高潮/结尾/卷终）走 A 档（链式串行），主编亲自精写或派最资深子代理
6. **锚点滚动**：每批结束后，主编从本批真实章节抽取最代表文风的 1-2 段，更新下一批细纲的「文风锚点示例」——锚点跟着故事走
7. **两轮质检 + 交叉互检**：子代理自检（第一轮）→ 主编验收（第二轮：硬底线全查 + 锚点章细看 + 风格抽查）→ **交叉互检（第三轮：两两互检，只挑刺不改写）**；注意**互检对象是已定稿章节**，不是还在写的
8. **失败换人**：单章失败 2 次 → 换新子代理重写（附失败原因清单），不退回原路死循环
9. **退回规则**：单章问题退回重写；批次级风格漂移 → 停下、重抽锚点、后批调整
10. **批次闸门脚本化（硬性）**：跑 `python scripts/check_batch_gate.py <项目目录>`——**退出码 0 才许继续下一章/下一批**。它查五项：① **乱序完成**（第3章完成但第2章没完成 ← 治乱序）② 字数达标 ③ 质检痕迹齐 ④ 台账推进 ⑤ 章节边界无悬空钩子。**这把"主编自觉"变成了"可验证的退出码"**。

### 主编流程

```
0. 并发前检查（parallel-workflow.md 第十一节）：细纲完整 / 锚点章已确认 / 台账已建 / 大纲字段全——缺一不开
1. 生成第一批细纲（含全书文风基因 + 锚点示例 + 人物状态总览 + 伏笔总览 + **每章接口契约**）→ 作者确认 → **锚点章"三候选定调"**（见下）
   > ### ★ 锚点章改为「三候选定调」（2026-09-23）
   >
   > **问题**：实测锚点章（第 1 章）跑了 **486 次**脚本调用，而中位章只有 **6** 次 = **32 倍**。
   > 原因不是它更该打磨，而是**它的交付物被定义错了**：
   > 锚点章的真正产出是**一段 150–250 字、可被后续 50 章模仿的锚**，
   > 不是"一份 17 个指标全绿的稿"。**这是两个不同的优化问题，搜索空间差一个数量级。**
   >
   > **做法（选择优于迭代）**：
   > 1. 先在**锚点章前**写 **3 个不同声音取向的开篇**（各 300–500 字，**不写整章**）；
   > 2. 作者挑一段（或指出"我要 A 的句子 + C 的节奏"）；
   > 3. **锚定了才补完整章**，此时锚已确定，后续所有章受益。
   >
   > **为什么便宜**：迭代路线 = 1 份稿 × 20 轮修改（20 次生成 + 20 轮上下文重发）；
   > 选择路线 = **3 份候选 × 1 次生成 + 一次"挑"**。3 次 < 20 次，
   > 而且"挑"这个动作**不需要重发上下文**。
   >
   > **锚点章的验收标准也随之改变**：不是"整章指标全绿"，
   > 而是「**这段锚能不能定住后续章**」——即它能否让下一个写手照着写出同一种声音。
2. 链式流水循环（章序串行，工序并行）:
   a. 【主编】定本章**接口契约**（进入状态 / 退出状态 / 承接要素 / 交付钩子）
   b. 【笔手】写第 N 章初稿 —— 任务包含：契约 + **上一章真实结尾** + 台账条目 + 锚点示例
   c. 【主编】笔手交稿 → **立刻提取本章真实结尾 → 派笔手接着写第 N+1 章**（不等打磨完成）
   d. 【磨手】并行打磨第 N 章（节律/词汇脚本 + 硬性句式 + 去AI味 + 对话/情绪专项）
   e. 【主编】磨手完成 → **缝合边界**（开头承接段接住上章结尾 / 结尾钩子段留下章接口）
   f. 【主编】跑 `python scripts/check_batch_gate.py <项目目录>` —— **退出码 0 才继续**；然后更新台账 + 滚动锚点 → 下一章
3. 全部章节完成 → 进入 Phase 4：自动校验
```

> **为什么 c 步"不等打磨"**：笔手只负责初稿，打磨不产生剧情。让笔手连续写、磨手跟着磨，速度不丢；而初稿链是串行的，所以**连贯性由"上一章真实结尾"保证**。这就是"并行单位从章节换成工序"的落地。
>
> **什么时候退回批次并行**：只有主编在细纲里显式标注 `独立章：可并行` 的章节（番外/支线日常，不承接上章），才允许多章同派（C 档）。默认全走链式流水（B 档）。

### 子 Agent 任务指令（每章一份，随任务包派发）

> **完整标准模板见 `references/guides/subagent-brief.md`——派发子 Agent 前必读，按模板装配任务包。** 以下为关键升级点（解决"子 Agent 不用体系工具"的历史问题）：

**必须装配给子 Agent 的东西（缺一不派发）：**
1. **工具权限声明**：告诉子 Agent"你有 Skill 工具，reasonix-novel-deai / hard-check / pad / dialogue-master / mood-composer / write-master / thrill-booster 均已安装，需要时直接加载"——**子 Agent 是完整 Agent，不是只会读文件的脚本**
2. **必读文件用绝对路径**：writing-mindset / human-quota / chapter-template / hook-techniques / ai-taste-selfcheck / continuity-check ——主编派发时填真实绝对路径，**找不到不许跳过，停下向主编要**
3. **自检必须调子技能**（不是读内建指南应付）：
   - 加载 `reasonix-novel-hard-check` 做机械质检（通过/退回）
   - AI 味自评 ≥4 项 AI侧 → **必须加载 `reasonix-novel-deai`** 深度清洗
   - **排班专项**：每章加载 `dialogue-master`（对话 AI 味重灾区必调）、偶数章加调 `mood-composer`、锚点章全调——不由自检结论决定
4. **脚本装配**：字数/重复检测（check_repetition）/统计指纹（check_aistyle）——给绝对路径
5. **人味配额**：子 Agent 写作时带配额写（毛边/废话/比喻/金句），自检数数
6. **回报格式**：质检结果 + 专项检查结果 + 人物终态 + 伏笔动作（主编写入 04-质检档案）

> 主编派发检查清单（subagent-brief.md 末尾）：所有占位符已替换绝对路径 / 上章结尾已附 / 台账条目已提取 / 锚点示例已附 / 奇偶已注明 / 锚点章已标记——**四缺一不派发，子 Agent 没装齐工具就开始写 = 裸奔。**

**并发安全**：章节由主编按批分配（一章一代理、批次不重叠）；人物状态与伏笔以台账为准（写前读起点、写后写回终态）；批次间串行保证衔接——不存在写入冲突，也不存在"各写各的"。

## 4. Agent Teams 模式（writingMode: "agent-teams"）

**平台支持时可用**。通过 TeamCreate 创建写作团队，Agent 之间可以通讯协作。

```
1. 使用 TeamCreate 创建写作团队
2. 派生 3-5 个团队成员（使用 Agent 工具 + team_name 参数）
3. 使用 TaskCreate 为每一章创建一个任务
4. 团队成员各自:
   a. 从 TaskList 读取可用任务
   b. 使用 TaskUpdate 认领任务（设置 owner）
   c. 执行「逐章创作流程」
   d. 使用 TaskUpdate 标记任务完成
5. 所有任务完成后 → 关闭团队 → 进入 Phase 4
```

**并发安全**：通过 TaskList 系统的内置所有权语义（owner 字段）和 Agent 间通讯避免冲突。

## 5. 疯狂创作铁律

- 进入本阶段后，**默认全程不打断用户**（除非 `writingTempo: "chapter-by-chapter"`）。锚点章（第 1 章）定调确认是唯一已发生的确认点
- 每章完成后立即认领下一章，循环直到全部完成
- 即使某章写得不满意，也先完成全部章节，把不满意的标记出来（`qualityLevel: anchor` 的章节值得回炉），Phase 4 统一校验、Phase 5 统一打磨
- 只有遇到真正需要用户决策的事（如故事方向重大分歧、用户主动喊停），才中断流程询问
- 写完 3-5 章时，在内部做一次**轻量节奏自检**（不需要打断用户——你既是作者也是主编，在无人打扰的环境里保证质量）：

### 节奏自检清单（每 3-5 章，来自 Reasonix Rhythm Doctor）

对刚写完的批次做四步检查：

1. **判定每章实际节奏类型**（以正文实际效果为准，不看规划）：
   - 紧张章：冲突密集
   - 缓冲章：张力下降，但情绪或信息仍在推进
   - 过渡章：连接事件的桥梁
2. **相邻章节情绪变化**：连续三章以上同类型 → 标记「节奏单调风险」
3. **连续紧张的强度**：连续紧张本身不是问题，前提是强度在升级（小冲突→正面对抗→生死决战）；同级别重复 → 标记「紧张疲劳风险」
4. **缓冲章实质内容**：读完对角色或世界的了解有没有增加？没有 → 标记「空缓冲」风险（缓冲不等于废话）

发现风险 → 在下一章写作时主动调节（如连续紧张后安排缓冲章，或让缓冲章带上实质内容），或在 Phase 4 校验后统一处理。

### 情绪自检（可选，来自 Reasonix Mood Composer）

批次内如果有预设的关键情绪节点（牺牲/反转/高潮），检查：
- **蓄能**：节点前 2-3 章有没有让读者积累期待？
- **落差**：事件前后状态差够不够大？
- **释放**：揭示方式有没有延迟放大、留余波？
- **蓄能是否被提前放空**：节点前的章节有没有用一句玩笑把紧张消解掉？
