全书写完后，还有最后一程。这一步决定了作品是"写完"还是"完成"。


## 0. 中途触发（写完后，完稿前）

- **作者想改剧情** → 走 `guides/change-management.md` 变更管理流程（登记→影响评估→分层执行→留痕→验证），改完再继续完稿
- **长篇多卷** → 每卷结束执行 `guides/volume-review.md` 卷末复盘（读者三层反馈→诊断→修订计划→档案更新），再开下一卷

## 1. 一致性通读

通读全书（或抽查关键章节），检查：

- **命名一致性**：人名、地名、专有名词前后统一
- **时间线一致性**：日期、季节、事件顺序没有矛盾
- **规则一致性**：世界观规则（魔法代价、力量体系、社会制度）没有被推翻
- **伏笔闭环**：对照 **`01-大纲.md` 的伏笔对照表**（★ **唯一权威载体**；圣经里的那张是卷终派生视图），检查每个伏笔是否已埋设、已回收；遗漏的标注出来
- **人物状态**：角色位置、情绪、关系、能力变化是否连贯

如果发现系统性偏差（比如某个设定中期改了）→ **必须调用 Bible Updater**（`reasonix-novel-bible-updater`，已安装时）把圣经更新为实际态，确保圣经永远是"活文档"；未安装则按 bible-template 的状态机手动维护。

## 1.5 台账对账（J-Novel 新增）

**这一步查的是"我以为写过的，是不是真写进去了"。** 一致性通读查正文内部的矛盾，台账对账查**台账与正文之间**的矛盾——后者更隐蔽，因为它不会在正文里显形。

逐条执行：

1. 把 `05-创作台账.md` 的每一条 **Verified** 拿回正文核一遍：这条真的写进去了吗？依据章号对得上吗？对不上的改标 `?` 或 `✗`（不删除）。
2. 把 `03-状态台账.md` 与伏笔对照表里所有标 `?` 的条目过一遍：**有没有哪一条被后文当成了既成事实来写？** 命中即修——要么把正文改成真的没发生，要么补写让它发生。
3. 检查是否有该标 `✓` 却还停在 `?` 的（写了忘了改标），一并补上。

> 这是三态铁律最后一次生效的机会。漏到出版之后，读者会比先发现。

## 1.9 全书去AI味：这一遍看的是**整本的分布**，不是"再跑一遍逐章质检"

**为什么要单独走这一遍。** Phase 3 的逐章质检是**单章视角**：每章都"没有硬伤"，
合起来仍然可能整本偏低（实测真实项目：10 章退出码**全 0**，而平均句长 **10/10 章**
低于人类下沿、动作短语 10/10 章为 0——**"全绿"被当成了"达标"，实际是整本欠写**）。
**分布级的毛病在单章报告里根本看不见，只有把全书曲线铺开才看得见。**
Phase 5 是全书最后一道，不补这一遍，前面每一章的"合格"会合起来掩盖"整本欠写"。

**第一步：拿全书曲线，不拿单章报告。**

```bash
python scripts/check_human_rhythm.py --project {项目目录}
```

看的是**系统性**偏离——不是"哪一章哪一项超标"，而是"**哪几项全书同向偏**"。
单章偶发偏离先放过；**全书同向**才是这一步要动的东西。

**第二步：按系统性偏低/偏高，分四层改（顺序不许反）。**

| 层 | 改什么 | 读哪本 |
|---|---|---|
| **频率层**（脚本可测） | 全书多数**偏低 = 欠写** → 先补足（走 A 顺序）；多数**偏高 = 配额拉满** → 再压住（走 B 顺序） | `guides/rewrite-playbook.md`（**A/B 两套顺序** + 第 11 节「改抽象句」） |
| **加法层** | 只删 AI 味会写成白开水——按偏低项去挑招，**挑 3–5 招，不许逐条打卡** | `guides/humanize-toolkit.md`（第〇节「场景 → 上哪几招」表） |
| **清洗** | AI 模板句式／禁用词：**先定位、后改写**（两步不许合并） | 定位读 `guides/ai-cliche-blacklist.md`；**动笔改时合上清单**，改用 `guides/occupancy-rewrite.md` 的**占位式**（说"**这里要放一个具体的东西**"，不说"不要写泛泛的感慨"） |
| **本体层** | 把通用件换成只属于这本书的实物（**频率层补完才轮到它**） | `guides/specificity-gate.md` 第三节：**可替换性四问**（换名／换书／删句／复述） |

> ⚠️ **「先定位、后改写」这条分工与 Phase 3 清单第 5 项（改写阶段）逐字同源，
> 两边口径不许不同。** 机制理由见 `guides/occupancy-rewrite.md` 第三节：
> **念清单的时机会毁掉清洗**——刚读完禁用清单就动笔，那些句式正处在激活态。
> 正确形态是**一张清单定位 + 一句占位指令动笔**（"一句诊断 + 一句占位指令，胜过一整张禁用清单"）。

> ⚠️ **顺序反了会越改越干。** ① 频率层没补完时句子还是碎的，在碎句上改具体性 =
> **在碎句上贴金**（改完还是一堆短句，具体性上去了、手感没变）；
> ② 频率层全绿 **≠** 本体层过了——17 项全是频率指标，全绿只说明"不像 AI 的平均像"。

**改完再跑一次 `--project` 确认曲线真的动了**——指标没改善 = 这一遍无效 = 重做。

## 2. 节奏评估

评估整体节奏：

- 有没有拖沓的章节（连续多章低张力）？
- 有没有过快的段落（重要转折一笔带过）？
- 高强度章节和缓冲章节的交替是否合理？

**必须调用 Rhythm Doctor**（`reasonix-novel-rhythm-check`，已安装时）逐章分析节奏类型、情绪曲线，标记节奏单调/紧张疲劳/缓冲空洞的风险；未安装用 phase3 的节奏自检清单兜底。建议加调 **Mood Composer** + **Reader Simulator** 做"三合一"健康检查（节奏、情绪、读者感受三个维度）。

## 3. 开篇重审

回头看看第一章——它够不够吸引人？

- 前 20% 是否建立了即时冲突？
- 核心钩子是否在第一章就亮出来了？
- 如果不够 → 重写开篇段落（参考 `references/guides/chapter-craft.md` 的十种开头技巧）

**第一印象只有一次。** 这是全书最重要的一章，值得花最多时间。

## 4. 结尾收束

- 对结尾章节调用 **Reader Simulator**（`reasonix-novel-reader-sim`），确认收尾有力、悬念闭环
- 检查全书的核心问题（采访第 6 轮确认的主题）是否通过主角的转变得到了回应
- 结尾是"合上书的最后一口气"——读者带着什么离开这本书，取决于这里

## 5. 后记、尾声与番外

询问用户是否需要：

- **后记**：作者创作谈、灵感来源
- **尾声**：故事主线结束后的余韵
- **番外**：支线人物、平行视角的补充故事

### 我的保留（必填）

```
💭 我的三个保留：
1. [一句话] —— 理由：[一句话]。（你可以不采纳，但你应该知道我为什么这么想）
2. …
3. …
```

完稿阶段最容易被咽下去的话：某一章其实没达到锚点章的水准、某个支线到最后也没收干净、某处为了赶进度做了妥协。**写下来。** 作者的利益优先于作者的舒适。

### 未检查项（必填）

把 Phase 4 带过来的未检查项更新一遍——哪些已经补查了，哪些仍然没有。

```
⚠️ 未检查项：
- [仍未被检查的部分] —— 建议：[谁来查 / 什么时候查]
```

**每件完成的事都有一个未检查的边缘。** 不写这一节，读者会默认"全都查过了"。

并把作品信息追加到 `user-preferences.json` 的 `creationHistory`（供下次创作的偏好参考）。
