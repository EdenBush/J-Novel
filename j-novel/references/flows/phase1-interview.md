# Phase 1：深度采访（挖掘模式）

**这是整个流程里最重要的部分。没有之一。** 别急着动手写。在动笔之前，你要通过系统的深谈，帮作者把脑子里那个模糊的念头变成一张清晰的地图。

你继承的是 Weaver Pro 的"故事采访"，并升级为**挖掘模式**：不局限于固定的七轮对话，而是**分析用户的每一句话**——无论是一句简单的提问还是一段复杂的表述——从中挖出情绪、动机、期待和画面，不断追问，直到故事被磨到经得起推敲。

```
本阶段执行清单：
[ ] 1. 【必须】加载采访挖掘引擎：读 guides/interview-engine.md（五层分析 + 追问策略库）
[ ] 2. 【必须】逐轮挖掘：分析用户每句话 → 追问 → 更新蓝图进度表（缺哪挖哪）
[ ] 2.5【必须·随时】**自动触发检测**：作者说出具体剧情意图（"第X章他……""我想让他……""有个场景……"
    "最后他……"）→ **立刻切剧情脚手架，把那个片段挖出来**（读 `guides/plot-scaffold.md` 第三节 B）
[ ] 3. 【必须】验收清单 12 项全部"已磨透"（不设轮数上限，只设质量下限）
[ ] 3.5【必须·主动提议一次】**剧情脚手架 + 剧情共创**：验收 12 项全过后，**必须主动提议一次** ——
    提议的是「**要不要现在先把前几章的钩子一起过一遍？我出草案，你看哪里不对**」，
    **不是**「你有什么想法」（把负担从"你来说"换成"你来选"）。
    · 作者给了具体片段 → 用「脚手架五问」挖出并写入 `07-剧情脚手架.md`（读 `guides/plot-scaffold.md`）
    · 作者给不出具体片段（"你看着办"）→ **出第一批剧情卡草案让他表态**（读 `guides/plot-co-creation.md`）
    **问过就算过**：作者说"没有 / 你看着办 / 以后再说"→ 记一行，继续走，**不阻塞**。
    ⚠️ **没问过 = 没做**（实测：29 本书只有 2 本产出脚手架 ≈ 7%，根因是这个"问"的动作被省掉）
[ ] 4. 【必须】生成故事速写（≤500 字）并经作者确认（硬闸门，未确认不进 Phase 2）
[ ] 5. 【必须】生成标题候选并确认（读 guides/title-guide.md）
[ ] 6. 【标准】共识同步 user-preferences.json
→ 清单全勾 + 速写经作者点头 = 本阶段完成，进入 Phase 2
```

## 采访的意义（先读这一段，这是你的态度）

- **采访不是问卷，是挖掘。** 你的目标不是收集完七个话题的答案，而是帮作者把一个念头磨成一个**经得起推敲的故事蓝图**。蓝图多磨一分，写作期就少返工十分。
- **多问一个问题，故事的质量就可能提高一分。** 缓存机制下，采访 20 轮的成本和采访 1 轮差不多——**所以别急着结束采访**。采访不设轮数上限，只设质量下限（验收清单）。
- **不满足于模糊答案。** 作者说"我想写个悬疑故事"——这不是答案，是起点。你要追到"什么谜题、谁在追、代价是什么"才算数。作者说"主角会慢慢改变"——这不是情节，是空话。你要逼出**具体的场景**。
- **每一句话都是线索。** 用户随口说的一个词（"憋屈"、"玉佩"、"从小就想写"）都可能藏着故事的心脏。抓住它，挖下去。

## 核心机制：采访挖掘引擎

**本阶段默认使用 `references/guides/interview-engine.md` 的挖掘引擎。** 它定义了：

1. **五层挖掘**：分析用户的每一句话——情绪层（这句话背后是什么情绪）、动机层（为什么想写这个）、期待层（读者想要什么体验）、想象层（有没有画面/道具/场景）、盲区层（漏掉了什么关键要素）
2. **追问策略库**：情绪追问/动机追问/具象化追问/反例试探/情景假设/代价追问等十式——拒绝"你觉得呢"式空问
3. **蓝图进度表**：验收清单 12 项的实时打勾状态——**缺哪挖哪**，每轮追问后更新
4. **冷场兜底**：用户没想法时，从话题库挑最缺的维度，给选项让 TA 选，不让对话冷场

**执行方式**：
- 用户每回答一句 → 做五层分析 → 找到最有挖头的一条线 → 用追问策略库的招式追问 → 更新蓝图进度表 → 复述共识 → 继续
- 顺着用户的表达流走，不打断、不死守轮次顺序——用户聊到哪，就跟到哪，挖到透
- 直到蓝图进度表 12 项全部"已磨透"，进入采访收尾

## 七轮话题库（兜底题库，非固定流程）

挖掘遇到冷场、或用户明确表示"不知道聊什么"时，按蓝图进度表的缺口，从以下话题库切入。**这是兜底，不是流程——默认不按顺序过七轮。**

### 话题 1：类型与核心悬念
类型方向（奇幻/科幻/悬疑/言情/历史/文学/轻小说，各说优劣）→ 选哪个为什么 → **核心钩子一句话**（"一个穿越故事"无效；"在时间循环里困了三千年的图书管理员突然能带书出来"有效）→ 读者读完第一章冒出的问题

### 话题 2：世界观基石
世界类型（纯架空/类古代/近未来加变量/异世界/封闭空间）→ 底层规则（代价/矛盾/与现实的差异）→ **规则被打破会发生什么**（故事危机的来源）→ 权力格局

### 话题 3：叙事架构
结构（三幕式/英雄之旅/多线/环形/碎片，参考 plot-structures.md）→ 篇幅（总章数/每章字数）→ 视角（**最合适还是最顺手？**）

### 话题 4：人物星系
主角想要 vs 需要（裂缝在哪）→ 恐惧如何阻碍 → 对手（自己故事里的英雄 + 对手眼中的主角）→ 配角阵容（各有动机和弧光）→ 关系网（谁瞒着谁什么）

### 话题 5：情节引擎
升级阶梯（日常动摇/不可逆事件/代价加重/虚假胜利/一无所有/最终对峙，**每级逼出具体场景**）→ 中点反转 → 伏笔（埋哪收哪/烟幕弹）→ 节奏

### 话题 6：主题与意义
故事在讨论什么 → 道德困境（两难落在哪个具体情节）→ 主题通过主角转变体现

### 话题 7：风格与语言
叙述风格（给方向）→ **参考书/作者**（希望"读起来像"谁——变成细纲文风锚点素材）→ 对话叙述比例 → 方言/语言标记

## 采访打磨验收清单（进 Phase 2 前的硬闸门）

**无论采访走了多少轮，逐项核对。有任何一项不过，回去继续追问——不允许带着未打磨的设定进入规划。**

- [ ] **核心钩子**：能用一句话说清，且够锋利（"一个穿越故事"这种无效钩子 = 未通过）
- [ ] **第一章承诺**：读者读完第一章心里冒出的问题已明确
- [ ] **世界观规则**：底层规则清楚，含"规则被打破会发生什么"
- [ ] **主角想要 vs 需要**：分离清楚，恐惧明确且知道它如何阻碍主角
- [ ] **对手自洽**：对手有"自己故事里的英雄"级动机，与主角矛盾不可调和
- [ ] **升级阶梯**：主冲突的每一级都有具体场景（无空话）
- [ ] **中点反转**：已设计（除非作者明确不采用）
- [ ] **伏笔**：至少一组主线伏笔（埋/收位置明确）
- [ ] **主题**：一句话说清故事在讨论什么
- [ ] **叙述风格**：已确定（含对话叙述比例）
- [ ] **篇幅规格**：总章数、每章字数已定
- [ ] **标题**：已生成候选并确认（用 `references/guides/title-guide.md`）

## 剧情脚手架 + 剧情共创（**必须·主动提议一次** · 把作者已有的剧情挖出来 / 或给草案让他选）

**验收清单全过之后、故事速写之前，做这一件事。**

上面那 12 项验收磨的全是**内核**（钩子/世界观/人物/主题）。
但作者心里可能还有更具体的东西——"第 3 章他遇到铁匠""第 5 章当众打脸""最后他站在塔顶"。
**这些在现有流程里没有采集入口**：它们不是内核（回答不了"这本书在讨论什么"），
也不是细纲（细纲是下游产物）。如果不专门问，作者这句话就没地方放，
最后会被 Agent 按通用节奏推导出来的大纲**盖掉**。

> ### ⚠️ **主动提议一次 = 必须做，不阻塞**
>
> - **必须做的只有一个动作：问。** 提议的是「**要不要现在先把前几章的钩子一起过一遍？
>   我出草案，你看哪里不对**」——**不是**「你有什么想法」。
>   前一种作者只需要**反应**（任何作者都做得到）；后一种要他**凭空生产**（没想法的人当场卡住）。
> - **作者怎么答都不影响流程继续**：说"没有 / 你看着办 / 以后再说" → **记一行，继续走**。
> - **没问过 = 没做。** 实测 29 本有 AI 推导大纲的书里只有 2 本产出脚手架（≈ 7%），
>   根因不是"作者没想法"，而是**"问"这个动作被省掉了**。
> - **也不要反向加码**：绝不要求"作者必须改点什么"才放行——那会把作者赶走
>   （见 `guides/plot-co-creation.md` 4.4 的防退化判据）。

```
[ ] 主动提议一次：验收 12 项全过后问一句 ——
    "要不要现在先把前几章的钩子一起过一遍？我出草案，你看哪里不对。"
[ ] 分支 A · 作者给了具体片段（时序 + 动作，如"第 5 章他当众复原那把剑"）
    → 用「脚手架五问」逐条挖（定位 / 内容 / 因果 / 情绪 / **画面**）
[ ] 分支 B · 作者给不出具体片段（"你看着办""都行""随便"）
    → **不要追问，改出草案**：读 `guides/plot-co-creation.md`，
      出第一批（默认前 5 章）剧情卡草案（逐章四件 + 每章 3 个带代价的钩子候选）→ 让他选/改/否
    → 他说"你看着办" = **共创完成**，按你推荐的记下来
[ ] 作者说"没有 / 以后再说" → 记一行，继续走，**不阻塞**
[ ] 边采访边检测：作者一旦说出具体剧情意图 → 立刻切脚手架，挖完再回来
[ ] 产物：`07-剧情脚手架.md`（**只记作者的原话与画面，Agent 不得覆盖**）
    ／ 或首批 `细纲/剧情卡-第01-05章.md`（共创结论，含 Agent 草案被采纳的部分）
```

**为什么值得做**（三条）：

1. **它保护作者的想法**——否则"第 5 章当众复原"会被换成 Agent 编的第 5 章。
2. **它给人一个"选"的机会，而不是"写"的任务**。大多数作者心里没有具体剧情、只有品味，
   给他三个带代价的候选，他至少能说"第二个吧"——**而这一句就是共创的全部成本**。
3. **它是人味的直接来源**。追问「问 5 · 画面」时，作者给出的具体画面
   （"他修的时候没人看，他自己在那儿看了半天"）**自带人味**，
   比 Agent 凭空编的具体性强一个量级。这几句会**原样进子代理任务包**，
   是整条流水线上最珍贵的素材——因为那是**作者自己的眼睛**。

> **完整方法**：
> · **采集模式**（作者已有具体剧情）——五问的追问话术、"粗/中/细"三档密度、
>   追问改前改后示例、产物模板、与 Phase 2/3/4 的四处接口、反模式：
>   见 **`references/guides/plot-scaffold.md`**。
> · **共创模式**（作者只有品味，没有剧情）——剧情卡格式与字段、每章 3 个带代价的钩子候选、
>   六类钩子方向、作者四种表态怎么记、三档经济性（全磨/推荐/节流）、三站齐备、反模式：
>   见 **`references/guides/plot-co-creation.md`**。

> **⚠️ 后续批次的主力时机在 Phase 2/3**：细纲是**分批生成**的，所以**每批细纲展开之前**
> 都要走一次"出剧情卡 → 磨 → 再展开"，这是最便宜的修复点（让作者改 5 行，
> 他愿意改；让他改几百行细纲，他只会点头）。本轮只负责**时机 A（采访末的第一次提议）**。

## 采访收尾：故事速写（作者确认的硬闸门）

验收清单全过后，用一段话帮作者总结整个故事蓝图："好的，经过这几轮深谈，我帮你梳理一下我们目前达成的共识……"

然后给他一个不超过 500 字的故事速写：世界观一句话、主角一句话、核心冲突、主题、章节规划。

**然后生成标题候选**：使用 `references/guides/title-guide.md` 生成 3-5 个候选（不同技法、附理由），供选择迭代（最多 5 轮）。

**速写确认是硬闸门**：
- 作者对速写有任何不满意 → 回到对应维度继续打磨，改到点头为止
- 作者点头 → 速写 + 标题进入 Phase 2 规划
- **没有作者确认的速写，不允许进入 Phase 2**——这是"故事没打磨清楚就直接开写"的最后防线

## 快速模式（仅限作者明确要求时）

只有作者说"快一点""直接写吧""别问那么多"时才启用。**不允许你主动提议跳过采访。**

快速模式下：
- 挖掘引擎降速：每句话只做两层分析（情绪层 + 盲区层），只追问最有价值的一条线
- **必须走完验收清单的最小版**：钩子、主角（想要/需要）、冲突（升级阶梯至少三级）、世界观规则、主题、篇幅六要素——缺哪个，当场补问
- 若作者连最小版都拒绝，进入 Phase 2 时用合理默认值补齐，并在规划摘要中**显式标注"默认值，未经作者确认"**，规划确认时让作者一并审

> **Phase 0 快捷入口的约束**：只有用户首次输入已明确覆盖「钩子/主角/冲突/世界观/篇幅」五要素时，才允许跳过采访直接规划；否则一律进入本阶段。跳过后，Phase 2 规划摘要必须标注"未采访，设定为提取/默认值"，请作者确认。
