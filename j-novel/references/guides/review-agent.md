# 独立质检子代理（Review Agent）——脚本测不出来的那一半

> **这份指南补的是质检环节的结构性空缺。**
> 现有质检全是**脚本**（`check_human_rhythm.py` / `check_aistyle.py` / `check_repetition.py`）。
> 但实测证明：**脚本全绿 ≠ 像人写的。**
>
> **硬证据（2026-09-13）**：一轮 A/B 里，加了新规则的那一版**所有脚本指标全部通过**（作者在场指数 0 → 7.93，完美落在人类区间），
> **但盲评以 3:0 判负**。三位评委各自独立地从同一个文件里挑出同一组三句：
>
> > 老王在那儿修了六年车，**这种事也值得**专门打个电话去举报？
> > 单数日子的排骨回锅，**这算什么**规律？
> > 天比平时黑得早，六点不到就黑成这样，**这算什么**秋天？
>
> **脚本抓不到"这三句是同一个模子"。** 子代理一眼就抓到。
>
> 所以：**脚本负责"数"，独立质检子代理负责"看"。两者不可互相替代。**
>
> **v7.0.0 补充（四 → 五）**：脚本全绿还有**第二种**失效方式——
> 17 项硬指标 + 成本配额卡**全是频率指标**（句子多长/某项多密/出现多少次/占多大比例），
> 它们**结构上测不到**"这句话里的东西是不是只属于这本书"（那是**本体层**）。
> 所以本指南从四条判据扩到**五条**，新增 **第五项 · 可替换性测试**
> （换名／换书／删句／复述，四问的完整规程与四象限定义见 `specificity-gate.md` 第三节）。

## 一、铁律：**独立性**

**质检子代理的价值全部来自"它不知道你是怎么写的"。** 一旦它看了写作过程，它就会替你辩护。

| 必须做 | 绝对不能做 |
|---|---|
| 只给**纯正文**（标题 + 正文，无任何元数据） | ❌ 不给细纲、大纲 |
| 每个质检子代理**独立启动**（新上下文） | ❌ 不给规则包、不告诉它"我用了什么规则" |
| 多个子代理时**各自独立**、互不可见 | ❌ 不给"我这次改了什么" |
| 让它自己判断，不给结论暗示 | ❌ 不给它看脚本报告（那会锚定它） |

> **反例**：如果你告诉它"我这章加了'作者在场'的规则"，它就会去数评价副词——那叫自我验证，不叫质检。

## 二、任务模板（复制直接用）

```
你是一位资深中文网文读者／编辑，现在只做一件事：判断这段正文"像不像人写的"。

【输入】下面是一章中文小说正文（约 XXXX 字）。你没有它的背景资料，也不需要。
【重要】不要分析作者的意图，不要给建议性表扬。**只报告你能从文本里直接看到的东西，并且必须引用原句。**

请依次完成五项测试：

【测试 1 · 同构测试】
找出全章里**读起来像同一个模子**的句子（句式骨架、功能、在段落中的位置三项都一样，只换了内容）。
- 有几组？每组列 2–3 句原句。
- 如果一句都没有，明确说"0 组"。

【测试 2 · 删除测试】
挑 5 处"看起来像闲笔"的句子，逐句问：**删掉它，故事或人物会变差吗？**
- 给"会变差 / 变淡 / 毫无影响"三选一，并说理由。
- 最后统计：5 处里有几处"毫无影响"。

【测试 3 · 作者在场测试】
把**引号里的对话全部划掉**，只读剩下的叙述部分，然后回答：
**"这里有一个人吗？"**
- 引用 3 处最能体现"叙述者是个活人"或"叙述者是台摄像机"的句子。

【测试 4 · 用力过猛测试】
有没有哪个地方，叙述者/作者**表态太用力、太刻意、像在完成一项任务**？
- **必须引用原句**。如果确实没有，说"没有"。

【测试 5 · 可替换性测试】（分两段：5A 句级三问，5B 章级复述。**两段都要做**）

5A · **句级三问**——先抽样，再逐句跑。
- **抽法**（防"只挑软柿子"）：把本章正文按句号／问号／叹号切成句子，
  **按正文出现顺序等距抽 8 句**（从第 1 句起，每隔「总句数 ÷ 8」取一句）。
  **不许挑**——不许挑"看起来最空的"，不许集中在某一段，不许跨段拼凑。
  不足 8 句就全取，并说明实际句数。
- 对抽到的**每一句**，依次跑这三问：
  ① **换名**：把句里所有专名（人名／地名／系统名／店名／器物名）逐个换成别的，这句还成立吗？
     换完**仍然成立 = 抽象句，不过**。
  ② **换书**：这一句能**原样**搬进另一本同类型小说吗？**能搬 = 通用件，不过**。
  ③ **删句**：删掉它，读者会少知道什么**具体的事**？答案只能是"一个具体的物／
     一个具体的数字／一个具体的动作"；只会少"一种感觉" = 空转，不过。
     （③与**测试 2** 的区别：测试 2 问"删了会不会变差"，允许用"一种感觉"作答；
     ③ 问"删了少知道什么"，只接受物／数字／动作。）
- 每一句**必须输出三行**，缺一行 = 这一句未完成：
    · **原句**：「……」（照抄，不许转述、不许概括）
    · **判**：① 过／不过（换名对照：把 X 换成 Y 之后，这句读成了"……"）；② 过／不过；③ 过／不过（删掉少知道的是：……）
    · **改后写法**：「……」——**不过的必须写出改完之后的完整句子**
- **空答无效**：只写"这句有点空""建议加强具体性""整体具体性尚可"，
  没有原句、没有一句话理由、或没有改后写法的——**这一句视为无效输出，退回重做**。

5B · **章级复述**——整章只做一次，**放在 5A 之后做**（免得被刚抽的 8 句锚住）。
- 现在**不再看正文**，写下你还能复述出的**具体的物**（不是结论、不是情绪、不是人物关系）。逐个列。
- 数一数有几个。**≥3 个算过；少于 3 个不算过。**
- ⚠️ **5B 与上面三问不是一回事**：①②③ 是**句级**（问"这一句"），5B 是**章级**（问"这一章"）。
  它失败通常不代表某一句写坏了，而是这一章**动笔前就没定要写哪些物**。

【最后】
6. 用一句话说：这一章**最该重写的是哪一处**？引用原句。
7. 如果让你删掉全章 10%，你会先删哪些段落？（列出起止句）

【输出格式】按 1–7 分节（第 5 项分 5A／5B 两小节）。**禁止和稀泥，禁止"整体不错"这类结论。**
```

## 三、五条**不可 hack 的判据**（为什么是这五条）

这五条都是**加法式 / 定位式**的，不是打分式的——模型没法"凑"出一个好分数。

| 判据 | 为什么不可 hack | 人类侧的真值 |
|---|---|---|
| **同构测试** | 要求**引用原句**；"没有"也是有效答案。你没法伪造"这三句不是一个模子" | 人类表态是**离散的**；模型是**成套的**（实测同构率 0% vs 16.7%） |
| **删除测试** | 是**二元事实**（删了有没有影响），不是程度判断 | 人类闲笔"删掉毫无影响" **1/5**；AI 稿 **3–4/5** |
| **作者在场测试** | 划掉对话后"有没有人"是**定性**判断，且要求引用 | 人类在场指数 3.73–8.40；AI 0.64–1.89（实测 5 轮里分离最干净的一项） |
| **用力过猛测试** | 专门找**过度执行**——这是最容易被忽略的失败模式 | 实测：配额化的规则让"更用力"变成"更假" |
| **可替换性测试**（第五项，四问见 `specificity-gate.md` 第三节） | 它的产出是「**原文 + 改后的具体写法**」——**套话在这里物理上通过不了**："整体具体性不错"既没有原句也没有改后句子，按规定直接判无效输出。而且它测的是**频率指标结构上测不到**的那一层（见下） | **≥3 个物**（判据；**无人类基线**——见下方诚实标注） |

**第五项为什么不可 hack，说透一点：**

1. **前四项都还在"频率层能看见的影子"里打转**（同构=句式重复、删除=闲笔占比、在场=副词密度、
   用力过猛=表述强度）。第五项问的是另一个问题：**"这句话里的东西，是不是只属于这本书？"**
   ——这需要先知道"这本书是什么"（人物、世界规则、前文），**是理解，不是匹配**。
   17 项频率指标 + 成本配额卡再多加十项，也补不上这个缺口。
2. **它的输出形态天然反 hack**：前四项可以靠"引用原句"约束，
   但一句"这三句有点像"仍然可能糊过去；第五项要求**写出改完之后的完整句子**——
   一个没读懂那句的人**写不出改后句**。所以这里的反 hack 不靠约束语气，靠**交付物的形态**。
3. **它的抽样规则也是反 hack 的一部分**：等距抽 8 句、不许挑，堵掉了
   "只挑软柿子批两句、剩下的夸过去"这条路——这是模型最容易走的那条路。

> ⚠️ **诚实标注（与前四项不同）**：前四项的"人类侧真值"栏是**实测出来的区间**；
> 第五项的 **"≥3 个物"是判据，不是统计量**——我们**还没有人类样本基线**。
> 按本项目"**宁可承认测不了，也不造看起来在工作的闸门**"的纪律：
> 第五项**只定位句子、不设硬退出码**（与 `check_contract.py` 的实物覆盖率**刻意为非阻塞**同理）。
> 等真实项目积累够样本，再谈要不要给它一个数。

> ⚠️ **不要让它打分**（"1–10 分像不像人"）。打分会被"总体不错"这类判断污染，
> 而且模型有把分数往中间拉的倾向。**要的是"哪一句"，不是"几分"。**

## 四、怎么用它的输出（不是评分，是**定位句子**）

| 它报出来的东西 | 怎么处理 |
|---|---|
| **同构组** | **删掉其中一句**（保留最自然的那句）。三步以内的模板组全删剩一句 |
| **"删掉毫无影响" 的闲笔** | 别删——**给它在句子内部付房租**：让它承载信息／态度／笑点／动机中的一样（见 `human-quota.md`） |
| **"这里有台摄像机"** | 按 `narrative-craft.md` 第八节的四类做法补，**但必须遵守三条硬约束**（禁止同构／必须挂钩／区间不是下限） |
| **"用力过猛" 的具体句** | **一律删掉**。用力过猛没有"改轻一点"的版本——那句存在的理由本来就是错的 |
| **抽象句 / 通用件的具体句**（第五项 5A） | 按它给的**改后写法**替掉原句；改不出来的（它没给改后句 = 无效输出）就退回重做。句子层面的活，`concrete-voice.md` 有替换对照表 |
| **复述出的物 < 3 个**（第五项 5B） | ⚠️ **这不是改句子能修的**——5B 失败说明**这一章动笔前就没定要写哪些物**。回生成端：查 `chapters/_meta/<章名>.meta.md` 的「实物清单」是不是没定、或者定了没进任务包（见 `specificity-gate.md` 第二节「实物清单」与 3.2 的 ④） |
| **"最该重写的一处"** | 优先处理这一处，改完再重跑脚本 |

## 五、预算与调度

| 场景 | 建议 |
|---|---|
| **普通章**（costMode: standard） | **1 个质检子代理**，跑上面 7 项（五项测试 + 两个收尾问题） |
| **品质锚点章 / 卷首卷末** | **2–3 个**不同视角（读者／编辑／机械测试），**各自独立乱序**，交叉验证 |
| **低成本模式**（costMode: low） | **独立但极轻**：仍然**另起一个子代理**，但把它的任务包压到最小——**只给本章纯正文 + 五个问题**，不给细纲、不给规则包、不给脚本路径。它的输入比任何角色都小（**它是全流程里最便宜的角色**），所以**"砍它"省不下钱，却砍掉了整条链上唯一"不看规则的眼睛"**。若确需进一步削减，**优先保 测试 1 同构 + 测试 3 作者在场**——这两项性价比最高 |
| **★ 自适应抽检（判据，2026-09-23）** | **强度按「连续合格章数」走**：连续 0–2 章合格 → 全检（**五项**全做）；**连续 ≥3 章合格 → 只做「同构 + 作者在场」**；**任一项失败 → 立刻回全检、计数归零**。这是工业的**跳批检验**：省的是「顺风局的重复劳动」，**不降保证水平**（失败立刻重置，风险窗口不扩大）。⚠️ 与 low 的「合并」是两回事：合并＝降总强度；抽检＝**按风险动态分配** |
| **一次不要超过 3 个** | 超过 3 个的边际收益很低；力气应该花在**改**上，不是**评**上 |

### ★ 第五项带来的增量成本（2026-10-07）

**它不新增调用。** 第五项与其余四项在**同一次调用**里问完（就是"另起一个子代理、只给纯正文"的那一次），
所以**调度口径不变**：普通章仍然是 1 个子代理，不是 2 个。

**唯一的增量是输出变长**：8 句 × 三问，每条要"原句 + 判断 + 改后写法"，
大约多 800–1200 字。这是**它全部的成本**。

**它消掉的是什么**：`check_contract.py` 的实物覆盖率是**字符串级、且刻意为非阻塞**——
一份**全是通用件**的清单（"一件礼物""一杯水""褪色的老照片"）也能 100% 兑现，
于是**没有任何脚本会报警**，而读者读完**记不住一个物**。
这一类问题的修复形态是**整章重写**，不是改几个句子。

> ⚠️ **"整章重写"必须限定作用域（2026-10-09 v7.2.0 修口径冲突）** ——
> 它**不是**"在改写阶段把整章重写一遍"。这是两件事，别串：
>
> - **回生成端重做**：若某章的**生成端承诺**（剧情卡已选定的钩子 ／ `_meta` 的实物清单）
>   **根本没兑现**（清单没定，或定了没进任务包），那是**回 Phase 2/3 的生成步骤**重做，
>   **不是在改写阶段整章重写**。这也是上面 5B 那一行的处置（回生成端）。
> - **就地把段落重写**：**改写阶段**的段落级手段是 **U5（单段）／U6（连续 2–4 段）**，
>   两者都**带强边界、范围限死在单段或段群**，验收 = 功能对账 + 复跑指标 + 契约项逐条核。
>   **不许把 U5/U6 用成"整章重写"** —— 见 `rewrite-units.md` 第一节总表与第二节 2.4。
>
> 判据（二选一）：**病根在"这一章动笔前就没定要写哪些物"** → 回生成端；
> **病根在"文字本身"**（落笔公式化 / 整段平 / 一个腔调）→ U5／U6，就地改，别整章重写。

> **一句话算账：多写一千字的质检报告，换掉一次整章返工。**
> 在 low 模式下如果还要再压，**压的是抽样量、不是判据**——把 8 句降到 4 句，
> 四问照样逐个跑（降的是覆盖率，不是标准）。这是抽检的同一逻辑：**先降强度，不降保证。**

> **⚠️ 2026-09-23 修正（本文件自己和自己矛盾）**：这一行原写的是
> 「四项都做，但**并入「判断合并」那一次调用**」（**当年是四项；现在是五项**——
> 见第三节第五项，但那条修正的理由与测试有几项无关：贵不在"问几个问题"）——而本文件**第六节**同时写着
> 独立质检必须「**另起一个子代理，只给纯正文**」。两者不可能同时成立：
> "并入判断合并"意味着由**同一个 agent**完成，而那个 agent
> ① **知道全部规则**（它按规则打磨的）→ 违反"只给纯正文、不给它看规则"；
> ② **刚打磨过这份稿子** → 违反独立性（人会为自己的改动辩护）；
> ③ 而且它**本身就是被评对象**（打磨质量也在评估范围内）。
>
> **「合并同类调用」这条原则本身是对的**——自评／配额／评分确实是同一个 agent
> 对同一份稿子做多个判断，合并它们只是少问几遍。**但它被误用在了"独立性"上**：
> 独立质检贵不在"问几个问题"，在**由谁问**。这几项测试之所以有效，
> 正是因为评委**不知道"应该长什么样"**。

> **判定"要不要改"的原则**：**两个以上独立评委指向同一处 → 必改。**
> 实测：三位评委各自独立地指向了同一组三句——那不是噪音，那是真缺陷。
> 只有一个评委提到、且引不出具体句子 → 可以先放过。
>
> ⚠️ 这条原则**默认评委是独立的**。若把这几项测试塞进同一个 agent，
> "两个以上评委指向同一处"就退化成"同一个 agent 说了两遍"——**判定依据随之失效**。
> 这也是 2026-09-23 那次修正的实质理由。

## 六、与脚本质检的分工（都要做，不可替代）

| | 脚本（check_*.py） | 独立质检子代理 |
|---|---|---|
| 看什么 | **频率与分布**（句长、密度、标点、占比） | **同构、空转、有没有人、还有这一句里的东西是不是只属于这本书** |
| 输出 | 数字 + 退出码（0/1） | **具体句子 + 修改位置**（第五项还要给"改后的具体写法"） |
| 能不能 hack | **能**（而且实测被 hack 过：底线当目标、配额当目标） | 较难（要求引用原句，且"没有"也是有效答案；第五项要求给改后写法） |
| 谁来做 | 主代理调用 | **另起一个子代理，只给纯正文** |
| 顺序 | 先跑（便宜、快） | 后跑（贵、慢，但抓得住脚本抓不到的） |

**顺序：先脚本后评委。** 脚本能修的先修掉（便宜），剩下的"感觉不对但说不出哪里"的，交给质检子代理定位。

### 实物覆盖率：脚本侧新增的那一半，与第五项的分工

脚本侧新增了 **「实物覆盖率」**（`scripts/check_contract.py`，v7.0.0）。
要说清它**不是**第五项，两件事不一样：

| | `check_contract.py` 的实物覆盖率 | 本文件第五项（可替换性测试） |
|---|---|---|
| 查什么 | **清单承诺 vs 正文兑现**：`_meta` 里写了 5 项，正文里出现了几项 | **清单本身好不好**，以及**正文里的句子是不是只属于这本书** |
| 粒度 | **字符串级**——只数"出现过没有" | **理解级**——要判断"这一项/这一句是否专有、是否可感" |
| 性质 | **刻意为非阻塞**——**因为它没有人类基线**（覆盖率低 ≠ 这一章差，所以它不进退代码） | 只定位句子、不给分数（同样因为无基线，见第三节诚实标注） |

**它不判断清单本身好不好。** 一份**全是通用件的清单**（"一件礼物""一杯水""褪色的老照片"）
也能做到 **100% 兑现**——脚本全绿，文章照旧空。
**"清单里塞通用件"这种问题，只有本文件第五项能抓。**

**所以两边都要做，不可替代**：
只有脚本 → 闸门全绿而文章空；只有子代理 → 清单定完就没人管，写手可能一项都没用上，
而且没有任何退出码提醒。完整的口径见 `specificity-gate.md` 第三节（3.4 与 5.3）。
