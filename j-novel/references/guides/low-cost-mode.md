# 低费用模式（Low-Cost Mode）

> 触发：`costMode: "low"`。给"质量已经满意、但 token 太贵"的场景——用**脚本代替判断、读一次复用、少说多写**，把单章 token 消耗压到标准模式的 1/3 左右，质量下降控制在可接受范围。
>
> 实测基线：标准模式写 6 章花了约 7.6M tokens（每写 1 字正文约烧 570 token）。本模式砍的是这五个大头。

---

## 一、五个 token 大头（实测数据）→ 对应砍法

| token 大头 | 占比 | 低费用模式怎么砍 |
|---|---|---|
| **tool/result**（读 guide 全文回传） | 13–35% | 必读文件从 6 本换成 1 张「写作速查卡」；子代理不读全套 guide |
| **reasoning**（质检人工判断的思考） | 14–19% | 质检降级为只跑 3 个脚本，用退出码代替"我觉得" |
| **assistant/message**（过程叙述+质检报告） | 20–28% | 过程叙述删掉；质检报告一行化 |
| **str_replace 反复重试** | 隐性 | 改文件用 Write 整文件覆盖，禁止反复试 old_str |
| **子代理重复加载**（各自读一遍必读文件） | 隐性 | 低费用模式默认**串行**；并行则速查卡塞进子代理初始 prompt |

---

## 二、低费用模式的硬规则

### 1. 必读文件：只读一张卡

- **标准模式**：动笔前读 writing-mindset + human-quota + concrete-voice + human-rhythm 全文，质检读 5–6 本。
- **低费用模式**：动笔前**只读 `guides/quick-reference-card.md`**（一页，约 1.5k tokens）。质检按卡片数值跑脚本。不再读任何 guide 全文——除非脚本报某项超了，才翻 `rewrite-playbook.md` 对应那一节（只读那一节，不读全文）。

### 2. 质检降级：只跑 3 个脚本

标准模式的质检是：hard-check 子技能 + 节律脚本 + 词汇脚本 + 重复脚本 + 字数脚本 + AI味自评 11 项 + 杠精 + 连续性 + 逻辑 + 评分 + dialogue-master + mood-composer。

低费用模式**只做三件事**：

```
1. python scripts/check_chapter_wordcount.py 第X章.md      # 字数
2. python scripts/check_human_rhythm.py 第X章.md           # 句法节律（退出码 1=不合格）
3. python scripts/check_aistyle.py 第X章.md                # 词汇指纹+模板短语
```

- 三个脚本**退出码全 0 = 本章合格**，直接收尾，不再做 AI味自评/杠精/评分/子技能。
- 某脚本报超 → 翻 `rewrite-playbook.md` 对应节按招改 → 重跑该脚本直到 0。
- **不做**：AI味自评量表、杠精自检、质量评分、dialogue-master、mood-composer、hard-check 子技能。这些是"判断型"检查，token 贵且结果已被脚本量化覆盖。

> 为什么敢砍：脚本的退出码已经把"像不像人"量成了数字。Agent 的 AI味自评是"再用 1000 token 重复一遍脚本已经得出的结论"。低费用模式只保留**能自动判定的**，砍掉**靠 reasoning 重复判定的**。

### 3. 写作模式：默认串行

- 低费用模式默认 `serial`（串行）。子代理并行会每个子代理独立读一遍上下文，是重复浪费。
- 若用户坚持并行：把「写作速查卡」+「本批细纲」+「上一章真实结尾」**直接塞进子代理的初始任务文本**，禁止子代理自己去读 guide 文件。

### 4. 文件编辑：Write 覆盖，禁止反复试

- 大纲/细纲/章节用 **Write 整文件覆盖**，一次性写完。
- **禁止**用 Edit/str_replace 反复试 old_str——实测这是巨大的隐性 token 黑洞（Agent 反复试匹配失败，每次失败都重新读文件重来）。
- 只有"改已写章节里的 1 句话"才用 Edit（且一次命中）。

### 5. 过程叙述压缩

- 不写"我来分析一下""现在我开始规划""接下来我要……"这类过程叙述。
- 质检报告**一行化**：`第X章：字数3125✓ 节律exit=0 词汇exit=0 → 合格`。
- 给用户的汇报也精简：只报"写到第几章 + 关键指标 + 有没有问题"，不写长篇总结。

### 6. 台账/圣经维护：合并批处理

- 不每章都重读 `05-创作台账.md` 五段全文。低费用模式改为：**每 5 章**做一次 seam 重读 + 台账回写（批量），而不是每章。
- 圣经、大纲、人物档案**只在章节切换时**才看，不在每章质检时反复翻。

---

## 三、低费用模式的保留项（不能砍的）

这些砍了质量会崩，**低费用模式也必须保留**：

1. **写前声音预置三行**（具体坐标/立场/留白点）——这是"人味"的根，不能省。
2. **三个脚本的退出码 0**——这是质量的底线。
3. **衔接检查**（续接型从上一章结尾接起，不另起炉灶）——防断档。
4. **三态标记**（标 ? 的不当既成事实写）——防伏笔断线。

---

## 四、费用/质量权衡（给用户选）

| 模式 | 单章 token（估） | 质检强度 | 适用 |
|---|---|---|---|
| standard | 1.0×（基线） | 全量（子技能+脚本+自评+评分） | 锚点章、关键章、定调章 |
| **low** | **约 0.3–0.4×** | 只跑 3 脚本 | 批量推进章、日常章、验证期快跑 |

**建议用法**：锚点章（品质 ⭐）用 standard 精写，普通推进章（●）用 low 快跑。两章混用，质量和费用都兼顾。

---

## 五、如何触发

写作计划 `02-写作计划.json` 里加字段，或作者在 Phase 2 确认时选：

```json
{
  "costMode": "low",        // "standard" | "low"
  "contentMode": "normal"   // "normal" | "nsfw"
}
```

子代理任务包 / 主 Agent 每章循环时，先读 `costMode`：low 就按本指南执行，standard 就按完整流程执行。
