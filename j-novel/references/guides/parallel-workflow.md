# 并发写作工作流：分层保真（Parallel Workflow）

**这份工作流回答一个问题：怎么并发写作，才能既快又有质量、上下文还统一。**

---

## 一、为什么并发会写崩（先诊断）

并发写作质量差的根源，不是子代理能力不够，是**机制缺陷**：

| 问题 | 根因 |
|------|------|
| 上下文不统一 | 子代理只看细纲，**看不到前面已经写好的真实章节**，只能按规划"猜"前文 |
| 风格漂移 | 文风锚点示例不滚动，所有章节都对照第一章的老腔调，越写越散 |
| 衔接断裂 | 批次边界没有真实交接，第 5 章结尾和第 6 章开头各写各的 |
| 状态断层 | 人物位置/情绪/受伤情况、伏笔状态无共享台账，第 3 章把主角弄伤了，第 4 章不知道 |
| 验收过轻 | 主 Agent "快速验收"看不过来，质量靠子代理自觉 |

**结论：并发省的是"写作时间"，但故事是顺序依赖的。** 无脑把 30 章同时派出去，等于 30 个人各写各的，必然崩。

---

## 二、核心原则：分层并发

```
创作（方向）→ 串行，主编独占     ← 质量上限由主编和细纲决定
执行（文字）→ 并行，子代理填字   ← 子代理只负责把蓝图填成文字
依赖（衔接）→ 串行保真           ← 有状态依赖的绝不并行
独立（同批）→ 并行提速           ← 无依赖的章节同时开工
```

- **并发的单元是"执行"，不是"创作"。** 所有创作决策（场景怎么展开、伏笔怎么埋、人物状态怎么变、情绪怎么走）都在细纲和状态台账里由主编定死，子代理**不自由发挥创作方向**——这就是上下文统一的根本保障。
- **质量上限由主编和细纲决定，不由子代理的运气决定。** 细纲写得越死，并发质量越稳。

---

## 三、滚动批次（批次间串行，批次内并行）

```
主编：生成第 1-5 章细纲（含锚点示例）→ 锚点章单独精写定调
   ↓
批次 A（第 2-6 章？不——锚点章除外，普通章 5 章/批并行）：
  子代理 2 / 3 / 4 / 5 / 6 各写一章 → 自检 → 主编验收 + 交叉衔接评审
   ↓
批次 B（第 7-11 章）：先更新细纲（锚点示例滚动 + 人物状态总览）→ 再并行
   ↓
批次 C …… （每批之间串行，批次内并行）
```

**规则：**
- 每批 5 章（可调），**批次间严格串行**——前批全部验收通过后才开下批
- 批次内并行：一章一代理，写完即交
- **锚点章不进并发批**（开篇/中点/高潮/结尾/卷终）：主编亲自精写或派最资深子代理，单独处理
- 每批细纲**重新生成**（不是复用第一批）：锚点示例滚动、人物状态总览按台账更新、伏笔清单按实际进度调整

### 批内依赖图（并行调度升级，治"中间章靠猜"）

并行有个固有缺陷：批内第 3 章和第 1 章同时开写时，第 3 章的子代理只能靠"细纲衔接锚点"猜第 1-2 章的实际结尾。**依赖图把这个缺陷显性化、调度化：**

1. **主编在细纲里标注每章的「上游依赖」**：
   ```
   第 3 章 上游依赖：第 2 章结尾（开头的画面/悬念直接从第 2 章结尾接）
   第 4 章 上游依赖：第 3 章结尾
   第 5 章 上游依赖：无（独立场景，可任意时间写）
   ```
2. **错峰调度**：
   - **无依赖章节**（或依赖已写完的章节）→ 立即派发并行
   - **有依赖章节** → 等上游章节完成后再派发（主编把上游真实结尾转给它）
   - 批内形成"第一波并行 → 第二波错峰 → …"的波浪，而不是一刀切全并行
3. **效果**：并行度不降（大多数章节仍能首波开写），衔接从"靠猜"变"靠真实结尾"——批次内的链条式交接从"事后补救"变成"事前调度"

> **依赖图画法**：主编生成细纲时顺手标注即可（一行一个依赖）。依赖关系看"本章开头是否承接上一章结尾的画面/悬念"——承接就标依赖，独立场景就不标。

### 批次验收闸门（硬性，防"下批开写时上批还没收尾"）

**这是并行写作最容易崩、也最常被跳过的闸门。** 实测事故：主编把第 7-8 章和第 9-10 章两批同时派了出去，第 9 章在第 8 章还没走完自检时就写完了——第 9 章的子代理没拿到第 8 章的真实结尾，只能靠细纲"猜"前文，章与章之间就断了。

**规则：下一批（或批内错峰章节）派发前，主编必须跑完下面 5 项验收，全部通过才放行。缺一项都不许开下一批。**

| # | 验收项 | 怎么查 |
|---|---|---|
| 1 | 本批所有章节 `status=completed` 且 `wordCountPass=true` | 读 `02-写作计划.json` |
| 2 | 本批每章质检记录已回写（AI味自评/节律检测/专项检查行齐全） | 读 `04-质检档案.md`，缺行 = 未收尾 |
| 3 | 状态台账"最近更新"推进到本批末章 | 读 `03-状态台账.md` |
| 4 | 创作台账"最近重读章号"推进到本批末章 | 读 `05-创作台账.md` |
| 5 | **章节边界无悬空钩子**（上章结尾的钩子人物，本章开头接住了） | 跑 `python scripts/check_continuity.py <项目目录>`，退出码 1 = 有边界需复查 |

**尤其第 5 项**：脚本报"钩子人物在本章开头缺席"时，主编逐条判断——是"该接没接"（bug，退回补一句桥接）还是"刻意留后章"（正常，但要在大纲/细纲标注"此钩子第X章回收"，否则下一批还会误报）。

> **为什么这 5 项是硬闸门**：它们把"前批收尾"从"主编自觉"变成"可逐项验证的清单"。
> 台账/质检档案停更、章节乱序完成，都是"主编自己在长跑中漂移"的信号——不是子代理的错，是主编没守闸门。**5 项全过，再开下一批。**

## 四、前序锚点：子代理写前必读（解决上下文割裂）

每个子代理写作前必须读（**读真实正文，不是细纲的一句话**）：

```
必读（短上下文，token 可控）：
1. 本批细纲（全书文风基因 + 锚点示例 + 本批人物状态总览 + 伏笔总览）
2. 上一章的真实结尾（500-800 字）——同批内也是链条式递进：
   第 3 章的子代理要读第 2 章的真实结尾，不是细纲的"承接自"一句话
3. 状态台账中本批出场人物的条目（当前位置/情绪/关系/已知信息/身体状态）
4. 文风锚点示例（最近确认的真实章节片段，不是第一章的老腔调）

选读（长上下文，大长篇用）：
5. 大纲摘要区的前 3 章摘要
```

> **任务包装配**：子代理的任务指令按 `references/guides/subagent-brief.md` 标准模板装配——**必须包含工具权限声明（Skill 工具可加载 reasonix-novel-* 子技能）、必读文件绝对路径、必调子技能（hard-check 每章 + 排班 dialogue/mood + 锚点章全调）、脚本绝对路径、人味配额标准**。四缺一不派发——子代理没装齐工具就开写 = 裸奔。

**关键**：批次内子代理之间的"上一章结尾"由主编在派发时随任务包提供（子代理写完自己那章，主编把结尾转给下一章的子代理）。**链条式交接，保证批次内部也接得上。**

## 五、状态台账（03-状态台账.md，解决状态断层）

这是并发的"共享记忆"，取代"让每个子代理读全部前文"。

```markdown
# 状态台账（实时更新）

## 人物状态
| 角色 | 位置 | 情绪 | 关系 | 已知信息 | 身体状态 | 最近更新 |
|------|------|------|------|---------|---------|---------|
| 林晚 | 城东旧宅 | 怀疑+恐惧 | 与沈渡决裂 | 知道照片背面名字 | 右手受伤 | 第12章 |

## 伏笔状态
| 伏笔 | 状态 | 埋设/推进章节 | 计划回收 |
|------|------|--------------|---------|
| 玉佩 | 已埋(第3章) | 第11章推进 | 第20章 |

## 时间线
当前故事时间：第 12 章，秋季，距开局 47 天
```

**台账规则：**
- **子代理写前**：读取自己章节出场人物的台账条目，作为本章状态起点
- **子代理写后**：把人物终态/伏笔动作写回台账（更新"最近更新"章号）
- **主编批次间**：核对台账一致性——发现冲突（两个子代理对同一角色状态写矛盾）→ 以细纲为准裁决，退回相关章节
- 台账由主编维护权威版本；子代理只在自己负责的章节范围内更新

## 六、锚点滚动（解决风格漂移）

```
第 1 批细纲的锚点示例：锚点章（第 1 章）确认版片段
   ↓
批次 A 完成后：主编从批次 A 的真实章节中抽取最代表文风的 1-2 段（150-250 字）
   ↓
第 2 批细纲的锚点示例 = 批次 A 抽出的新锚点（不是第 1 章的老片段）
   ↓
每批如此滚动……
```

**锚点示例跟着故事走**——后批子代理对照的是"最近的文风"，不是开篇的老腔调。同时保留「全书文风基因」（叙述者口吻/内心独白/对话节奏/感官偏好/收尾方式）作为不变的骨架，锚点示例作为滚动的血肉。

**风格抽查**：主编验收时随机抽段落对照当前锚点示例——"这读起来像不像同一个人写的？"不像 → 退回。

## 七、两轮质检 + 交叉衔接评审（解决验收过轻）

### 第一轮：子代理自检（每章强制）
- 字数脚本 + 硬性句式 + **AI 味自评量表（十一项，含「开场同质」）** + 杠精自检 + 衔接检查 + 逻辑 BUG 四查
- 质检结果回报主编，由主编统一写入 `04-质检档案.md`（**不写入章节正文**，正文保持纯净）

### 第二轮：主编验收（每章都过，不只看抽检）
- **硬性底线**：字数、硬性句式清零、`04-质检档案.md` 记录齐全（全部章节，机械检查）
- **正文纯净检查**：章节正文不含质检痕迹（如发现从正文移除，补记到质检档案）
- **细看抽检**：每批抽 1-2 章精读（文风统一性 + 场景落实度 + 人物状态正确性）——锚点章/半锚点章必抽
- **风格抽查**：随机段落对照当前锚点示例

### 交叉衔接评审（批次边界必做）
前批末章 vs 后批首章，专门对比四项：
1. **承接**：开头是否接住上章结尾的画面/悬念/情绪
2. **人物状态**：位置/情绪/关系/伤势是否连续（对照台账）
3. **时间线**：无跳跃矛盾
4. **风格**：读起来像同一个人写的

### 第三轮：交叉互检（质检独立于作者——自检不可信，别人的眼睛更尖）

子代理的自检（第一轮）由作者本人完成，天然带着"作者盲区"（自己觉得没问题）。**批内互检用"别人的眼睛"补上这一层：**

- **互检安排**：主编在批内组织两两互检——A 检 B 的章节、B 检 C 的章节、C 检 A 的章节（环形互检，每人检一章）
- **互检职责**：**只挑刺，不改写**——找出：文风是否与锚点一致、人物状态是否对得上台账、衔接是否顺、对话是否像"同一个人写的"、逻辑 BUG
- **互检产出**：每章一张"互检意见卡"（发现的问题清单，标注"必改/建议"），回报主编
- **主编处理**：互检"必改"项 → 退回原作者修改；互检发现但自检没发现的问题 → 记入质检档案（说明自检盲区）
- **成本控制**：每章多一次"只读挑刺"（比写作便宜得多），收益是质检有了独立视角

### 退回规则与失败换人（同一子 Agent 反复错 = 死循环）

- **单章问题**（字数/句式/状态错）→ 退回该章子代理重写
- **失败 2 次仍不过** → **换人机制**：不再退回同一子代理，**派一个新的子代理重写**（新的任务包 + 已积累的问题清单 + 前两稿的失败原因，明确"避开前两稿的错误"）；或先调 `reasonix-novel-write-master` 深度增强旧稿，再换人润色
- **批次级风格漂移** → 停下并发：主编重新抽取锚点示例，后续批次按新锚点调整（漂移章退回重写）
- **状态冲突** → 以细纲和圣经为准裁决，退回冲突章节

## 八、主编的职责（并发质量的关键，不可外包）

主编不是"发任务的"，是**质量负责人**：

1. 细纲写死创作决策（场景速写/人物状态追踪/伏笔清单/情绪曲线）——子代理不自由发挥
2. 维护状态台账（权威版本）
3. 每批滚动锚点示例
4. 提供"上一章真实结尾"给每个子代理（链条式交接）
5. **标注批内依赖图**（每章"上游依赖"，错峰调度）
6. 交叉衔接评审 + 风格抽查 + **组织交叉互检**（批内两两互检）
7. **失败换人**（失败 2 次换新子代理，附失败原因清单）
8. 发现漂移立即叫停，不将就
9. 全程持有圣经 + 全部真实章节（长上下文窗口足够），随时可亲自下场改

---

## 九、上下文预算（大长篇怎么不爆）

| 角色 | 必持上下文 | 策略 |
|------|-----------|------|
| 主编 | 圣经 + 全部真实章节 + 台账 + 各批细纲 | 长上下文窗口（100 万 token）足够 |
| 子代理 | 本批细纲 + 上章结尾(≤800字) + 台账条目 + 锚点示例 | 短任务包，随任务派发 |

大长篇（>30 章）：子代理选读前 3 章摘要即可，不必读全文——连续性由台账 + 上章结尾 + 细纲保证。

---

## 十、与写作模式的对应

- **serial（串行）**：主编自写，台账自然维护，本工作流的机制退化为"每章走一遍完整流程"
- **subagent-parallel（子代理并行）**：本工作流完整生效
- **agent-teams（Teams）**：机制相同——TaskList 的 owner 语义认领章节，主编负责台账/锚点/交叉评审；子代理之间通过 SendMessage 交接"上一章结尾"

---

## 十一、并发前的检查清单（不满足不开并发）

- [ ] 第一批细纲完整（文风基因 + 锚点示例 + 人物状态追踪 + 场景速写 + 伏笔清单）
- [ ] 锚点章已精写并经作者确认（文风基准已锁定）
- [ ] 状态台账已创建并初始化
- [ ] 大纲每章字段完整（核心事件 2-3 句 + 承接上章 + 悬念钩子 + 人物状态变化）
- [ ] 主编已就位（熟悉圣经 + 承诺做交叉衔接评审）

**四缺一，就不要并发——退回串行，把规划补扎实再开。**
