# 批量模式（Batch Mode）—— 无人值守写一批

> **它解决的那件事**：v9 之前，"写完一章"需要人填 4 个格子（状态台账/世界包/病灶/作者画面）。
> 10 章 = 40 次人工介入 —— **那不叫自动化，那叫"把手动做得更整齐"**。
> v9.2 起这四格全部由脚本从项目文件里抽（抽不到才 fail-closed），
> **一批 10 章的人工介入次数：2 次（批前确认 + 批后验收）。**

---

## 零、四个阶段（时间轴）

```
阶段 0  预备（脚本，0 次模型调用）
        make_task_package.py --batch 6-15
        → 看"齐备度"。不齐的章**先补齐，不许开写**（batch 不跳过缺料的章）

阶段 1  定（**模型调用，每章 1 次，先做完整批再动笔**）
        给每章写 chapters/_meta/<章名>.meta.md：
          ## 故事账（五格：选择/代价/位移/可删性/欲望）
          ## 后果链（五栏：动作/一阶/二阶/没看见的路/误判）   ← v11.0
          ## 实物清单（3–8 项，只属于这一章）
        ★ 为什么"先做完整批"：这十章的账摆在一起，你能一眼看出
          **位移是不是同一类**（原地转）、**代价是不是都没有**（白给）。
          这比写完十章再由 check_story 事后发现便宜一个数量级。
        ★ **后果链在批量模式下更值钱**：整批的 `二阶` 铺开之后，
          **第 7 章说的"下一章"到底有没有兑现**一眼就能对上——
          单章写单章推的时候，这件事永远看不出来。

阶段 2  编译（脚本，0 次调用）
        make_task_package.py --batch 6-15      → 应全 ✓
        python scripts/check_promises.py <项目> → 逾期必须 = 0

阶段 3  写 + 判（**每章 2–4 次调用**）
        写：只读 brief，一次成型，不自评
        判：make_workorder.py --archive N --retry 0   （9 脚本，退出码）
            make_blindtest.py --chapter N             （像不像人）
            make_grill.py --chapter N                 （站不站得住）
        改：只在红时，最多一轮（cards/card-revise.md）

阶段 4  批末（脚本 + 1 次调用）
        四个体检 + 锚点滚动 + 剧情卡共创（下一批）
```

## 一、停止条件（**没有这一节，批量就是批量生产垃圾**）

| 触发 | 处置 |
|---|---|
| **连续 2 章**盲测人类置信度 ≤1/3 | **停**。这不是某几句的问题，是语域整体偏了 → 升 R3 看全书 |
| **连续 2 章**出现同类硬伤（挑刺） | **停**。这是系统性问题（多半是"定"那一步没做），改规则不要改句子 |
| 任一章改到 **第 3 轮**仍红 | **停**并上报（铁律七：第三次撞同一堵墙 = 问题被错误框架化） |
| 承诺账**逾期 > 0** | **停**。债没还就开新线，读者会弃书 |
| 检查器本身报错（退出码 2 / 找不到稿子） | **停**。**"看不见稿子"不是"通过"** |

> **停的条件是质量信号，不是数量。** 不设"写到第 N 章自动停"——
> 那等于承认质量与章号无关，而它有关。

## 二、每一步的产物与落点（逐字，别改名）

| 步 | 产物 | 落点 | 谁写 |
|---|---|---|---|
| 0 | 齐备度表 | 终端输出（不落盘） | 脚本 |
| 1 | 故事账 + **后果链** + 实物清单 | `chapters/_meta/第NN章-*.meta.md` | **模型**（每章 1 次） |
| 2 | brief ×N | `任务包/第NN章-任务包.md` | 脚本 |
| 3 | 正文 | `chapters/第NN章-*.md` | 模型 |

| 3 | 盲测题/答案 | `chapters/_meta/第NN章-盲测{题,答案}.md` | 脚本 |
| 3 | 挑刺题 | `chapters/_meta/第NN章-挑刺题.md` | 脚本 |

## 三、成本（实测口径）

| 项 | 数 |
|---|---|
| brief | ≈ **9.5k 字**（上限 11500） |
| 每章调用 | **4–6 次**（定 1 + 写 1 + 判 2 + 改 0–1 + 记 0） |
| 一批 10 章 | **40–60 次调用** |
| 对照 v8 | 10–18 次/章 **+ 单章 21 本指南** |

> **省下来的不是"检查项"，是"读"和"反复查"。**
> 质检项从 7 项增到 9 项（多了故事账、承诺债），还多了盲测和挑刺两个独立评委。

## 四、反模式（每一条都会让批量变成灾难）

| ❌ | 为什么坏 |
|---|---|
| **一次派 10 个子代理各写一章** | 章序是**链式依赖**：第 N+1 章开头要接第 N 章结尾。派发时第 N 章还没有真实结尾 → 逻辑 BUG + 持续崩坏 |
| **跳过阶段 1 直接写** | 写完再补故事账，只能补出"我写的东西的意义"；写完再补后果链，只能补出"我写的东西的后果"。**判断必须在假设之前** |
| **批中改圣经** | 前三章和后三章不再是同一个世界，而且**当场没有任何脚本会报** |
| **只看退出码** | 指标全绿而盲测 0/3 = 典型的"达标的 AI 味"。三个读数缺一不可 |
| **为了让 10 章都过而放宽标准** | 那批量生产的就是"合格的平"。**批量模式的价值在于一致性，不是在于产量** |
| **批末不做剧情卡** | 下一批就回到"AI 按通用节奏推导"。**改在细纲之前是最便宜的修复点** |

---

## 五、人在这条流水线上的位置（只剩三个）

1. **批前**：确认剧情卡（这一批要发生什么）——**唯一需要做创作决定的地方**。
2. **批中**：只在**停止条件**触发时介入。不触发就一句话都不用说。
3. **批后**：看四个体检 + 盲测趋势 + **"这一批最强的一段是哪段"**。
   （第 3 条是给你的，不是给系统的：它是唯一能告诉你"这本书有没有长进"的读数。）

> **诚实标注**：批量模式降低的是**人工介入次数**，不是**质量标准**。
> 它保证"每章都过同一道闸"，**不保证"这本书会好看"**——那是剧情卡与作者画面的事。
