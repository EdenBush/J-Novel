# 成本纪律（Token Efficiency）

> **这份指南解决一个反直觉的事实：长篇连载的成本不由"写了多少字"决定，由"来回折腾了多少次、每次带着多重的上下文"决定。**
>
> 实测（《灰烬之契》前 6 章、1.24 万汉字，来自日志里的**真实 usage 字段**）：
>
> | 项 | token | 占比 |
> |---|---:|---:|
> | **cacheReadTokens（上下文重发）** | **44,411,008** | **97.8%** |
> | inputTokens（新增输入） | 676,482 | 1.5% |
> | outputTokens（模型产出） | 330,135 | 0.7% |
> | **合计** | **≈45.4M** | 每章 7.6M |
>
> **放大倍数 135×** —— 每产出 1 token，要读回 135 token 的上下文。**正文本身几乎不花钱，读回去的上下文才是全部成本。**

---

## 一、成本模型（先理解，再执行）

Agent 每一轮 LLM 调用都要**重发全部上下文**，所以：

```
成本 ≈ 调用次数 N × 平均上下文 C     （97.8% 是 cacheRead = 上下文重发）
```

内容加进上下文一次，之后**每一次**调用都要再为它付一次费——这是**复利**，不是线性。

**两条推论，直接决定本指南的所有规则：**

| 推论 | 含义 |
|---|---|
| **减少调用次数是主杠杆** | 实测 63 次调用/章，其中约 **60% 花在「改一处 → 跑脚本 → 再改一处」的微步循环**里。调用数砍到 1/3，成本近似砍到 1/9（N 与 C 同降）。 |
| **少读一个文件 ≠ 省钱** | 一本指南的代价 = 它的大小 × **读完之后还剩多少次调用**。实测"去掉全部指南读取"只省 **12.4%**——不是没用，但绝不是主杠杆。 |

---

## 二、四条硬纪律（按收益排序）

### 纪律一：批量化——消灭微步循环【最高优先，省 ~75%】

**禁止**：改一处 → 跑一个脚本 → 看结果 → 再改一处 → 再跑。
**改成**：一次跑完全部脚本 → 一次读完整报告 → **一次批量改写** → 复跑一次确认。

| 动作 | 现状（实测） | 目标 |
|---|---|---|
| 跑质检脚本 | **30 次/章** | **≤4 次/章**（初检 / 修后复检 / 收尾确认） |
| 改文件 | **12–27 次/章** | **≤5 次/章**（初稿 1 + 批量修 1–2 + 台账回写 1） |
| 每次调用做的事 | 一件 | **一批同类事**（能并行发的工具调用一次发完） |

**具体做法**：质检时用**一条命令**跑完全部脚本：

```bash
python scripts/check_chapter_wordcount.py 第XX章.md; python scripts/check_human_rhythm.py 第XX章.md; python scripts/check_aistyle.py 第XX章.md; python scripts/check_repetition.py 第XX章.md
```

→ 一次调用拿到**全部超标项** → 一次改完 → 复跑一次。**不要"修一项验一项"。**

> **为什么这不会降质量**：脚本已经把问题量化了。分 30 次跑和一次跑完，得到的**信息完全相同**，区别只是多付了 29 次全上下文重发。

### 纪律二：生成时配额——把 AI 味挡在初稿之前【质量与成本双赢】

**大模型的 AI 味不是"无能"，是"默认倾向"**：它默认把信息拆成短句、默认用"一+量词"泛化指代、默认把对话写成短促信息交换。**它有能力写 60 字复合句、有能力写一段完整发言——只是不会主动写。**

所以给出**配额数字**（不是原则），让它一开始就写对：

```
本章写作配额（写的时候就满足，不要等事后来修）

【一、必须补足的】
· ≥2–3 处 ≥60 字的复合句：把同一时刻／同一动作链／同一观察对象打包进一句
· ≥1 处 ≥30 字的完整发言（讲道理/诉苦/回忆/辩解），不是短促应答
· 具体数字 ≥1.5 次/千字（时间/距离/数量/钱），不要用"一会儿""很远"糊过去

【二、必须压住的】
· "一+量词"泛化指代（一个人/一张脸/一群人）≤ 8 次/千字 → 换具体数字或专有名词
· 明喻（像/如同/宛如/仿佛）≤ 1.2 次/千字 → 多写白描；全是明喻＝比喻审美均质化
· 身体部位（后颈/喉咙/手指/胸口/太阳穴…）≤ 0.9 次/千字 → 情绪别全靠身体反应
· 破折号 ≤ 3 处／章 → 补充信息并入主句，不要用破折号补刀
· 句首代词 ≤ 15%

【三、区间项（不是越低越好，归零同样是 AI 味）】
· 情绪词 0.25–0.5 次/千字（取中值 0.35 最稳）—— 不能是 0（归零＝过度克制，人类会直说情绪）
· 节奏：每 3 个 500 字段落里句长均值要有起伏（紧张段全短句，抒情段长句铺陈）
  —— 只补长句会让节奏变均匀，这条是防它的

【四、加法配额（抗 hack：有没有是二元的，多不多一定会被 hack）】
· 至少 1 处「叙述者知道但没说」或「角色不知道」—— 人类会不解释，AI 会把一切补全
· 2–3 处**删了故事完全不变**的小细节（一个用过就扔的东西／一段无人的环境／一次没有后果的小动作）
· 主角至少判断错一次，或漏一环，或先往错的方向想
· 对话里 1–2 处不完美：结巴／改口／说到一半被打断／称呼叫错
· 现实锚定计量 ≥0.05/千字（具体的钱数／门牌号／线路号／年级）—— 架空世界观豁免
```

> **【四】为什么单独成一栏**：前三栏都是"频率"（多不多），**一定会被 hack**（本项目实测：把"三件事"改成"三桩事"就骗过了量词检查）。**第四栏是"存在"（有没有），hack 不了**——你没法假装写过一段"删了故事也不变"的细节，也没法假装主角判断错过。
> 写法示范与人类原文见 `human-exemplars.md`。

> **⚠️ 三栏必须齐全——这是实测教训。** 早期版本只列了"【一、必须补足的】"，实测（《第0号存档》第 11 章 A/B）：超长句 1.40→3.63 ✓、量词 19.17→10.47 ✓、数字 0.31→1.67 ✓（四项翻绿），**但明喻 1.1→2.38、身体部位 0.5→1.19、情绪词 0.27→0，总不达标项数几乎没降**。
> **注意力是零和的：没被写进配额的项目，会被写进配额的项目挤出去。** 只写"要补什么"的配额卡，是半个配额卡。

**这张卡必须内联进子代理任务包**（子代理不会自己去读 guide）——见 `subagent-brief.md`。

> **为什么这是双赢**：事后精修 = 写错了再纠偏，每次纠偏是新的 LLM 调用，而且跑在已经膨胀到 400k 的上下文里；生成时配额 = 让倾向没机会发作，成本是 ~150 token。
>
> **但实测边界要说清楚**（《第0号存档》第 11 章 A/B，三轮，同一细纲、同一模型）：
>
> | 指标 | 10 章基线 | 带配额卡 | 变化 |
> |---|---:|---:|---|
> | 超长句(≥60字)占比 | 1.40 ✗ | **4.41 ✓** | **2.6×** |
> | 数字/千字 | 0.31 ✗ | **1.55 ✓** | **5.4×** |
> | 中文量词/千字 | 19.17 ✗ | **11.3** | 近腰斩（差一点过线） |
> | 节奏变异系数 | 0.28 ✓ | **0.36 ✓** | 改善 |
> | 身体部位/千字 | 0.55 ✓ | **0.89 ✓** | 仍在限内 |
> | 明喻/千字 | ~1.1 ✓ | 1.78 ✗ | **被挤超标** |
> | 情绪词/千字 | 0.27 ✓ | 0.22 ✗ | **被挤到线下** |
>
> **结论：配额卡治"缺什么"很灵（长句/数字/量词三项大幅翻绿），但 14 项指标是耦合的——补长句会把明喻挤上去，补数字会把情绪词挤下去。** 三轮都没能一次全达标。
>
> **所以生产流程按两段走**：① 生成时用配额卡把大头压住（干净的一半，零额外调用）→ ② 复跑一次脚本 → ③ 只对残留的 2–3 项做**一次**批量精修。
> **不要为了全绿无限迭代**——那是新的微步循环。硬线项（脚本退出码）必须过；软线项尽力即可。
>
> **成本对照**：本实验全章 3 次写作 + 3 次脚本 = **6 次调用/章**；基线项目实测 **63 次调用/章**。

### 纪律三：会话卫生——断掉上下文复利【第二优先】

上下文越到后面越贵：同一个改写动作，在 50k 上下文里做，比在 600k 里做**便宜 12 倍**。

| 规则 | 做法 |
|---|---|
| **分段** | 每 **2–3 章**换一个新会话。交接靠**文件**（`05-创作台账.md` 的 Verified/Open/Next + `故事圣经.md` + 大纲章节摘要），**不靠上下文记忆** |
| **禁止晚期大修** | 长会话后期不做整章重写。要重写就先分段，在新会话里做 |
| **交接清单** | 新会话开场只读：`05-创作台账.md`（五段）+ 本章细纲 + 上一章真实结尾 + 状态台账本章人物条目。**不重读全套指南、不重读已写章节正文** |

### 纪律四：子代理瘦身——不要让 N 个子代理各读一遍全套指南【省 ~12%】

**实测**：`writing-mindset.md` 被读 **15 次**；6 本指南各被读 **6 次**（= 6 个子代理各读一遍）。去掉全部指南读取可省 **12.4%**。

| 对象 | 读什么 |
|---|---|
| **主 Agent** | 全套指南（只读**一次**，会话内不重复读、不逐章重读） |
| **子代理** | **只读一张速查卡** `quick-reference-card.md` + 任务包**内联**的内容（配额卡 / 锚点示例 / 上一章真实结尾 / 台账条目）+ **本章**相关的那 1–2 本指南 |

**禁止**在任务包里给"全套必读路径清单"——那是把主编的固定开销复制了 N 份。
**禁止**同一会话里逐章重读同一本指南（读过的记住，需要时引用，不重读）。

## 三、每章调用预算（自查用）

> **⚠️ 计数口径（必须先读，否则这张表会被误用）**
>
> 本预算数的是 **「需要模型推理的回合数」，不是 tool call 条数**。
>
> | 操作 | 计入 | 为什么 |
> |---|---:|---|
> | `read_file` / `ls`（批量读，一次装进上下文） | **0.2 次** | 纯 I/O，不触发新一轮推理；批量读 5 个文件仍算 ~1 次 |
> | `write_file` | **0.5 次** | 落盘不推理；但改完往往要回读确认，所以不设 0 |
> | Skill / Agent 派生 | **1 次** | 每次都是一个新的推理主体 |
> | 脚本执行（`check_*.py`） | **0.2 次** | 同上，读报告才算 |
> | 你自己做一次判断/决策 | **1 次** | 这才是真正烧钱的部分 |
>
> **为什么必须写清**：若按 tool call 条数算，「读 6 个文件 + 读 4 本 guide」光读就 10 条，
> 还没写正文就撑爆 18。但真实成本远低于此——**贵的不是读，是想**。
> 按"推理回合"算，读文件合并成 1–2 次，整章才落在这个区间里。

| 阶段 | 预算（standard） | 预算（low） |
|---|---:|---:|
| 启动 + seam 重读 + 写前分析 | 3 | 2 |
| 撰写初稿 | 1–3 | 1–2 |
| 质检（一次跑完全部脚本 + 一次读报告） | 2 | 1 |
| **独立质检子代理**（另起子代理，只给纯正文） | **1** | **1** |
| 批量修改 + 复检 | 2–4 | 1–2 |
| 收尾（注册审计 + 台账回写 + JSON 更新） | 2 | 1 |
| **合计** | **11–19** | **7–11** |

> **独立质检那 1 次不要省**——它是唯一能抓住"脚本全绿但读起来还是 AI"的环节，是整章性价比最高的一次调用。

**超过 25 次/章 → 停下来检查是不是掉进微步循环了。**

> 实测现状是 **63 次/章**。目标 15–20 次/章，成本降约 **75%**，且不损失任何质检信息。

## 四、成本自查（可测量）

跑一次审计脚本，看自己有没有掉进微步循环：

```bash
python scripts/audit_tokens.py <项目目录> --chapters <已写章数>
```

输出：真实 usage（cacheRead / input / output）、调用次数、每章折算、改写次数、指南读取次数、判据结论。

**判据**：
- 调用数 > 25/章 → 违规
- 脚本调用 > 6/章 → 违规
- 同一文件被改写 > 6 次 → 违规
- 同一本指南被读 ≥2 次 → 违规

## 五、禁止清单（每一条都实测过）

| 禁止 | 原因 |
|---|---|
| **逐项修、逐项验**（改一处跑一次脚本） | 最大单项浪费，占 60% 调用、约 75% 成本 |
| **逐章重读同一本指南**（实测 `writing-mindset.md` 被读 15 次） | 读完一次即记住；需要时引用，不重读 |
| **给子代理"全套必读清单"** | 固定开销 ×N（实测 6 本指南各被读 6 次） |
| **用 LLM 复述脚本输出**（"脚本说句首引号 12.3%，超标，我需要…"） | 脚本输出已经是结论。改为一行的 `超标项：句首引号12.3 / 破折号2.1 → 批量修` |
| **质检报告写成分析散文** | 报告一行化。结论 + 数字即可 |
| **同一会话内重复读同一文件** | 读过就记住；需要时引用，不重读 |
| **在 400k+ 上下文里做大段重写** | 先分段，再在新会话里重写 |
| **为省 token 而减少质检项** | 减的是**次数**，不是**项目**。质检项一个都不能少 |

> **最后一条是本指南的底线**：成本纪律优化的对象是"同样的检查做几次、在多重上下文里做"，**绝不是"少检查几项"**。
