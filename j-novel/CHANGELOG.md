# j-novel 版本记录

## v6.5.0 —— 工业化：建工单、量良率、给耦合指标一个终止条件（2026-09-23）

两轮分析（产线体检 + 返工深挖）得出的结论很硬：**整条链只有分子（成本）、没有分母（一次合格率）**，
而返工**高度集中**且**大部分本可以"给定"**。本版把结论落成机制，并**全部接进执行清单**
（否则又会变成新一轮孤儿）。

### 1. 新增 `scripts/make_workorder.py` —— 每章质检那一步的入口

```bash
python scripts/make_workorder.py <项目> --archive <章号> --retry <返工轮次>   # 每章一次
python scripts/make_workorder.py <项目> --report                            # 批末一次
```

- **一条命令 = 质检 + 归档**：内部跑完全部机械脚本（字数/节律/词汇/重复/连续性/世界/契约），
  **按退出码**判定**缺陷类型**，把一行**工单**追加进 `06-章节工单.md`。
  取代了原来的"逐项跑脚本 + 人肉抄进 `04-质检档案`"。
- **`--retry` 让 `retryCount` 第一次落盘**。此前它只存在于铁律七的规则描述里
  （「==2 强制换路」），**从未被记录过任何一次实际值** → 「一次合格率」在**定义上不可统计**。
- **`--report`** 出三个数：**一次合格率（判据 ≥70%，低于就停线分析）**、
  **缺陷帕累托**（决定该改哪条规则，只改头部 1–2 类）、成本回填（从平台轨迹按日期取）。
- **工单写独立文件，绝不碰 `04-质检档案`**：两份记录性质不同——
  `04` 是**人写的判断**（AI味自评/人味配额/四项测试），`06` 是**机器写的度量**
  （机械结论/缺陷类型/返工轮次）。**实测踩过**：初版 upsert 进 04，把用户项目里那一行
  的 **9 列质量数据覆盖成 6 列**（已还原）。**教训：向"别人的文件"追加前先看清它现有的列；
  覆盖式更新一个你没定义过 schema 的表，就是数据丢失。**

### 2. 指标分层（CTQ）+ `indicator-waived` —— 给耦合指标一个终止条件

**机制诊断**：句法目标表 17 个指标**物理上互相耦合**——拆长句→平均句长↓/超长句占比↓/p90↓；
合并句子→节奏 CV↓/段落 CV↓。而闸门要求 **17 项同时达标**：
**在耦合系统里这是一个「搜索问题」，不是"更努力"的问题。**
实测某项目第 1 章的 `check_human_rhythm.py` 被跑了 **189 次**（同章脚本调用 486 次）。

两层修法（进 `execution-contract.md`）：

| 级别 | 指标 | 判定 |
|---|---|---|
| **CTQ（硬门）** | **段落节律 CV** · **硬性句式（不是X，是Y）** · **作者在场指数** | 不过 = 阻塞 |
| **参考指标** | 其余全部 | **只记录 + 看趋势，单章不阻塞** |

**硬门少了，"同时达标"才成为一个可解的问题。**
再加 **`indicator-waived`**（沿用边界 waiver 的已验形态：理由 ≥8 字 + 记台账 + Phase 4 抽查）——
**一个"只有全绿才能出"的闸门，在耦合系统里等价于没有出口。**

### 3. 字数从"检验项"降为"工序参数"

实测：**`check_chapter_wordcount.py` 被调用 734 次 = 全部质检脚本调用的 52%**。
而字数是**唯一一个写前就完全确定的量**（配额卡已给目标）。
→ 改成：按配额卡一次写足（±10%），**只在收尾确认一次**；不足用补字 SOP 一次补齐。
**不要"查-改-查"——那是在反复问一个你写前就知道的数。**

### 4. 自适应抽检（判断项强度按风险分配）

工业的**跳批检验**：

| 连续合格章数 | 判断项强度 |
|---|---|
| 0–2 章 | **全检**（四项测试全做） |
| **≥3 章** | **抽检**（只做「同构 + 作者在场」） |
| 任一项失败 | **立刻回全检 + 计数归零** |

**省的是"顺风局的重复劳动"，不省保证水平**（失败立刻重置，风险窗口不扩大）。
⚠️ 与 low 的"合并"是**两回事**：合并＝降总强度；抽检＝**按风险动态分配**。

### 5. 前馈槽位：给"已用过的事实"，不给目标

任务包新增 `used_devices` 槽位（脚本自动从细纲抠）：
```
本批（截至上一章）**已经用过**的手法——本章请避开同型：
- 第1章：开场 新起型 / 章末 丁·悬念
- 第2章：开场 续接型 / 章末 丙·喜剧反转
```
**跨章同质**原本是"写完由 `check_repetition` 报警"（反馈＝多一轮 × 15 万 token）；
现在变成写前的事实（前馈＝几行字）。**且不可被 hack**——它是已发生的事实，没有可凑的数字。

★ **实测立刻在真实项目上抓到两处既有缺陷**：第 2、3 章**连续同型**章末（丙·喜剧反转），
以及第 2/3/4 章**连续三章**「续接型」开场。**这些此前只能等写完才发现。**

### 6. 锚点章改「三候选定调」（选择优于迭代）

实测锚点章（第 1 章）**486 次**脚本调用 vs 中位 **6 次** = **32 倍**。
原因不是它更该打磨，而是**它的交付物被定义错了**：锚点章真正的产出是
**一段 150–250 字、可被后续 50 章模仿的锚**，不是"一份 17 指标全绿的稿"。

→ 先在锚点章前写 **3 个不同声音取向的开篇**（各 300–500 字）→ 作者挑 →
**锚定了才补完整章**。迭代路线 = 1 份稿 × 20 轮；选择路线 = 3 份候选 × 1 次 + 一次"挑"。
**验收标准也随之改变**：不是"整章全绿"，而是「**这段锚能不能定住后续章**」。

## v6.4.0 —— 任务包编译器：把"记得填"变成"编译不过"（2026-09-23）

按 v6.3.1 的基线结论，**第一优先是压"每次调用带的上下文"**（实测中位 **149,675 tokens/次**，
而成本的大头就在"被乘数"这一侧）。本版落地它的机械手段。

### 新增 `scripts/make_task_package.py`

任务包此前由**主编手工装配**（十项）。手工装配有三个必然缺陷，**每一个都实测发生过**：

| 缺陷 | 实测表现 |
|---|---|
| **槽位没有 schema** → 少填一个没人知道 | 「锚点滚动」「句法目标表」写了却**从未进包**（漏了几个月） |
| **槽位没有预算** → 有的一塞 3000 字 | 实测每次调用平均重发 **149,675 tokens** 上下文 |
| **脚本能拿到的东西却靠人记** → 必然漏 | 上章真实结尾 / 契约 / 锚，**都能从文件里自动抠** |

**编译器做三件事**：

1. **装配** —— 脚本填它拿得到的：**上章真实结尾 / 接口契约 / 批次全局三件套 / 章号奇偶字数**；
   其余留成**显式待填标记**（世界设定包 / 台账条目 / 作者画面 / 已知病灶 / 诊断句）。
   **脚本不假装自己能写世界设定包。**
2. **预算** —— 九个槽位各有上限，**总上限 5000 字**（CJK ≈ 1 token/字）。
3. **校验** —— `--check` 对「缺必填槽位 / 超预算 / 待填残留」**退出 1**。
   **缺槽位 = 拒绝开工**。

```bash
python scripts/make_task_package.py <项目> --chapter 12 --write   # 编译
python scripts/make_task_package.py <项目> --check --all          # 校验（批闸）
```

**实测（某真实项目第 5 章）**：编译出 1767 字的包，脚本自动抠出了细纲全局段的
**文风基因 / 文风锚点示例 / 句法目标表**三样——而这三样此前只能靠子代理**自愿**去读
细纲的"批次全局信息"段，而任务包原话是"**重点读本章部分**"（等于让它跳过）。
`--check` 随后正确地报出 3 个待填槽位（含"细纲第 5 章没有契约块"——正是上一轮的活体发现）而拒绝开工。

### 🔴 顺带修了一个"脚本族不可复用"的根因

写编译器时要复用 `check_contract` / `make_handoff` 的解析逻辑，**一 import 就崩**：

```
ValueError: I/O operation on closed file   (lost sys.stderr)
```

原因：12 个脚本各自在**模块级**写
`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, ...)`。
而 `sys.stdout` 已经是 TextIOWrapper 时，`.buffer` 是**共用的**底层 buffer；
再包一层后，旧 wrapper 被 GC 回收会**连底层 buffer 一起关掉**。

> **换言之：这 12 个脚本此前是"不可被复用"的**——而"能复用"是任何工程化的前提。
> 这也解释了为什么这些脚本会各自复制一份 `read_text` / `extract_body`：
> **不是没人想复用，是一复用就崩。**

修法：`_shared.ensure_utf8_stdio()`（**幂等**），全部 13 个脚本统一走它。
→ 新增守卫「**模块级的全局副作用必须幂等**」。

### 守卫与测试

- 「关键脚本参数」新增 `make_task_package --check|--write`
- 「关键脚本必须存在」新增 `make_task_package.py`
- **新增守卫「模块级全局副作用必须幂等」**（扫全脚本，禁用裸 `TextIOWrapper(sys.stdout.buffer)`）
- `test_guards.py`：**52/52**（新增 51 任务包失去校验、52 非幂等 stdio 包装）

### 本轮踩的坑

- **第 8 次「存在性判据命中无关文本」**：新的 stdio 守卫**匹配到了它自己的注释**
  （注释里引用了那个模式）。而本文件里**早就有 `_code_only()` 专治这个**——
  我没用。**规律：写任何"按模式扫描源码"的守卫，第一件事是套 `_code_only()`。**
- **测试 fixture 里的"坏代码"必须拼接构造，不能字面写**：守卫会扫 `test_guards.py` 自己，
  字面写进去等于让它命中本文件的 fixture（基线立刻变红）。
- **预算要容纳"度量粒度"**：`prev_tail` 按**段落**往回拼到 ≥800 字，多带一段就溢出
  （实测 882 > 820）。这种"超预算"是**度量口径**问题、不是包写胖了 ——
  **放宽容量的正确做法是调预算，不是放宽判据。**

## v6.3.1 —— 量基线：找到真实数据源，并因此**改了优先级**（2026-09-23）

这是 v6.3.0 那份计划里的**第 0 步**（"先量基线，再决定中段并行值不值得做"）。
结果很值：**基线一量出来，优先级就变了。**

### 🔴 数据源修正：成本审计工具自己是个孤儿

`audit_tokens.py` 一直在找 `<项目目录>/AGENT工作日志/session.jsonl`。
实测**全盘搜索：该目录从未被任何环节产出**——项目里没有，脚本里也没有写它的代码。

> **它本身正是本轮审计的那个病灶**：有校验点（调用数/超标的判据都写好了），
> 却指向一个**不存在的生成点**。所以"成本纪律"这条铁律，
> 在长达几个月里**没有任何一次可复现的验证**（文档里那些"实测"数字成了孤证）。

**真实数据在平台侧**：`~/.workbuddy/traces/<pid>/trace_*.json`，每个文件 = 一个 agent 会话，
其 `trace.modelInfo` 带真实 usage（`callCount` / `totalInputTokens` /
`totalCachedTokens` / `totalOutputTokens`）。→ 新增 `--traces`，并把它设为主路径。

### 🔴 口径修正：`cacheReadTokens` 是 `inputTokens` 的**子集**，不是并列项

初版把两者当互斥去算占比，得出"cacheRead 49.6% / input 50.3%"——
**与文档里"97.8% 是 cacheRead"对不上**，差点把一条正确的历史结论当成错的。

实测核对：某轨迹 `20,782,208 / 21,285,947 = 97.6%` —— **文档没写错，是我算错了。**
正确口径：`prompt = inputTokens`（其中 cached 是命中缓存的子集、新增 = input − cached）。

### 实测基线（471 个会话 / 8,457 次调用）

| 指标 | 实测值 |
|---|---|
| promptTokens（每轮发出的上下文） | **2,336,020,596**（99.7%） |
| ├ 其中 cacheRead（缓存命中） | 2,305,004,145 = prompt 的 **98.7%** |
| └ 其中新增输入（非缓存） | 31,016,451 = **1.3%** |
| outputTokens（模型产出） | 6,995,983（**0.30%**） |
| **放大倍数** | **334×** |
| **每次调用平均重发上下文（中位）** | **149,675 tokens/次** |
| 同（p90） | **420,203 tokens/次** |

### ★ 新增判据：**每次调用平均重发上下文**

「cacheRead 占 98.7%」是个**比例**，它不告诉你绝对量。真正该盯的数是
**`promptTokens ÷ 调用次数`**：

| 每次调用重发上下文（中位） | 判据 |
|---|---|
| < 50k | ✓ 纪律良好 |
| 50k–100k | ⚠️ 偏高 |
| **> 100k** | **✗ 失守**（实测 **149,675** = 严重超标） |

### 🔴 结论：优先级被数据改了

会话长度分布（471 个）：

| 调用数 | 会话数 | 占比 |
|---|---|---|
| 1–5 | 207 | 44% |
| 6–20 | 133 | 28% |
| 21–50 | 94 | 20% |
| 51–120 | 31 | 6.6% |
| **121+** | **6** | **1.3%** |

> **中位会话只有 8 次调用**（短会话、按需派发）——**"调用次数爆炸"并不是主症**。
> 而**长会话（>120 次）只占 1.3% 的会话数、贡献 16.2% 的 cacheRead**。

于是两笔账被分开了：

| 攻击对象 | 盘子 | 优先级 |
|---|---|---|
| **每次调用就带 15 万 token 上下文**（被乘数） | **大**（中位会话也这样） | **★ 第一优先** |
| 长会话的上下文累积（乘数的复利） | 约 **16%** 的 cacheRead | 第二优先 |

**所以「中段并行」的收益上限大约就是那 16% 那一档**，而"**压每次调用的上下文规模**"
（主编零正文 / 任务包瘦身 / 按需读不重读 / 分层锚只给该给的）**是更大的池子**。
——这正是"先量基线"的价值：**如果凭直觉先动中段并行，会打在一个 16% 的盘子上。**

  `check_repetition --imagery`

## v6.3.0 —— 一致性机制审计：从「文档里的散文」到「三站齐备」（2026-09-23）

前四轮（v5.6→v6.2）修的是**接缝**。这一轮换了个层面问：**多 agent 写同一本书，
跨章的文风与逻辑到底靠什么统一？**

结论出乎意料：**项目不缺机制，缺的是机制走完全程。**
审计出的 9 个缺口里，相当一部分是"规则写了、但某一站断了"。

### 新框架：一条机制必须走完「三站」

项目原有判据是「放错层级 = 规则不存在」。这轮把它拆细：

```
① 生成点  这条信息在哪一步被【产出】？  缺 → 不存在（不是没生效，是没有）
② 交付点  它怎么【进入执行者上下文】？  缺 → 看不到（写了、算了，但没送到）
③ 校验点  怎么知道它【被遵守了】？      缺 → 不可证伪（全靠自觉，长跑中静默失效）
```

**用它体检的结果：文风线六项机制里只有一项三站齐全。** 这也解释了
"为什么写了几十万字却越来越不像开头那本书"——**没有任何一站会报错**。

### 修的东西（按"三站"归类）

| 机制 | 缺的是 | 修法 |
|---|---|---|
| **接口契约**（并行写作的**主**逻辑机制） | **生成点 + 校验点** | 细纲规格加「接口契约（冻结 · 机器可读）」**键值栏位**；新增 **`check_contract.py`** 做**相邻章状态 diff** |
| **锚点滚动**（主力文风机制） | **交付点** | 此前"全库只有 3 处提及，**两套执行清单都没有它**"→ 进 SKILL.md 新增的批末动作 10.5 |
| **句法目标表**（可测量锚） | **交付点** | 此前 Phase 2 算完就被三个下游全部忽略 → 任务包新增「**批次全局三件套**」内联（文风基因/锚点示例/句法基线） |
| **累积漂移** | **校验点（设计缺陷）** | 三层锚：`--vol-base` / `--book-base` |
| **意象使用记录** | **三站全缺（唯一真孤儿）** | 脚本化：`check_repetition.py --imagery` |

### 🔴 契约：主机制「读点 12 处、产出 0 处、校验 0 处」

并行写作里，第 N+1 章的写手**看不到第 N 章正文**，只能靠契约知道
"第 N 章结束时人物在哪、什么情绪、知道什么、受没受伤"。所以契约是**接口定义**。

实测核对：`outline-template.md` 搜「契约」= **0**；`scripts/` 搜「契约」= **0**。
**而它在文档里有 12 处引用。** 读点齐全 → 让人以为这条机制很可靠 → 实际没人产出、也没人验。

- **`scripts/check_contract.py`**：解析细纲里的契约键值 → ① 齐备性 ② **相邻章 diff**
  （第 N 章「退出·X」vs 第 N+1 章「进入·X」）。
- **时点刻意放在派发写手之前**——此刻还没有 3000 字要改；写完再发现要动两章 + 重做缝合。
- 键值格式（一行一键，机器可读）：`- 进入·位置时间: …` / `- 退出·情绪: …` / `- 承接要素: …`
- 真实验证：本机某项目 10 章细纲**全部没有契约块** → 脚本一次报出 10 条。

### 🔴 三层锚：累积漂移此前**在定义上不可见**

这是上一版（v6.2.0）由构造产生的盲区：`--base <批首章号>` 让每批重新定基，于是
批 1 比第 1 章、批 2 比第 11 章、批 10 比第 91 章——**每批都合格，全书可以漂到任意远**。
而"读着不像开头那本书了"恰恰**不是批内问题**，所以每一道批级闸门都放它过去。

- **三层锚**：**全书锚**（第 1 章，**永不滚动**）／**卷锚**（每卷第 1 章）／**批锚**（本批首章，滚动）。
- 新增 `--vol-base` / `--book-base`；同一章兼任多层时**标签合并显示**（`卷锚/全书锚`）——
  若按索引直接去重，报告会莫名少一层，读的人会以为那层没生效。
- **「累积漂移」的判据是"胜出的锚比门控锚更早"**，不能只看"比滚动中位数更敏感"——
  否则批锚自己也会被标成累积漂移，那就分不清批内波动与跨批累计。
- **`--selftest` 加了第 5 项，专门证明这个盲区**：同一组数据，"只看批锚"= 0 报警、
  "加全书锚"= 判失败。**盲区本身成了回归用例。**
- `--drift` 同时**从"只有 low 链"提到 standard 也跑**——因为**定调章（锚点章/卷首卷末）走 standard**，
  而它恰恰是全书声音的基准，此前是唯一不受检测的章。

### 🔴 意象使用记录：把唯一真孤儿变成脚本

`bible-template.md` 四·五 早就定义了规则（**同一意象每卷 ≤4 次，且至少有一次"该出现时缺席"**），
但**全库只有那一处定义、零读点**。而它天然可脚本化 → `check_repetition.py --imagery`。

实测中修了两处**精度陷阱**（都是真实数据踩出来的）：
- `炉火/火光` —— 表里用斜杠列同义写法，整串做 `str.count` **恒为 0** →
  这个意象**永远"合格"**（静默通过，比报错更糟）。修：按斜杠拆变体后求和。
- `门` —— 单字在中文里无法可靠计数（门口/部门/门票）。修：**丢弃并**在报告里点名
  「**无法计数、已跳过**」——宁可明说"这项没查"，也不给一个看似正常的假数字。

真实项目上立刻报出一条可用发现：`数字` 这个意象出现在 3/5 章（⚠ 过密）。

### 🔴 独立质检：low 模式此前把「独立性」当成成本砍掉了

`review-agent.md` **自己和自己矛盾**：§六 写明独立质检必须「**另起一个子代理，只给纯正文**」，
而 §五 的 low 行写「并入判断合并那一次调用」——而"并入"意味着由**同一个 agent** 做，
那个 agent ① 知道全部规则（它按规则打磨的）② 刚打磨过这份稿子 ③ 本身就是被评对象。

> **「合并同类调用」这条原则本身是对的**（自评/配额/评分确实是同一 agent 对同一稿子做多个判断），
> **但它被误用在了"独立性"上。** 独立质检贵不在"问几个问题"，在**由谁问**。

修：**独立但极轻** —— 仍另起子代理，但任务包压到最小（**只给纯正文 + 4 个问题**）。
它其实是全流程**最便宜**的角色（输入一章、输出几行，且"没有"也是有效答案）。
**砍它省不下钱，却砍掉了整条链上唯一"不看规则的眼睛"。**
→ **要省，就省它的输入，不要省它的独立性。**

### 🟠 其余口径修正（每一条都有实测依据）

1. **`phase2-planning.md` 的「模式选择」提示还写着旧口径**——而且那是**最坏的位置**：
   它在**作者做选择的那一刻**说「低费用模式（只跑 3 个脚本…**质量略降**）」，
   作者会带着这个预期去选。**选项描述里的口径污染，比说明里的严重得多。**
   守卫名单此前只查 flow 文件与 SKILL.md，**本轮补上 phase2**。
2. **伏笔对照表双载体同名**（圣经 vs 大纲）—— 双载体同名必然漂移，
   而漂移表现恰好是"同一伏笔两处状态不同"，**正是伏笔机制想防的事**。
   依实际运行路径判定：**`01-大纲.md` 是唯一权威**（每章同步 + 三处检查）；
   圣经那张降级为**卷终派生视图**。三方文档同步声明。
3. **low 对铁律六的静默豁免**——铁律六写「**【必须】每章** seam 重读」，
   而 low 改为"每批一次"，**没有声明是例外**。后果：读铁律六的 Agent 每章重读（贵但"合规"）；
   读 low 的按批做（省但"违规"）；而 **Phase 4 还要抽查"最近重读章号"是否推进** →
   low 可能被判"缺痕"（假报警）。→ 显式写成「**对铁律六的例外**」+ **Phase 4 分档判据**。
4. **数字 `3` 承担四种语义**（同形异义）：窗闸窗口／领先上限／连续三章同型／每 N 章换会话。
   其中**前两个确实是同一个数**（必须相等），另两个**纯属巧合**——后者最坏，
   会让人以为它们也有关联。→ 新增「本书里的四个「3」」对照表，要求写完整说法。
5. **会话卫生口径冲突**（token-efficiency「每 2–3 章」vs low「每批」）——
   两者都对，**因为会话策略本来就该随组织形式变**：串行时主 Agent 线性累积，要勤换；
   流水线里各角色上下文近似常数，勤换只是白白重读圣经/大纲。
   → 补分档说明，明确 low 取"每批一次"**不是打折，是复利本来就不存在**。
6. **任务包说"重点读本章部分"会让子代理跳过细纲全局段** —— 而**批次级的三样东西
   （文风基因/锚点示例/句法目标表）正好在全局段里**。→ 新增「批次全局三件套」内联槽位。
7. **新增「分层锚」**：**写手管手感（文本锚）、改稿手管分布（差异表：方向 + 段号位置）**。
   以前把一段锚点同时指望它定住语感和分布，是错配——**一个统计分布不能靠看样例命中**。
   **分布层不给数字目标**（项目实测过"底线当目标、配额当目标"被 hack），
   给的是"本章平均句长 19、本书基线 29 → 第 4/7/11 段各有一处可合并"——**有靶子，没有可凑的数**。

### 守卫：新增「一致性机制的『三站』不齐」

13 项检查，覆盖契约（生成/交付/校验三站）、三层锚、意象配额、锚点滚动、独立质检独立性、
伏笔单载体、台账例外。**它的价值不只是盯住这 13 条——它是第一个能自动发现孤儿的守卫**：
任何"文档里定义了、却没有任何执行链引用"的东西都会被它抓出来。

### 本轮踩的坑（都是新形态）

- **第 7 次「存在性判据被无关文本／否定句命中」**：新加的「低费用…质量略降」判据
  初版只查 `质量略降|质量下降|牺牲质量` → 立刻炸出 4 处假阳性，其中三处是
  「**这不是**牺牲质量换省钱」这种**反话**。修：判据**要求同现**（本行同时出现 low 与降质说法）
  + 排除否定。**规律：判据要么要求同现，要么排除否定，不能只查关键词。**
- **排除词的作用域**：把 `'不是'` 加进全局排除表后，**SKILL.md 的一条真问题被漏掉**
  （那行是"组织形式走链式流水线 + 批次（**不是**串行……）……只跑 3 个脚本"——
  同一行里的旧口径被整行豁免）。**故障注入用例 ㊵ 立刻变红抓到回归。**
  **规律：排除词要按"它在否定什么"限定作用域，不能全表共用。**
- **守卫关键词太泛 = 验不到东西**：契约生成点的判据初版写"接口契约"，
  改成"接口契约（X）"照样通过 → 判据改成查**键名** `进入·位置时间`，
  这才真正验到"栏位是否存在"。（用例 ㊷ 一开始就是这么漏的。）
- **自测数据本身可能证明不了结论**：累积漂移用例初版把批锚设成第 1 章——
  而**批锚恰好就是全书锚**，"只看批锚"当然也能抓到，那一项**证明不了盲区的存在**。
  改成「批锚 = 第 7 章 + 全书锚 = 第 1 章」，并断言"只看批锚时应为 0 报警"。

## v6.2.0 —— 低消耗 × 链式流水线：补上「又快又低」漏掉的三个洞（2026-09-21）

上一版（v6.1.0）把 low 模式的组织形式定成链式流水线。**这一版处理两者接缝上的三个洞**——
不补，就是"跑得飞快、但错误以同样的速度扩散"。

### 贯穿全局的一条判据

> **质量闸门的位置必须满足：发现缺陷的时点 ≤ 该缺陷被"定稿"的时点。**

晚一步，修复就从"在队列里改"变成"**回头改**"：要重做缝合、重抽文风锚点、重写台账，
成本超线性；而且**回头改本身会成为新的不一致源**。
推论（这条推翻了"质检要全部提前"的直觉）：**只把跨章项提前**——
单章缺陷晚发现也只改一章（不敏感），跨章缺陷（同质/漂移/分裂）晚发现要改 N 章。

### 🔴 洞 1（成本）：主编读正文 —— 子代理省下的钱被它一个人花回去

- **冲突**：流水线的收益来自"子代理上下文彼此隔离、不累积"（实测 cacheRead 占 97.8%），
  而**主编是活得最久的角色**——它每章读两遍正文（取结尾 + 缝合），
  读过的每一章都留在上下文里，跟着它之后**每一次**调用被重发。
- **旧文档甚至还写着**主编"必持**全部真实章节**"，理由是"100 万 token 窗口足够"——
  那是**窗口够不够**的论证，不是**成本**的论证。
- **修**：新增 **`scripts/make_handoff.py`** —— 从正文裁出**交接卡**
  （上章真实结尾原文 + 本章首段 + 本章末段 + 三者指纹，≤800 字）。
  **主编读卡不读正文**：每章进入主编上下文的量从两整章（~6000 字）降到一张卡（~800 字），
  且**不再随章数累积**。
- **这不是牺牲质量换省钱**：缝合需要的信息**就是边界段**，读全文反而把它淹在 6000 字里。
  裁卡是信息提纯。
- `parallel-workflow.md` §八「主编的职责」第 9 条与 §九 上下文预算表一并修正
  （该文件里"全部真实章节"共有**两处**，第二处是守卫扩宽正则后才抓出来的）。

### 🔴 洞 2（质量）：跨章缺陷批末才发现 —— 回头修

- **病**：10 章一批、批末才跑一次闸门。笔手从第 3 章起连用同一种开场 →
  到批末才发现 → **7 章要回改**。
- **修**：**三道闸门**（`low-cost-mode.md` 第三节）
  - **章闸**（每章）：单章机械项 —— 0 token
  - **窗闸**（**每章**，滚动窗口 3 章）：跨章项 —— 0 token
  - **批闸**（每批）：判断项 1 次调用 + 全批视野，**交给子代理跑**（主编跑就得装全批正文）
- **窗闸的两个硬要求**：
  ① **必须每章跑**（就是上面那条判据）；
  ② **报告必须定长** `--window N --brief` —— 否则明细随章数变长，每章重读一遍
  = 把省下的上下文又花回去（省钱的机制变成花钱的机制）。
- **新增 `--window` / `--brief`**：`check_repetition.py`、`check_aistyle.py`。

### 🔴 洞 3（质量）：磨手改结尾 —— 接力棒被掉包（**两边都通顺，没有脚本会报**）

- **病**：笔手写第 N+1 章时拿到的是第 N 章的**草稿**结尾；磨手随后打磨第 N 章、
  把结尾改写（"换落笔形态"这类指令**恰恰鼓励**改结尾）
  → **第 N 章定稿的结尾 ≠ 第 N+1 章开头所承接的结尾**。串行模式不存在这个病。
- **修**：**边界冻结** —— 把 chained-pipeline 已有的「**契约冻结**」从**状态层**
  延伸到**文本层**：交接段（首段 + 末段）是**接口**，只有主编能动；
  磨手打磨交接段之外的一切；中间段落改动**不影响**（指纹不变、不必重做）。
- **指纹让"冻结"从纪律变成可检测**：改第 3 章末段，`make_handoff.py --check`
  **同时报出第 3 章和第 4 章**（第 4 章的卡里存着它当时承接的上章末段）——
  正好指向那对被拆散的接力棒。实测两向都验过（改中间段：0 报警；改末段：2 报警）。

### 🟠 洞 4（效率）：缺陷路由与流量控制

- **缺陷路由**（判据：**"这个缺陷会不会污染下游？"**）
  - 局部 → 磨手改（并行）
  - 系统·可向前 → **不回改已定稿章**；写进「本批已知病灶」→ 注入笔手任务包 → 后续章不再犯
  - 硬伤 → **停线回改**
- **流量控制**：笔手最多**领先磨手 3 章**。
  **为什么正好等于窗闸窗口**：两个数必须相等，因为
  「窗口 = 领先上限」⟺「发现缺陷时被污染的章还没定稿」⟺「**只向前修是安全的**」。
  它们不是两个可各调各的旋钮，是**同一个数的两个约束**。
  **顺带解掉一个取舍**：风险窗口与批次大小无关 → 批次可放心取大值（8–10），摊薄每批固定开销。
- **批首验章**：批次第 1 章走完整判断项（含四项测试）并**作为闸门**——
  low 不是不需要锚点，而是**锚点降到批次粒度**。成本不增（判断项本来每章一次），只是**位置**变了。

### 新增「声音漂移」检测（把风格一致性从判断层降到机械层）

风格一致性以前只能靠 LLM 读全章比风格（判断层价格，且拖到批末）。

## v6.1.0 —— 低 Token 模式重新设计：从「砍质检」到「换组织形式」（2026-09-21）

### 需求

> "重新设计低 Token 模式，核心就是：**快速的批量写文，高效质检修改润色（人味）**，
> 快速写文，低 token 消耗。"——要求**先按整个 SKILL 工程体系结构分析**。

### 分析：旧设计的三个根本问题

**问题 1 · 方向反了：「默认串行」与「批量」直接冲突，而且串行更贵**

旧设计原话：「低费用模式默认 `serial`（串行）。子代理并行会每个子代理独立读一遍上下文，是重复浪费。」

**这个判断是错的**：

- **串行**：主 Agent 连写 N 章，上下文**线性累积** → 写第 N 章时要重发前 N−1 章的一切。
  **97.8% 的 cacheRead 就是这么来的**；
- **并行（链式流水线）**：每个子代理的上下文**只有任务包**（速查卡 + 细纲 + 上章尾 + 设定包），
  **不带历史、互不污染** → cacheRead 反而小。

→ **批量场景下，链式流水线又省又快。旧设计把最该做的一条做反了。**

**问题 2 · 把免费的扔了，把贵的砍了**

| | 性质 | 消耗 | 旧设计 |
|---|---|---|---|
| **机械项**（6 个脚本） | 退出码是硬判据 | **0 reasoning token**（免费质检） | **只跑 3 个** —— 砍掉了 `check_repetition`，而它是跨章开场/章末同质检测的载体 |
| **判断项**（LLM） | 贵在"重复问好几遍" | 4–5 次调用 | **5 项全砍** |

→ 新设计反过来：**机械项全跑（6 个），判断项合并成 1 次**——**检查项目一个不少，只是不再分 4–5 次问。**

**问题 3 · 落后于体系好几轮**

最近几轮新增的人味机制——**独立质检子代理四项测试、跨章开场/章末同质检测、世界设定包、
剧情脚手架、加法层（humanize-toolkit）、人类范本片段**——**low 模式里一个都没有**。
它停留在几轮之前。用旧标准快跑 = 产出"快速但人味差"的稿子，而用户要的恰恰是"高效质检（人味）"。

### 重新设计

**四把钥匙**（按效果排序，替换原来的"六条硬规则"）：

| # | 钥匙 | 省的是 |
|---|---|---|
| ① | **子代理隔离（链式流水线 + 批次 5–10 章）** | cacheRead 大头 |
| ② | **减少轮次**（一次跑完脚本／一次批量改／一次成稿） | 每一轮的上下文重发 |
| ③ | 上下文里少放东西（只读速查卡 + 内联） | 每轮重发量 |
| ④ | 会话分段（每 2–3 章换会话，文件交接） | 上下文累积 |

**质检新形态**：

```
机械项：一条命令跑完 6 个脚本（字数/节律/词汇/重复与跨章同质/连续性/世界设定）—— 全跑，0 token
判断项：合并成 1 次调用（AI味自评 + 人味配额 + 四项独立测试 + 一句可执行改法）
```

**人味不降清单**（low 必须保留，降的是重复劳动不是人味）：
写前声音预置三行 · 人类范本片段 · 加法层 3–5 招 · **世界设定包** · **作者画面** · 四项测试 · 跨章同质检测

**调用预算**：low 由 `6–10` 收敛为 **`6–9` 次/章**（6 个文件同步）。

**收归唯一事实源**：`low-cost-mode.md` 成为 costMode 的唯一事实源，
其余 8 处（phase3 三处 / phase4 两处 / guide-index / 速查卡 / review-agent）**只引用不重复数字**
——旧设计把同一套规则散在 8 个文件里各写一份，改一处漏一处必然自相矛盾。

## v6.0.0 —— 剧情脚手架升级：从「采访期采集」到「作者意图全生命周期管理」（2026-09-21）

### 需求

> "我希望它也能**当按照作者想法或者框架写完了前 1-2 章，然后自动询问作者想法**：
> 比如接下来怎么发展，**提供后续剧情建议**这样的。"

用户要求先分析确认方向再动手。分析后发现了比"加个询问"更深的东西。

### 分析发现：Phase 3 **明令禁止**这件事

> `phase3-writing.md` 核心规则：「一旦进入本阶段……**全程禁止向用户确认任何事**」
> 「**不要使用 AskUserQuestion**，不要向用户确认，不要停下来」

整个 Phase 3 只有**一个**被允许的确认点——`phase2-planning.md` 写明的：
锚点章定调，"这是疯狂创作模式下**唯一**允许的中途确认点"。

**而锚点章确认的是「文风」（怎么写）；"写什么"从来没人问过。**
→ 作者的剧情意图在 Phase 2 之后**再没有出口**。

**所以这个新能力不是"加一个询问"，而是要开第二个例外口子**——
必须和锚点章同级：**有边界、有触发条件、可关闭**，否则"疯狂创作"就废了。

### 设计（三处关键修正全部来自用户）

**① 频次不按章号，按「作者意图浓度」**

| | 有清晰意图的作者 | 把决定都交给 AI 的作者 |
|---|---|---|
| 被问 | **享受**（想表达，缺输出口） | **负担**（没想法，问了白问） |
| 策略 | 可高频，**即使在疯狂创作模式也值得开口** | 低频，只在真缺方向时 |

**判定按"最近表现"，不按历史厚度**（用户明确要求）——因为作者状态会变：
一开始热情、后来累了；或反过来写着写着来劲了。
→ 看**最近 2–3 次交互**；**连续 2 次"都行"才降级**（一次疲惫不算）；
降级时留一句"想多参与随时说"，**作者主动开口立刻升档**。

**② 触发点按「内容边界」，不按章数**

❌"每 5 章问一次"是机械规则。作者的意图天然按**故事段落**给（"前五章新手村"），
所以触发点落在内容边界：**作者安排的范围用完了** / 一个小阶段结束 / 卷末。
**且必须"察觉到作者对剧情有清晰需求"才开口**——浓度=弱时静默通过。

**③ 顺序：挖意图 → 摊素材 → 给建议 → 留口子**（★ 用户这条比我的原设计好）

我原来写的是"直接给 2–3 个方向让他选"，那会**把作者往我的方向上带**。改成四步：

```
① 先问（不预设答案）："你心里有方向吗？哪怕只是个感觉。"
② 先摊素材（不是先给建议）：把没回收的伏笔／人物走到哪／没用到的世界观／
   你定过的硬设定／情绪曲线，摆给作者看
③ 再给建议：2–3 条互斥路线 + 各自代价
④ 留口子："也可以说'都行'——那我按 C 走，记一笔你授权的。"
```

**第②步还有一个额外价值**：它让作者**看到自己的素材被好好用着**——这本身就是信任建设。

### 实现

- **`plot-scaffold.md` 重写**：从"采访期采集工具" → **四阶段全生命周期**
  （P1 采集 → P2 落点 → **P3 续航** → P4 对账）。
  新增：意图浓度判据、四条触发点、方向对齐四步、**建议质量四条硬要求**

- **产物扩展**：`07-剧情脚手架.md` 加「意图浓度」（动态）、「方向对齐记录」，

**规则本身写得不差**：`hook-techniques.md` 有四型 + 实测占比 + 每型的落笔要求；
`human-quota.md` 的金句配额是**上限**（≤1 句／全书约每 5 章 1 句）；
`writing-mindset.md` 甚至明说"**不要每章都画一个完美的句号……不是每章都要金句收尾**"。

**但两个漏洞让规则失效**：

1. **闸门只查大纲里的「章末型」字段（标签）**——`check_batch_gate` 的红线是
   "连续 3 章同章末型"，读的是 `01-大纲.md` 的表格列。
   → **标签轮换了，手感没换，闸门完全看不出来。** 这是一次"检查标签而非检查实体"的典型失效。
2. **`subagent-brief.md` 的兜底策略鼓励同型**："细纲没标就**用乙·关系余韵兜底**"——
   → 连续多章细纲没标，就连续多章走乙型；而"乙"容易被理解成"温和收束"，
   写成"叙述 + 余味"，连"小动作 + 一句对话"这个乙型的关键都没落地。

**结果**：五章**全部**落在"叙述一句 + 留点余味"上，
四型里"对话收尾（乙）／面板收尾（甲）／吐槽收尾（丙）"**一次都没出现**。

> **这就是"僵硬公式化"的实质：选了不同的型，落笔却都回到同一种手感。**

### 修复（五处）

1. **`hook-techniques.md` 加「选对「型」≠写对「落笔」」**：附上实测表格 +
   **四型落笔对照表**（甲=客观陈述/面板；乙=**小动作+一句对话**；丙=**一句吐槽**；丁=十三式）
   + 禁令"不要把四型都写成叙述一句+余味" + **换落笔形态的六种**。
2. **`subagent-brief.md` 改兜底策略**：从"没标就用乙兜底"改为
   "**看前两章用的什么型，避开它**再选"（并保留"乙最安全但连续用就变同构"的提示）+ 落笔约束。
3. **`check_repetition.py` 新增「跨章章末同质」检测**，两级判据（保守，减少误报）：
   - **失败级**：**相邻两章以同一个词起句收尾**（"反正…"接着"反正…"）
     —— 最硬的信号，人类作者不会连写两章同一个自嘲句式；
   - **提示级**：同一收束词全书 ≥3 次；**连续 ≥5 章无对话/面板收尾**。
4. **速查卡新增「一之六、章末不许公式化」**（子代理唯一读物）。
5. 新守卫：`PROPAGATION_RULES` 加「章末·选型≠落笔」（源指南有 → 速查卡必须有）。

### 验证

| 项 | 结果 |
|---|---|
| `audit_release.py --regress` | 0 处问题，回归 人类 3/3、AI 3/3 |
| `test_guards.py` | **31/31**（新增 ㉚速查卡缺禁令 / ㉛相邻两章同收束词必须被抓到） |

**实测对本批稿子**：准确报出两条——
`✗ 相邻两章都以「反正」起句收尾：第03章、第04章` +
`⚠ 连续 5 章都是「叙述」类落笔，没有任何对话/面板收尾`。

> **本轮的一般化教训**：闸门查**标签**（大纲字段、枚举值）而不是查**实体**（正文写法），
> 就会被"改标签不改写法"绕过。**凡是能从正文直接测的，就不要只信元数据里的字段。**

## v5.8.0 —— 规则过度执行：修「三到五章开头都是时间+环境空镜」（2026-09-21）

### 症状（用户报告）

> "我的其他项目出现了：三到五章的开头都变成了同一套「时间＋环境空镜」。
> 这其实是照我写的文风铁律执行的副作用——**规则被过度执行了**。"

### 根因：**两条**规则叠加，互相放大（用户只意识到一条）

**推手 ① `rewrite-playbook.md` 第 1 节第 ② 招「时间/地点/动作开头」**

它本来是**降「句首代词占比」的四招之一**（手段），不是文风。但：

- ② 招**门槛最低**——把状语提到句首，几乎不用重写句子 → 模型会**本能地多用它**；
- 它的两条真人范式本身就是 **"一公里外的沙丘，厄九披着…"（地点开头）**
  和 **"这是第二天的下午，封不觉…"（时间开头）** → 示范进一步强化倾向；
- **没有任何上限，也没有"禁止同构"** —— 四招里唯一没设边界的。

**推手 ② `chapter-craft.md`「日常进入型」开场**

这条说"日常章用日常进入型：**起床/走路/坐车/吃饭/上班/检查装备**"，
而它的三条真人原文里**两条是"时间/地点＋环境"起手**：
"早上五点，港城的天还是蒙蒙亮…" / "克洛废品站，第七区规模最大的垃圾站…"。
→ 被读成"日常进入就该先交代时间地点"。

**叠加效果**：日常章走「日常进入」（推手②）→ 开场要写"起床/走路"→
同时为了压句首代词用 ② 招提状语到句首（推手①）→ 产出 **"时间＋环境空镜"** →
连写几章就是同一个模子。

> **两条规则各自都没错。错在它们的示范都是"时间/环境"起手，且都没写"禁止同构"。**
> 这是本项目第 N 次验证同一条规律：**任何"N 处/要这样写"型规则，若不追加"禁止同构"与"上限"，
> 都会被填成模板。**

### 修复（六处）

1. **`rewrite-playbook.md` ② 招加三条上限**：四招轮换、同一段 ≤1 次、
   **连续段落不得同起句模式**、**章节开头不适用本招**（章首是最容易重复的位置）。
   并明确"② 招是**降指标的手段**，不是文风——手段变成风格就是同构"。
2. **`chapter-craft.md`「日常进入型」加关键辨析**：
   **抽掉环境那层，让真人原文成立的是"人物在做一个具体动作、露出性格"**。
   加了正误对照表，并明确 **"入口应该是人物，不是天气"** + 跨章换入口的六种类型。
3. **`check_repetition.py` 新增「跨章开场同质」检测**（`--all` 时跑）：
   给每章开头分类（时间/环境/对话/人物/其他），**连续 ≥3 章同类且是"空镜起手"即报错**，
   并直接打印根因与改法。这是批量写作特有的**结构级同构——单章看不出来，连写才暴露**。
4. **速查卡新增「一之五、开场不许同质」**（子代理唯一读物，必须在这里）+
   **`subagent-brief.md` 创作前清单**在"② 开场方式"下加约束
   （"动笔前先看上一章怎么开的，别和它同型"）。
5. **顺带修两个老 bug**（都在 `check_repetition.py`）：
   - 它自带**第五份** `extract_body`，且口径明显偏窄（只剥 3 种元数据块，
     漏了伏笔标记/自评/质检等 11 种）→ 同一稿子在重复脚本和节律脚本里分母不同 →
     已收归 `_shared`；
   - `--all` 又是 `glob('第*.md')`（**只在项目根扫**）→ 对合规项目找不到章节。
     这是同一个 bug 的**三胞胎**（前两次：wordcount、batch_gate）→ 已收归
     `_shared.find_chapter_files`，并改为 fail-closed exit 2。
6. 新守卫：`PROPAGATION_RULES` 加「日常进入≠环境空镜」（源指南有 → 速查卡必须有）。

**实测**：对《我战力全负》跑检测 → 5 章开场类型分别为 其他/人物/时间/其他/其他，**未构成同质**（正确不误报）；

## v5.7.0 —— 剧情脚手架：采集作者已有的剧情设想（2026-09-21）

### 新功能填的是流程里的一个真空区

现有 Phase 1 的 12 项验收**全是内核级**：核心钩子 / 第一章承诺 / 世界观规则 /
主角想要vs需要 / 对手自洽 / 升级阶梯 / 中点反转 / 伏笔 / 主题 / 风格 / 篇幅 / 标题。

而作者心里可能还有更具体的东西：**"第 3 章他遇到铁匠""第 5 章当众打脸""最后他站在塔顶"**。

> 这句话**不属于上面任何一项**——它回答不了"这本书在讨论什么"（不是内核），
> 也不是细纲（细纲是 Agent 从大纲推的下游产物）。**它没有入口。**

结果两种，都不好：① 被当成内核问题问岔（"你说的打脸，想表达什么主题？"）；
② **根本没人问它**——最后被 Agent 按通用节奏推导的大纲盖掉，
**而且没人发现它丢了，因为它从来没被写下来过**。

### 功能设计（新增 `guides/plot-scaffold.md`）

**触发两条路**：
- **主动提议**：验收 12 项全过后问一句"你脑子里有没有已经想到的具体片段？"
- **自动触发**：采访途中检测到信号（时序+事件／意愿+具体动作／具体的物／结局指向）立刻切

**脚手架五问**：定位 → 内容 → **因果** → 情绪 → **画面**
（问 3 查"是不是孤岛"，问 5 是整个功能价值最高的一问）

**三档密度**：作者给一句话就接"粗"档拆阶段目标；给节点就走五问；给画面就重点扣画面。

**产物 `07-剧情脚手架.md`**：作者原话（不改写）+ 条目（含**作者脑中的画面**）+
**未定位的碎片**（作者随口提的点子不丢）+ 对账表。
状态机 `未定位 → 待落细纲 → 已落细纲 → 已写 ／ 已偏离（原因）`。

> **「已偏离」必须写原因**——它让"作者的想法被改掉了"**有地址、可追溯**。
> 偏离本身不是错（写作中一定会变形），**无声的偏离才是**。

**四处接口**：Phase 2 大纲（条目是输入，**优先于自由发挥**）→ Phase 2 细纲（抄条目+画面）
→ Phase 3 任务包（**作者画面原样进包**）→ Phase 4/5 对账。

### 隐藏价值：作者画面 = 人味源

追问「问 5」挖出的**作者原话**（例：**"没人催他，也没人看他。"**）会**原样进子代理任务包**，
像人类范本一样**给原文不给路径**。三个理由：

1. 那是**作者自己的眼睛**——作者真的"看见"了场景，Agent 只是"合理生成"；
2. 它是子代理在这一章拿到的**唯一非规则素材**（其余全是约束，只有这段是**方向**）；
3. **它不可替代**——你没法用指令造出这个具体度，你能造出的只有"要写出孤独感"，
   而那正好是最 AI 的一句话。

⚠️ **给画面，不给解释**：绝不把画面改写成要求，否则人味立刻消失、退回成普通指令。

### 可选性（不许阻塞）

作者没有剧情设想 → 跳过、不生成文件、流程照走。**绝不因脚手架没做而卡住 Phase 1 出口。**

| `test_guards.py` | **27/27**（新增 ㉖㉗：Phase 1 无脚手架环节 / 任务包无作者画面） |

新增守卫：**剧情脚手架传导链**（7 环：指南存在／Phase 1 环节／Phase 2 对账／
任务包作者画面／速查卡纪律／guide-index 映射／SKILL.md 描述）。

## v5.6.0 —— 世界设定传导链：修「落笔时不是一个庞大的世界」（2026-09-20）

### 症状（用户报告，真实项目）

> "故事设定、游戏设定太单薄了。Agent 落笔的时候感觉不是一个庞大的世界，
> 子 Agent 写的时候感觉不是同一个世界，世界观或者背景设定会被吃掉。"

三个症状，一个根因。

### 诊断：世界观在计划期写完就断了传导链

**决定性证据**：`00-故事圣经.md` 在整个 SKILL 里**只有一处提及**——
而且是在 `phase2-planning.md` 的项目结构树里，只是说明"这个文件存在"。**创作期零读点。**

```
Phase 2 写完圣经 → ★ 链在这里断掉
      ↓
Phase 3 每章「写前分析」读：大纲字段 + 人物档案 + 细纲 + 续接检查
      → 大纲管"这章发生什么"、人物档案管"谁在场上"、细纲管"这场怎么演"
      → **没有一样回答"这个世界长什么样"**
      ↓
子代理任务包 8 个槽位：路径/细纲/上章结尾/人物条目/文风锚点/奇偶/病灶/诊断句
      → **一个世界设定都没有**
      ↓
落笔时"世界"是空的 → 用通用先验填 → 补出的是"一个村子"，不是"灰炉村"
      → 每个子代理各自填 → 不一致
```

这与 v5.5.0 修的是**同一类问题**：`skill-mechanics.md` 自己写着"**放错层级 = 规则不存在**"，

|---|---|---|

| **设定激活率** | **21%** | ≥60% |

而 `bible-template.md` 里这一节长期只有 **6 行占位符**，其中「关键地理/场景」还明确写着
**"每个一两句话"**——模板不要求，Agent 就不会写。它写出来的薄版已经是"尽力了"。

### 五处修复

**① 圣经模板：世界观手册 6 行 → 一本手册**（`bible-template.md`）
- **写法铁律**：写实体不写形容词（"低阶矿产与药草丰富" → "灰铁矿（含硫高、熔点八百）· 灰叶草（刷新 12 分钟）· 岩纹铁（纹理对不上就报废）"）

- **密度判据**：按短/中/长篇分档（手册字数、词表条目、场景卡、势力卡）
- **类型专属补充表**：游戏/玄幻/都市/悬疑/科幻/历史各一组必填项
- **反模式清单**：只写形容词 / 只有概念没实体 / 不写边界 / 词表空着 / 场景卡无可调用细节

**② 子代理任务包：新增「世界设定包」槽位**（核心修复，`subagent-brief.md`）

四块，**给原文不给路径**：场景卡（抄原文）/ 规则切片（"能做什么"必须配"做不到什么"）/
**专有名词表**（★ 禁止另造同义新词）/ 本章绝不能矛盾的三条硬设定。

> **为什么"专有名词表"是关键**：子代理看不见它 → 会发明"赤铁矿"来指你已经命名为
> "灰铁矿"的东西 → 两章之后世界就分裂了。**词表是比文风更硬的约束**：
> 文风可以各自接近，**名词必须完全一致**。

**③ 子代理唯一读物（速查卡）加「一之三、世界一致性」**四条纪律

## v5.1.0 —— 重标「人类区间命中率」：原阈值会判掉 89% 的真实人类章节（2026-09-17）

**触发**：给真实项目《我不是大师》第 1 章做全量重写时，该章命中率 65% 却报"软线未达"，

### 🔴 核心缺陷：尺度混淆（同一类错误第 3 次）

`人类区间命中率`（v4.9.0 新增）的硬/软线 **50% / 70%** 是在**整本书**上量出来的
（超神 100% / 重生啊 94% / 惊悚 70%）——**却被用在单章上**。

多数指标在单章尺度上是**成簇分布**的（打斗段情绪词扎堆、日常段为 0）。
整书平均会把簇抹平，单章抹不平。实测（人类三部长文切 4500 字窗口 ≈ 一章，n = **2948**，
用脚本自己的 `analyze()`）：

| | p10 | p25 | 中位 | p75 | p90 |
|---|---:|---:|---:|---:|---:|
| **人类单章** | 18% | 24% | **35%** | 41% | 53% |
| **非人类单章** | 0% | 6% | **6%** | 12% | 18% |

**后果**：硬线 50% → 人类章只有 **10.9%** 能过，即 **工具会判掉 89% 的真实人类章节**；
软线 70% → 人类 **0%** 能达到（形同虚设）。

**重标定**：硬线 **20%**（人类通过 81.6% / 非人类 8.0%，间隙最大档）｜软线 **35%**（= 人类单章中位）。

### ⚠️ 附带的反向洞察：这一项**不是越高越好**

人类章是**分散**的；而"按区间逐项调优"的稿子会**异常居中**。
实测重写后的第 1 章 **65% > 人类 p90（53%）**，落在人类分布的顶端 ~1%。
→ 脚本新增提示：**命中率 >55% 时警告"异常居中可能是被指标驯化的痕迹"**。
> **"每一项都刚好及格"不等于"像某个人写的"。**

### 落地

`check_human_rhythm.py`（阈值 + 注释重写 + >55% 警告）｜ 文档同步 3 处（`phase3-writing` /
`quick-reference-card` / `SKILL.md`）

### Bug ② 批次闸门算「下一章」会跳章


## v4.3.0 —— 作者在场：定位到最重的一层 AI 味（2026-09-13）

### 一、方法创新：把「对话部分」和「叙述部分」拆开

前四轮所有指标都在整篇上算，但 **AI 的问题不在对话，在叙述者**。本轮**剥掉全部引号内容**，只在**叙述部分**统计。

### 二、发现：五轮里**分离最干净**的一层

| 指标（每千字叙述） | 人类三部 | AI 全书三样本 | 上轮 A/B 四篇 |
|---|---:|---:|---:|

| 叙述里 `！` 占比 | 0.58–7.62% | **0.00–0.06%** | **全部 0.00%** |

**根因：AI 的叙述是透明的——只报告事件，不表态。** 它把所有的态度都让角色用对话说出来，**叙述者自身没有立场**。
最极端的两个信号：**口语插话在 AI 的十个样本里密度是 0.00**；**AI 把所有的 `？`/`！` 都放进引号里**（叙述感叹号差 **252 倍**）。

- `audit_release.py` 的阈值一致性检查同步纳入（**14 项**），并支持区间型（`lo=`）比对

### 四、⚠️⚠️ 本轮最重要的发现：**指标达标了，人味掉了**

写出规则后（第一版写成"≥3 处叙述者评价 + ≥2 处叙述句里的 `？`/`！`"），两个独立子代理产出：

| | 加规则前 | 加规则后 | 人类区间 |
|---|---:|---:|---|
| 章 12 在场指数 | **0.00** | **7.93（达标）** | 3.73–7.84 |
| 章 13 在场指数 | **0.32** | **5.84（达标）** | 3.73–7.84 |

**但盲评判决：第 12 章 v4.2 以 3:0 判负加了规则的那一版。**

**三位评委看到三份不同乱序、不同标号，却各自独立地从同一个文件里挑出同一组三句**：

> 老王在那儿修了六年车，**这种事也值得**专门打个电话去举报？
> 单数日子的排骨回锅，**这算什么**规律？
> 天比平时黑得早，六点不到就黑成这样，**这算什么**秋天？

> 「差别不在技巧，在**是否成套出现**。」
> 量化：**同构率 16.7% / 12.5%（加了规则）vs 0% / 0%（没加）**。

### 五、这是第 **4** 次同类错误——统一规律找到了

| 轮次 | 错误 | 后果 |
|---|---|---|
| 2 | **底线当目标** | 句长"≥18"（底线）→ 写到 19–22 就收手，人类 30.8 |
| 4 | **配额当目标** | 毛边"≥2 处" → 生产**填充物**，删掉毫无影响 |
| 4 | **方向当强度** | "用「道」"→ 92% 对话都挂；"一句一段"→ 景物也切碎 |
| 5 | **真指标做成配额 → 也变模板** | 作者在场 0→7.93 达标，**盲评反被判负** |

> **统一规律：任何"数量配额"都会被模型填成同构模板。**
> 因为模型的默认模式就是**同构生成**——给它一个"N 次"，它就会用一个模板填 N 次。
> **所以修的不是数量，是结构。**

### 六、规则改写：三条硬约束 + 从"做法"改成"视角"

- **指标必被 hack**：任何"次数型"指标都能被字面满足（实测：把"三件事"改成"三**桩**事"即骗过量词检查；删掉明喻却造出"似的/一般"新口癖）。**故设计"加法配额"（有没有是二元的）与"不可 hack 判据"（删除测试 / 找错测试）作为补充。**

- **配额卡治"缺什么"灵，治"耦合失衡"要配合批量精修**：14 项指标耦合，改一项会牵动别项（实测三轮均未一次全绿）。生产按两段走：生成时配额 → 复跑脚本 → 只对残留 2–3 项做一次批量精修。
- **量词密度对"倒计时/悬疑"题材偏严**（`17秒`/`41分钟` 这类剧情必需数字也被计入）。
- **情绪词表全是强情绪双字词**（恐惧/愤怒/悲伤/震惊），冷调恐怖里天然只能放 1–2 个。
